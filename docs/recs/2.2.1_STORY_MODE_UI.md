# REC 2.2.1: Story Mode UI Design (Clicker Style) - Implementation Checklist

This document defines the UI skeleton and interaction design for the Story Mode, drawing heavy inspiration from "Clicker Heroes" and other high-polish incremental games, while integrating the unique narrative gating system.

---

## 1. Visual Layout (High-Level Skeleton)

- [ ] **1.1 Master Layout Zones**
    - [ ] **Narrative Block:** Specific designated area for paragraph-by-paragraph text blocks.
    - [ ] **Combat Stage (PixiJS):** Center area for enemy sprites, damage numbers, and VFX.
    - [ ] **Global Buff Tray (Header):** Top area for persistent multipliers (including Dark Ritual).
    - [ ] **Generic Audio Player (Footer):** Dedicated player controls (Play, Pause, Restart, Speed, Visualizer).
    - [ ] **Interaction Side/Bottom Panels:** Hero Stats, Skill Hotbar, and Upgrade Menu.

---

## 2. Component Breakdown

### 2.1 Global Header & Buff Tray
- [ ] **2.1.1 Chapter Metadata:** Display "CHAPTER X | Scene Y" breadcrumbs.
- [ ] **2.1.2 Global Buff Tray:** Implement a tray for active multipliers.
- [ ] **2.1.3 Dark Ritual Bar:** Implement a persistent bar that fills as the player accumulates Dark Ritual levels across the chapter.
- [ ] **2.1.4 Sync Status:** Implement a hidden "Silent Sync" handler that listens for backend state corrections.

### 2.2 Narrative Text Area
- [ ] **2.2.1 Block Rendering:** Implement a specific screen area where text PNGs appear in blocks triggered by calculated delays.
- [ ] **2.2.2 Scroll & Fade:** When new blocks trigger, previous blocks must **scroll up with a fade-out** effect.
- [ ] **2.2.3 Reading Context:** Ensure text is layered correctly with a background blur/dimmer for readability.

### 2.3 Main Combat Zone (Center)
- [ ] **2.3.1 PixiJS Enemy Sprite:**
    - [ ] **Hit Flash:** 50ms white tint overlay on hit.
    - [ ] **Sprite Shake:** Apply shake effect *only* to the enemy sprite (not the whole screen).
    - [ ] **Animations:** Idle breathing, recoil on hit, particle burst on death.
- [ ] **2.3.2 HP Bar Logic:**
    - [ ] Implement color shifting (Green -> Yellow -> Red).
    - [ ] Implement vibration effect when HP < 10%.
- [ ] **2.3.3 Floating Damage Numbers:**
    - [ ] White (Normal), Yellow/Large (Crit), Blue (Auto), Red (Burst).
- [ ] **2.3.4 Environment Background:**
    - [ ] Implement a **Parallax Layered Background** (e.g., distant layers moving slower than foreground).
    - [ ] Ensure the PixiJS stage dynamically scales (Dynamic Aspect Ratio) to fill available space.
- [ ] **2.3.5 Infinite Wave Logic:**
    - [ ] If required waves finish before narrative: Trigger "Additional enemies discovered!" and spawn infinite waves until narrative completes.
- [ ] **2.3.6 Visual Fallback Handling:**
    - [ ] If an enemy sprite asset fails to load or is missing from the registry, display a **Generic Shadow Sprite** (placeholder) to ensure gameplay continuity.
    - [ ] The UI must still render the correct enemy name and calculated HP even if the visual is generic.

### 2.4 Generic Audio Player (Bottom)
- [ ] **2.4.1 Audio Controls:** Play, Pause, Restart, and Volume.
- [ ] **2.4.2 Playback Speed:** Toggle for 0.5x, 1.0x, 1.5x, and 2.0x speeds.
- [ ] **2.4.3 Progress Bar:** Display current time and total duration.
- [ ] **2.4.4 Visualizer:** Simple CSS/JS waveform overlay.
- [ ] **2.4.5 Narration Gate:** Block "Next Scene" until the scene's calculated duration is reached (or audio finishes).

---

## 3. Interaction Panels

### 3.1 Hero Stats & Gold
- [ ] **3.1.1 Gold Odometer:** Implement a **Digit-Flip** (flip-clock style) animation for the gold counter.
- [ ] **3.1.2 Gold Pop VFX:** Animate gold coins "popping" in a fountain from the enemy before flying to the counter.
- [ ] **3.1.3 Large Number Display (Scaling):**
    - [ ] Implement formatting: 1,000 -> **K**, 1,000,000 -> **M** ... through 10^30 -> **No**.
    - [ ] Implement transition to alphabetical: 10^33 -> **aa**, 10^36 -> **ab**, etc.
    - [ ] Display rule: Show 2 decimal places for suffixed numbers (e.g., `12.55 Qa`).
- [ ] **3.1.4 Silent Authority:** If the backend pings a gold mismatch, the UI must "force update" the odometer to the server-verified amount.

### 3.2 Active Skills Hotbar
- [ ] **3.2.1 Visual Feedback:** Ready (glow), Active (timer overlay), Cooldown (sweep).
- [ ] **3.2.2 Stacking:** Clicking must be allowed and stackable with all active skill effects (e.g., Clickstorm).
- [ ] **3.2.3 Purchase Logic:** Skills must be purchased with session gold before appearing as "Ready."

### 3.3 Session Upgrade Menu
- [ ] **3.3.1 Global Multi-Buy Toggle:** Implement a single toggle for **x1, x10, x100, MAX** that applies to all upgrade buttons.
- [ ] **3.3.2 Purchase Buttons:** 
    - [ ] If the selected increment (e.g., 10x) is unaffordable, grey out the button.
    - [ ] Always display the **cost for the selected increment** (or cost for 1x if 0 affordable).
    - [ ] **Buy Max** logic: Purchases the maximum possible increments of that specific item with current gold.
- [ ] **3.3.3 Bonus Previews:** Display "Next Big Bonus" labels (e.g., "Lv 25: +400% DMG") on the upgrade buttons.
- [ ] **3.3.4 Exponential Costing:** Real-time cost calculation on all buttons.

---

## 4. Boss & VFX Polishing

- [ ] **4.1 Interrupt Zones:** Red reticle click targets for Chapter Bosses.
- [ ] **4.2 Click Feedback:** Cursor-position shockwave particles.
- [ ] **4.3 Gold Fly-Path:** Animate coins flying from enemies to the gold odometer.
- [ ] **4.4 Combo Heat:** Screen-edge "heat" VFX at high CPS (>10).
