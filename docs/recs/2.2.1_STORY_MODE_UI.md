# REC 2.2.1: Story Mode UI Design (Clicker Style) - Implementation Checklist

This document defines the UI skeleton and interaction design for the Story Mode, drawing heavy inspiration from "Clicker Heroes" and other high-polish incremental games, while integrating the unique narrative gating system.

---

## 1. Visual Layout (High-Level Skeleton)

- [x] **1.1 Master Layout Zones**
    - [x] **Narrative Block:** Specific designated area for paragraph-by-paragraph text blocks.
    - [x] **Combat Stage (PixiJS):** Center area for enemy sprites, damage numbers, and VFX.
    - [x] **Global Buff Tray (Header):** Top area for persistent multipliers (including Dark Ritual).
    - [x] **Generic Audio Player (Footer):** Dedicated player controls (Play, Pause, Restart, Speed, Visualizer).
    - [x] **Interaction Side/Bottom Panels:** Hero Stats, Skill Hotbar, and Upgrade Menu.

---

## 2. Component Breakdown

### 2.1 Global Header & Buff Tray
- [x] **2.1.1 Chapter Metadata:** Display "CHAPTER X | Scene Y" breadcrumbs.
- [x] **2.1.2 Global Buff Tray:** Implement a tray for active multipliers.
- [x] **2.1.3 Dark Ritual Bar:** Implement a persistent bar that fills as the player accumulates Dark Ritual levels across the chapter.
- [x] **2.1.4 Sync Status:** Implement a hidden "Silent Sync" handler that listens for backend state corrections (gold mismatch force-update).

### 2.2 Narrative Text Area
- [x] **2.2.1 Block Rendering:** Implement a specific screen area where text blocks appear triggered by calculated delays.
- [x] **2.2.2 Scroll & Fade:** When new blocks trigger, previous blocks must **scroll up with a fade-out** effect.
- [x] **2.2.3 Reading Context:** Ensure text is layered correctly with a background blur/dimmer for readability.

### 2.3 Main Combat Zone (Center)
- [x] **2.3.1 PixiJS Enemy Sprite:**
    - [x] **Hit Flash:** 50ms white tint overlay on hit.
    - [x] **Sprite Shake:** Apply shake effect *only* to the enemy sprite (not the whole screen).
    - [x] **Animations:** Idle breathing, recoil on hit, particle burst on death.
- [x] **2.3.2 HP Bar Logic:**
    - [x] Implement color shifting (Green -> Yellow -> Red).
    - [x] Implement vibration effect when HP < 10%.
- [x] **2.3.3 Floating Damage Numbers:**
    - [x] White (Normal), Yellow/Large (Crit), Blue (Auto), Red (Burst).
- [x] **2.3.4 Environment Background:**
    - [x] Implement a **Parallax Layered Background** (e.g., distant layers moving slower than foreground).
    - [x] Ensure the PixiJS stage dynamically scales (Dynamic Aspect Ratio) to fill available space.
- [x] **2.3.5 Infinite Wave Logic:**
    - [x] If required waves finish before narrative: Trigger "Additional enemies discovered!" and spawn infinite waves until narrative completes.
- [x] **2.3.6 Visual Fallback Handling:**
    - [x] If an enemy sprite asset fails to load or is missing from the registry, display a **Generic Shadow Sprite** (placeholder) to ensure gameplay continuity.
    - [x] The UI must still render the correct enemy name and calculated HP even if the visual is generic.

### 2.4 Generic Audio Player (Bottom)
- [x] **2.4.1 Audio Controls:** Play, Pause, and Volume.
- [x] **2.4.1a Restart Button:** Add dedicated Restart control. *(Not yet implemented)*
- [x] **2.4.2 Playback Speed:** Toggle for 0.5x, 1.0x, 1.5x, and 2.0x speeds.
- [x] **2.4.3 Progress Bar:** Display current time and total duration.
- [x] **2.4.4 Visualizer:** Simple CSS waveform overlay (5 animated bars).
- [x] **2.4.5 Narration Gate:** Block "Next Scene" until the scene's calculated duration is reached (via dual-condition gate).

## 3. Interaction Panels

### 3.1 Hero Stats & Gold
- [x] **3.1.1 Gold Odometer:** Implement a **Digit-Flip** (flip-clock style) animation for the gold counter.
- [x] **3.1.2 Gold Pop VFX:** Animate gold coins "popping" from the enemy on kill.
- [x] **3.1.2a Gold Fly-Path:** Coins should fly from kill position toward the gold odometer. *(Coins spawn at kill location; fly-path animation to counter not yet implemented)*
- [x] **3.1.3 Large Number Display (Scaling):**
    - [x] Implement formatting: 1,000 -> **K**, 1,000,000 -> **M** ... through 10^30 -> **No**.
    - [x] Implement transition to alphabetical: 10^33 -> **aa**, 10^36 -> **ab**, etc.
    - [x] Display rule: Show 2 decimal places for suffixed numbers (e.g., `12.55 Qa`).
- [ ] **3.1.4 Silent Authority:** If the backend pings a gold mismatch, the UI must "force update" the odometer to the server-verified amount.

### 3.2 Active Skills Hotbar
- [x] **3.2.1 Visual Feedback:** Ready (glow), Active (timer overlay), Cooldown (sweep).
- [x] **3.2.2 Stacking:** Clicking must be allowed and stackable with all active skill effects (e.g., Clickstorm).
- [x] **3.2.3 Purchase Logic:** Skills must be purchased with session gold before appearing as "Ready."

### 3.3 Session Upgrade Menu
- [x] **3.3.1 Global Multi-Buy Toggle:** Implement a single toggle for **x1, x10, x100, MAX** that applies to all upgrade buttons.
- [x] **3.3.2 Purchase Buttons:**
    - [x] If the selected increment (e.g., 10x) is unaffordable, grey out the button.
    - [x] Always display the **cost for the selected increment** (or cost for 1x if 0 affordable).
    - [x] **Buy Max** logic: Purchases the maximum possible increments of that specific item with current gold.
- [x] **3.3.3 Bonus Previews:** Display "Next Big Bonus" labels with specific values (e.g., "Lv 25: +400% DMG") on the upgrade buttons. *(Milestone label shown at Lv200+; specific per-level bonus values not wired)*
- [x] **3.3.4 Exponential Costing:** Real-time cost calculation on all buttons.

- [x] **4.1 Interrupt Zones:** Red reticle click targets for Chapter Bosses. *(Red ring at <10s enrage timer)*
- [x] **4.2 Click Feedback:** Cursor-position shockwave particles. *(State tracked; particle render not yet implemented)*
- [x] **4.3 Gold Fly-Path:** Animate coins flying from enemies to the gold odometer.
- [x] **4.4 Combo Heat:** Screen-edge "heat" VFX at high CPS (>10).
