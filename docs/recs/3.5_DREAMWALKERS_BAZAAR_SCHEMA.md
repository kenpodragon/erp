## 1. Migration 053 — Overview

Migration 053 introduces the Dreamwalker's Bazaar (Player Marketplace) and NPC Vendor (Salvage) systems.

**New Tables (4):**
- `marketplace_listings` — Active and historical item listings
- `marketplace_trades` — Completed trade records (buyer + seller)
- `marketplace_notifications` — Trade notifications for players
- `marketplace_price_history` — Price change audit log

**Altered Tables (3):**
- `players` — Add `marketplace_slots_purchased` column
- `player_artifacts` — Add `marketplace_listing_id` FK column
- `player_inventory` — Add `marketplace_listing_id` FK column

**Modified Constraints (2):**
- `shard_transactions.source_type` CHECK — Add `'marketplace_purchase'`, `'marketplace_sale'`
- `shop_items.category` CHECK — Add `'marketplace_permit'`

**Modified Functions (1):**
- `enforce_inventory_slot_cap()` — Exclude marketplace-listed items from count

**Seed Data:**
- 7 Bazaar Permit shop items
- 4 marketplace titles
- 9 marketplace achievements (with parent chains)
- 15 game_configs keys (marketplace + salvage categories)

## 2. New Table: `marketplace_listings`

Tracks all marketplace listings (active, sold, expired, cancelled).

```sql
CREATE TABLE marketplace_listings (
    id              SERIAL PRIMARY KEY,
    seller_id       INTEGER NOT NULL REFERENCES players(id) ON DELETE CASCADE,
    buyer_id        INTEGER REFERENCES players(id) ON DELETE SET NULL,  -- populated on sale

    -- Item snapshot (denormalized for display after item transfers)
    item_type       VARCHAR(20) NOT NULL,  -- 'artifact' | 'equipment'
    item_ref_id     INTEGER NOT NULL,      -- PK in player_artifacts or player_inventory
    item_name       VARCHAR(150) NOT NULL,
    item_rarity     VARCHAR(50) NOT NULL,
    item_stats      JSONB NOT NULL DEFAULT '{}',
    item_icon_key   VARCHAR(100),
    item_gear_slot  INTEGER REFERENCES gear_slots(id) ON DELETE SET NULL,  -- equipment only
    is_curated      BOOLEAN NOT NULL DEFAULT FALSE,

    -- Pricing
    price_shards    INTEGER NOT NULL CHECK (price_shards >= 1),

    -- Status lifecycle
    status          VARCHAR(20) NOT NULL DEFAULT 'active',
    listed_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at      TIMESTAMPTZ NOT NULL,  -- listed_at + 24hr
    sold_at         TIMESTAMPTZ,
    cancelled_at    TIMESTAMPTZ,
    expired_at      TIMESTAMPTZ,
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT marketplace_listings_status_check
        CHECK (status IN ('active', 'sold', 'expired', 'cancelled')),
    CONSTRAINT marketplace_listings_item_type_check
        CHECK (item_type IN ('artifact', 'equipment'))
);

CREATE INDEX idx_mpl_seller ON marketplace_listings(seller_id);
CREATE INDEX idx_mpl_status_expires ON marketplace_listings(status, expires_at)
    WHERE status = 'active';
CREATE INDEX idx_mpl_item_name_rarity ON marketplace_listings(item_name, item_rarity)
    WHERE status = 'active';
CREATE INDEX idx_mpl_price ON marketplace_listings(price_shards, listed_at)
    WHERE status = 'active';
CREATE INDEX idx_mpl_buyer ON marketplace_listings(buyer_id)
    WHERE buyer_id IS NOT NULL;
```

**Column notes (matching live DB conventions):**
- `seller_id` / `buyer_id`: INTEGER FK to `players(id)` — matches all existing FK patterns
- `item_stats`: JSONB — matches `player_artifacts.stat_bonuses` and `inventory_items.base_stats`
- `price_shards`: INTEGER — matches `shop_items.price_shards`
- `status`: VARCHAR(20) with CHECK — matches pattern used in `player_active_boosters`
- `expires_at`: TIMESTAMPTZ — lazy expiry, checked at query time
- Timestamps: TIMESTAMPTZ — matches all existing tables

## 3. New Table: `marketplace_trades`

Records completed trades with full audit detail for both buyer and seller.

```sql
CREATE TABLE marketplace_trades (
    id              SERIAL PRIMARY KEY,
    listing_id      INTEGER NOT NULL REFERENCES marketplace_listings(id) ON DELETE CASCADE,
    buyer_id        INTEGER NOT NULL REFERENCES players(id) ON DELETE CASCADE,
    seller_id       INTEGER NOT NULL REFERENCES players(id) ON DELETE CASCADE,

    -- Item snapshot (denormalized from listing)
    item_type       VARCHAR(20) NOT NULL,
    item_ref_id     INTEGER NOT NULL,
    item_name       VARCHAR(150) NOT NULL,
    item_rarity     VARCHAR(50) NOT NULL,

    -- Financial
    price_shards    INTEGER NOT NULL,
    tax_shards      INTEGER NOT NULL DEFAULT 0,
    seller_proceeds INTEGER NOT NULL,

    -- Claim queue (equipment only, when buyer inventory is full)
    claim_status    VARCHAR(20) NOT NULL DEFAULT 'claimed',

    traded_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT marketplace_trades_claim_status_check
        CHECK (claim_status IN ('claimed', 'pending', 'discarded', 'reversed')),
    CONSTRAINT marketplace_trades_item_type_check
        CHECK (item_type IN ('artifact', 'equipment'))
);

CREATE INDEX idx_mpt_buyer ON marketplace_trades(buyer_id);
CREATE INDEX idx_mpt_seller ON marketplace_trades(seller_id);
CREATE INDEX idx_mpt_listing ON marketplace_trades(listing_id);
CREATE INDEX idx_mpt_pending_claim ON marketplace_trades(buyer_id, claim_status)
    WHERE claim_status = 'pending';
CREATE INDEX idx_mpt_traded_at ON marketplace_trades(traded_at DESC);
```

**Column notes:**
- `price_shards` / `tax_shards` / `seller_proceeds`: INTEGER — `seller_proceeds = price_shards - tax_shards`
- `claim_status`: Defaults to `'claimed'` (immediate transfer). Set to `'pending'` when buyer equipment inventory is at cap. `'discarded'` if buyer chose to discard. `'reversed'` if admin reversed the trade.
- `item_ref_id`: References `player_artifacts.id` or `player_inventory.id` depending on `item_type`. Not a FK because the referenced table varies.

## 4. New Table: `marketplace_notifications`

Stores trade notifications displayed to players on login/return (piggybacks on idle gains UI).

```sql
CREATE TABLE marketplace_notifications (
    id                  SERIAL PRIMARY KEY,
    player_id           INTEGER NOT NULL REFERENCES players(id) ON DELETE CASCADE,
    notification_type   VARCHAR(30) NOT NULL,
    title               VARCHAR(200) NOT NULL,
    message             TEXT NOT NULL,
    related_listing_id  INTEGER REFERENCES marketplace_listings(id) ON DELETE SET NULL,
    is_read             BOOLEAN NOT NULL DEFAULT FALSE,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    read_at             TIMESTAMPTZ,

    CONSTRAINT marketplace_notifications_type_check
        CHECK (notification_type IN ('item_sold', 'listing_expired', 'listing_removed'))
);

CREATE INDEX idx_mpn_player_unread ON marketplace_notifications(player_id)
    WHERE is_read = FALSE;
CREATE INDEX idx_mpn_created ON marketplace_notifications(created_at DESC);
```

**Purge policy:** Read notifications older than 30 days are deleted opportunistically (on access or via admin cleanup endpoint). Configured via `game_configs` key `marketplace_notification_retention_days`.

## 9. Modify Trigger: `enforce_inventory_slot_cap()`

Update the trigger function to exclude marketplace-listed items from the 10-item cap count.

```sql
CREATE OR REPLACE FUNCTION enforce_inventory_slot_cap()
RETURNS trigger
LANGUAGE plpgsql
AS $function$
DECLARE
    stored_count INTEGER;
BEGIN
    IF NEW.is_equipped = FALSE OR NEW.is_equipped IS NULL THEN
        SELECT COUNT(*) INTO stored_count
        FROM player_inventory
        WHERE character_id = NEW.character_id
          AND (is_equipped = FALSE OR is_equipped IS NULL)
          AND marketplace_listing_id IS NULL;
        IF stored_count >= 10 THEN
            RAISE EXCEPTION 'Inventory full: maximum 10 stored items per character.'
                USING ERRCODE = 'check_violation';
        END IF;
    END IF;
    RETURN NEW;
END;
$function$;
```

**Change:** Added `AND marketplace_listing_id IS NULL` to the `WHERE` clause. Items on the marketplace don't count against the 10-item storage cap.

## 17. Essence Credit Mechanism

Salvage Essence is credited to `player_essence.current_balance` (NUMERIC(20,4)) using the existing Essence credit pattern:

```sql
-- Equivalent SQL (done via ORM in application code)
UPDATE player_essence
SET current_balance = current_balance + :essence_amount,
    updated_at = NOW()
WHERE player_id = :player_id;

-- Also update meta progression tracking
UPDATE player_meta_progression
SET elysium_essence = elysium_essence + :essence_amount,
    total_essence_earned = total_essence_earned + :essence_amount,
    updated_at = NOW()
WHERE player_id = :player_id;
```

## 18. Shard Flow Summary

```
BUYER                          MARKETPLACE                     SELLER
  │                                │                              │
  │  debit_shards(price)           │                              │
  │ ──────────────────────────────>│                              │
  │  source_type='marketplace_purchase'                           │
  │                                │                              │
  │                                │  tax = floor(price × 0.05)  │
  │                                │  (burned — not credited)     │
  │                                │                              │
  │                                │  credit_shards(price - tax) │
  │                                │ ────────────────────────────>│
  │                                │  source_type='marketplace_sale'
  │                                │                              │
  │  transfer item                 │                              │
  │ <──────────────────────────────│── unlock from seller ────────│
  │                                │                              │
```
