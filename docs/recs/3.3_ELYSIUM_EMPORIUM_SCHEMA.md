## Pre-Existing Tables (Extended)

### `players` — New Columns

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `equipped_flair_id` | `INTEGER` | `DEFAULT NULL` | Currently equipped shop flair item. NULL = default/subscriber flair. |
| `equipped_badge_id` | `INTEGER` | `DEFAULT NULL` | Currently equipped shop badge item. NULL = default/subscriber badge frame. |
| `equipped_avatar_id` | `INTEGER` | `DEFAULT NULL` | Currently equipped shop avatar item. NULL = default class portrait. |

No FK constraint to `shop_items` — the item may be deactivated but still equipped. Application logic validates ownership on equip; unequip sets NULL.

### `player_characters` — New Columns

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `equipped_skin_id` | `INTEGER` | `DEFAULT NULL` | Currently equipped shop skin. NULL = base class default appearance. Lost when character is deleted (ownership persists in `player_shop_items`). |

Same pattern as existing `equipped_title_id` (047). No FK — skins are account-wide ownership, character-level equip.

### `shard_transactions` — CHECK Constraint Widened

The existing CHECK constraint on `source_type` (migration 046) must be widened to support new source types from 3.2 and 3.3:

**Before (046):**
```sql
CHECK (source_type IN ('achievement', 'purchase', 'refund', 'admin_grant', 'admin_deduct', 'spend'))
```

**After (051):**
```sql
CHECK (source_type IN (
    'achievement', 'purchase', 'refund', 'admin_grant', 'admin_deduct', 'spend',
    'subscription_stipend', 'subscription_refund',
    'shop_purchase', 'admin_refund'
))
```

New values:
- `'subscription_stipend'` — monthly shard stipend credit (from 3.2, constraint not previously widened)
- `'subscription_refund'` — stipend clawback on subscription refund (from 3.2)
- `'shop_purchase'` — shard debit for Emporium purchase (3.3)
- `'admin_refund'` — admin-initiated shop item refund credit (3.3)

**ALTER approach:** PostgreSQL requires dropping and re-adding the CHECK constraint:
```sql
ALTER TABLE shard_transactions DROP CONSTRAINT IF EXISTS shard_transactions_source_type_check;
ALTER TABLE shard_transactions ADD CONSTRAINT shard_transactions_source_type_check
    CHECK (source_type IN (...));
```

### `player_meta_progression` — No Schema Changes

The existing `shard_balance` field is used for debit/credit via `payment_service.debit_shards()` / `credit_shards()`.

### `game_configs` — New Seed Data Only

9 new rows seeded (category: `economy`). No column changes. Uses existing columns: `key` (PK), `value_json` (JSONB), `category`, `description`.

## New Tables

### `shop_items`

Master catalog of all purchasable shop items (cosmetics and boosters). Admin-managed.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `item_key` | `VARCHAR(60)` | `NOT NULL UNIQUE` | Machine-readable key (e.g., `'skin_void_engineer'`, `'booster_xp_1hr'`) |
| `name` | `VARCHAR(100)` | `NOT NULL` | Display name (e.g., "Void Engineer Skin") |
| `description` | `TEXT` | `DEFAULT NULL` | Flavor text / marketing description |
| `category` | `VARCHAR(20)` | `NOT NULL CHECK (category IN ('skin', 'flair', 'badge', 'avatar', 'booster'))` | Item category |
| `price_shards` | `INTEGER` | `NOT NULL CHECK (price_shards > 0)` | Price in Elysium Shards |
| `icon_path` | `VARCHAR(255)` | `DEFAULT NULL` | Relative path to icon/thumbnail asset |
| `class_restriction` | `INTEGER` | `DEFAULT NULL REFERENCES character_classes(id) ON DELETE SET NULL` | NULL = universal. Set to class ID for class-specific skins. |
| `item_metadata` | `JSONB` | `DEFAULT NULL` | Category-specific config. Boosters: `{"boost_type":"xp","magnitude":1.25,"duration_seconds":3600}`. Skins: `{"portrait":"path","avatar_config":{...},"battle_bar":"path"}`. Flair: `{"border_color":"#8B00FF","icon":"void_spiral"}`. **Note:** Named `item_metadata` (not `metadata`) to avoid conflict with SQLAlchemy's reserved `metadata` class attribute. |
| `is_active` | `BOOLEAN` | `NOT NULL DEFAULT TRUE` | Soft-delete flag. FALSE = hidden from shop. |
| `is_featured` | `BOOLEAN` | `NOT NULL DEFAULT FALSE` | Whether item appears in the Featured section. |
| `featured_from` | `TIMESTAMPTZ` | `DEFAULT NULL` | Start of featured spotlight window. NULL = featured immediately if `is_featured = TRUE`. |
| `featured_until` | `TIMESTAMPTZ` | `DEFAULT NULL` | End of featured spotlight window. NULL = featured indefinitely while `is_featured = TRUE`. |
| `available_from` | `TIMESTAMPTZ` | `DEFAULT NULL` | Start of availability window. NULL = available immediately. |
| `available_until` | `TIMESTAMPTZ` | `DEFAULT NULL` | End of availability window. NULL = permanently available. |
| `sort_order` | `INTEGER` | `NOT NULL DEFAULT 0` | Display ordering within category |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | |

**Indexes:**
- `idx_shop_items_category_active` ON `(category, sort_order)` WHERE `is_active = TRUE` — catalog browsing
- `idx_shop_items_featured` ON `(is_featured, featured_from, featured_until)` WHERE `is_featured = TRUE` — featured section query
- `idx_shop_items_availability` ON `(available_from, available_until)` WHERE `available_until IS NOT NULL` — limited-time item filtering

**Trigger:** `trg_shop_items_updated_at` — auto-sets `updated_at` on UPDATE.

### `shop_bundles`

Curated bundle packages. Separate from `shop_items` because bundles contain multiple items and have their own pricing/discount logic.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `bundle_key` | `VARCHAR(60)` | `NOT NULL UNIQUE` | Machine-readable key (e.g., `'adventurers_starter_pack'`) |
| `name` | `VARCHAR(100)` | `NOT NULL` | Display name |
| `description` | `TEXT` | `DEFAULT NULL` | Marketing description |
| `price_shards` | `INTEGER` | `NOT NULL CHECK (price_shards > 0)` | Discounted bundle price |
| `original_price_shards` | `INTEGER` | `NOT NULL CHECK (original_price_shards > 0)` | Sum of individual item prices (for discount display) |
| `discount_pct` | `INTEGER` | `NOT NULL DEFAULT 20 CHECK (discount_pct >= 0 AND discount_pct <= 100)` | Discount percentage shown in UI |
| `icon_path` | `VARCHAR(255)` | `DEFAULT NULL` | Bundle icon/thumbnail |
| `is_active` | `BOOLEAN` | `NOT NULL DEFAULT TRUE` | Soft-delete flag |
| `is_featured` | `BOOLEAN` | `NOT NULL DEFAULT FALSE` | Whether bundle appears in Featured section |
| `featured_from` | `TIMESTAMPTZ` | `DEFAULT NULL` | Featured window start |
| `featured_until` | `TIMESTAMPTZ` | `DEFAULT NULL` | Featured window end |
| `available_from` | `TIMESTAMPTZ` | `DEFAULT NULL` | Availability window start |
| `available_until` | `TIMESTAMPTZ` | `DEFAULT NULL` | Availability window end |
| `sort_order` | `INTEGER` | `NOT NULL DEFAULT 0` | Display ordering |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | |

**Indexes:**
- `idx_shop_bundles_active` ON `(is_active, sort_order)` WHERE `is_active = TRUE`

**Trigger:** `trg_shop_bundles_updated_at` — auto-sets `updated_at` on UPDATE.

### `shop_bundle_items`

Junction table linking bundles to their contained items.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `bundle_id` | `INTEGER` | `NOT NULL FK shop_bundles ON DELETE CASCADE` | Parent bundle |
| `shop_item_id` | `INTEGER` | `NOT NULL FK shop_items ON DELETE CASCADE` | Item included in bundle |
| `sort_order` | `INTEGER` | `NOT NULL DEFAULT 0` | Display order within bundle contents list |

**Unique constraint:** `(bundle_id, shop_item_id)` — no duplicate items in a bundle.

**Index:**
- `idx_bundle_items_bundle` ON `(bundle_id, sort_order)` — contents listing

### `player_shop_items`

Player ownership of shop items. Separate from `player_inventory` (which has slot limits from 2.4.2). No ownership cap — players can own unlimited cosmetics.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `player_id` | `INTEGER` | `NOT NULL FK players ON DELETE CASCADE` | Owning player (account-wide, persists through character deletion) |
| `shop_item_id` | `INTEGER` | `DEFAULT NULL FK shop_items ON DELETE SET NULL` | The owned item. NULL for bundle-level ownership records. |
| `source_bundle_id` | `INTEGER` | `DEFAULT NULL FK shop_bundles ON DELETE SET NULL` | If acquired through a bundle purchase. NULL for direct purchases. |
| `status` | `VARCHAR(20)` | `NOT NULL DEFAULT 'owned' CHECK (status IN ('owned', 'refunded'))` | Ownership state |
| `purchased_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | When the item was acquired |
| `refunded_at` | `TIMESTAMPTZ` | `DEFAULT NULL` | When admin refund was processed (if ever) |

**Indexes:**
- `idx_psi_player_status` ON `(player_id, status)` WHERE `status = 'owned'` — owned items query
- `idx_psi_player_item` ON `(player_id, shop_item_id)` WHERE `status = 'owned'` — duplicate ownership check
- `idx_psi_player_bundle` ON `(player_id, source_bundle_id)` WHERE `source_bundle_id IS NOT NULL` — bundle purchase check

**Unique constraint:** `(player_id, shop_item_id)` WHERE `status = 'owned'` — partial unique index prevents duplicate ownership of the same item. Refunded items don't block re-purchase.

---

### `player_active_boosters`

Tracks active and expired time-limited boosters. One active row per boost type per player.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `player_id` | `INTEGER` | `NOT NULL FK players ON DELETE CASCADE` | Player with the active booster |
| `boost_type` | `VARCHAR(20)` | `NOT NULL CHECK (boost_type IN ('xp', 'essence', 'drop_rate'))` | Type of boost |
| `magnitude` | `NUMERIC(5,2)` | `NOT NULL CHECK (magnitude > 1.0)` | Multiplier value (e.g., 1.25, 1.5, 2.0) |
| `duration_seconds` | `INTEGER` | `NOT NULL CHECK (duration_seconds > 0)` | Total duration in active-play seconds |
| `elapsed_seconds` | `INTEGER` | `NOT NULL DEFAULT 0 CHECK (elapsed_seconds >= 0)` | Accumulated active-play seconds. Incremented on session complete, booster pings, and idle training ticks. |
| `shop_item_id` | `INTEGER` | `DEFAULT NULL FK shop_items ON DELETE SET NULL` | The shop item that created this booster (last purchase, for display/refund lookup) |
| `status` | `VARCHAR(20)` | `NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'expired'))` | Booster lifecycle state |
| `activated_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | When the booster was first activated |
| `expired_at` | `TIMESTAMPTZ` | `DEFAULT NULL` | When the booster expired (elapsed >= duration or admin refund) |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Last time elapsed_seconds was incremented |

**Indexes:**
- `idx_pab_player_active` ON `(player_id, boost_type)` WHERE `status = 'active'` — active booster lookup (critical path for `get_effective_multipliers()`)
- `idx_pab_player_history` ON `(player_id, activated_at DESC)` — booster history/audit

**Trigger:** `trg_player_active_boosters_updated_at` — auto-sets `updated_at` on UPDATE.

**Constraint note:** There is no unique constraint on `(player_id, boost_type)` WHERE `status = 'active'` at the DB level — uniqueness is enforced by application logic in `_activate_booster()` which finds and extends existing active boosters rather than creating duplicates. This allows the `expired` rows to remain for audit.
