## 1. New Tables

### 1.1 Player Entity Discovery *(Migration 042)*

Tracks per-player, per-entity encounter and kill counts with ranked reveal progression.

```sql
CREATE TABLE player_entity_discovery (
    id SERIAL PRIMARY KEY,
    player_id INTEGER NOT NULL REFERENCES players(id) ON DELETE CASCADE,
    entity_id INTEGER NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
    encounters INTEGER NOT NULL DEFAULT 0,
    kills INTEGER NOT NULL DEFAULT 0,
    rank VARCHAR(2) DEFAULT NULL,  -- NULL, 'E', 'C', 'A', 'SS' (denormalized cache)
    first_seen_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    is_new BOOLEAN NOT NULL DEFAULT TRUE,  -- Badge flag, cleared on view in Codex
    UNIQUE (player_id, entity_id)
);

CREATE INDEX idx_ped_player ON player_entity_discovery(player_id);
CREATE INDEX idx_ped_entity ON player_entity_discovery(entity_id);
CREATE INDEX idx_ped_player_rank ON player_entity_discovery(player_id, rank);
```

**Rank computation:** The `rank` column is a denormalized cache updated on each kill for fast filtering/sorting. Rank is derived from `kills` vs. `game_configs` thresholds:
- `NULL` = encountered but never killed
- `E` = kills >= `codex_rank_e` (default: 1)
- `C` = kills >= `codex_rank_c` (default: 25)
- `A` = kills >= `codex_rank_a` (default: 100)
- `SS` = kills >= `codex_rank_ss` (default: 500)

### 1.2 Player Discovery Log *(Migration 042)*

Tracks discovered skills, item components, and effects.

```sql
CREATE TABLE player_discovery_log (
    id SERIAL PRIMARY KEY,
    player_id INTEGER NOT NULL REFERENCES players(id) ON DELETE CASCADE,
    discovery_type VARCHAR(20) NOT NULL,  -- 'skill', 'item_prefix', 'item_suffix', 'item_quality', 'lore_tag', 'effect'
    reference_id INTEGER NOT NULL,         -- FK to the relevant table (skill_id, prefix_id, etc.)
    discovered_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    is_new BOOLEAN NOT NULL DEFAULT TRUE,  -- Badge flag, cleared on view in Library
    UNIQUE (player_id, discovery_type, reference_id)
);

CREATE INDEX idx_pdl_player ON player_discovery_log(player_id);
CREATE INDEX idx_pdl_player_type ON player_discovery_log(player_id, discovery_type);
```

**Note:** `reference_id` is not a formal FK constraint because it references different tables depending on `discovery_type`. Application-level validation ensures referential integrity.

### 1.3 Chat Channels *(Migration 044)*

Supports multi-channel architecture. Only the `global` channel is active in 2.6.

```sql
CREATE TABLE chat_channels (
    id VARCHAR(50) PRIMARY KEY,          -- e.g., 'global', 'chapter_1_3'
    name VARCHAR(100) NOT NULL,          -- Display name
    channel_type VARCHAR(20) NOT NULL DEFAULT 'global',  -- 'global', 'chapter', 'book', 'custom'
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by INTEGER REFERENCES players(id) ON DELETE SET NULL  -- Admin who created (NULL for system)
);

-- Seed the default global channel
INSERT INTO chat_channels (id, name, channel_type, is_active)
VALUES ('global', 'Global Chat', 'global', TRUE);
```

**Important:** Chat messages are NOT stored in the database. They are held in an in-memory rolling buffer on the server and lost on restart. This table only manages channel metadata.

## 2. Table Alterations

### 2.1 Entities — Family Grouping *(Migration 042)*

```sql
ALTER TABLE entities
ADD COLUMN entity_family VARCHAR(100) DEFAULT NULL;

CREATE INDEX idx_entities_family ON entities(entity_family);

-- entity_family is populated via a one-time classification tool script
-- (tools/classify_entity_families.py) followed by manual SQL review.
-- Examples: 'Wraith', 'Golem', 'Shade', 'Construct', etc.
-- Entities with NULL entity_family appear as standalone entries in the Codex.
```

### 2.2 Tick Request Extension *(No migration — API change only)*

The `/tick` endpoint request body is extended with optional discovery fields. No schema change needed — this is handled in the Pydantic request model:

```python
# Extended TickRequest (backend/routes/story_mode.py)
class EntityEncounter(BaseModel):
    entity_id: int
    encounters: int = 0
    kills: int = 0

class ItemDiscovery(BaseModel):
    type: str        # 'item_prefix', 'item_suffix', 'item_quality', 'lore_tag', 'skill', 'effect'
    reference_id: int

class TickRequest(BaseModel):
    # Existing fields:
    clicks: int
    elapsed_ms: int
    zone: int
    wave: int
    gold_delta: float
    waves_completed_delta: int = 0
    # New optional discovery fields:
    entity_encounters: Optional[List[EntityEncounter]] = None
    item_discoveries: Optional[List[ItemDiscovery]] = None
```

## 5. Removed from Legacy Schema

The following items from the original schema doc have been **removed or replaced**:

| Legacy Item | Reason |
| :--- | :--- |
| `chat_messages` table | Chat is in-memory only — no DB persistence |
| `registry_kills` JSONB on `player_progress` | Replaced with `player_entity_discovery` table (proper relational) |
| `registry_discoveries` JSONB on `player_progress` | Replaced with `player_discovery_log` table |
| `has_completed_onboarding` on `player_progress` | Moved to `player.settings` JSONB (already exists) |
| JSONB atomic update functions | No longer needed — replaced by standard INSERT/UPDATE on relational tables |
| `discrepancy_score` on `admin_audit_log` | Anti-cheat anomalies logged to `activity_events` instead |
| `is_hidden` on `entities` | Replaced by `entity_family` column + visibility logic based on `first_appearance_scene_id` and `entity_scene_appearances` |
| Weekly chat pruning worker | Not needed — chat is in-memory |
