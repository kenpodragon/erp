# REC 3.2: Subscription — Elysium Ascendant

This document defines the complete requirements for the Elysium Ascendant subscription system — a single-tier recurring revenue model providing cosmetic, convenience, and soft-boost benefits.

## 1. Overview & Scope

### 1.1 Purpose
Section 3.2 adds a single recurring subscription tier — **Elysium Ascendant** — that provides a mix of cosmetic perks, quality-of-life convenience, and soft gameplay boosts. The subscription is positioned as a "supporter plus" tier: it accelerates collection and progression without gating content or creating a pay-to-win advantage. There is no PVP in the game, so boosts primarily let subscribers accumulate things faster.

### 1.2 Scope Boundaries
- **In Scope:** Stripe Subscription lifecycle, benefit application/revocation, business-day grace period, monthly shard stipend, loyalty streak bonuses, player-facing management page, subscriber indicators in chat and leaderboards, subscription achievements, admin management tools.
- **Out of Scope:** Multiple subscription tiers (single tier only), free trials (deferred), mobile app store billing, Stripe Billing Portal (we build our own management UI).
- **Dependencies:** Stripe foundation (3.1), Firebase Auth (1.0), Chat system (2.6.4), Leaderboard/Achievement system (2.7.3), Shard economy (2.7.0/3.1).

## 2. Subscription Model

### 2.1 Single Tier: Elysium Ascendant

| Plan | Billing | Price (USD) | Effective $/mo |
|:---|:---|:---|:---|
| Monthly | Every month | $1.99/month | $1.99 |
| Annual | Every year | $19.90/year | ~$1.66 (2 months free) |

- **No free trial.** Players pay from day one.
- **No multiple tiers.** One subscription, two billing frequencies.
- **USD only** at launch (consistent with 3.1).

### 2.2 Plan Switching
- Players can switch between monthly and annual at any time.
- **Proration applies:** Stripe prorates the billing. Switching from monthly to annual mid-cycle credits the unused portion of the monthly plan toward the annual price. Switching from annual to monthly is similarly prorated.
- Benefits continue uninterrupted during the switch.

### 2.3 Price Changes
- If the subscription price is changed by an admin, **all subscribers move to the new price** on their next billing cycle. No grandfathering.
- Stripe handles this via `price` updates on the subscription object.
- Players receive an email from Stripe notifying them of the price change before their next renewal.

## 3. Subscription Benefits

### 3.1 Benefit Categories
The Elysium Ascendant subscription provides three categories of benefits:

#### A. Soft Gameplay Boosts (Accelerators)
These speed up progression and collection. Since ERP has no PVP, these provide convenience rather than competitive advantage.

| Boost | Base Value | Description |
|:---|:---|:---|
| XP Multiplier | 1.15x (+15%) | Applies to all Character XP earned (Story Mode completion, Idle Training) |
| Essence Multiplier | 1.15x (+15%) | Applies to all Elysium Essence earned (Story completion, Idle Training, achievements) |
| Drop Rate Boost | 1.10x (+10%) | Applies to artifact drop chance rolls (curated + generated) |
| Idle Training Speed | 1.10x (+10%) | Reduces idle skill training time by 10% |

- All boost values are stored in `game_configs` and admin-adjustable.
- Boosts stack multiplicatively with shop boosters (3.3) — e.g., 1.15x sub XP × 1.25x shop booster = 1.4375x total.
- Boosts are applied server-side. The client displays a "Ascendant" indicator on boosted values.

#### B. Monthly Shard Stipend
| Benefit | Value | Description |
|:---|:---|:---|
| Monthly Shards | 150 Shards | Credited on subscription renewal date each month |

- **Annual subscribers** receive 150 shards on each monthly anniversary of their subscription start date (12 credits per year = 1,800 shards total — more than Starter Pack value at $0.99 × 12 = $11.88). Anniversary stipend credits are evaluated lazily on-access — credited the next time the player's subscription status is checked (login, status page, or any boost-dependent action).
- Stipend is logged as `shard_transactions` with `source_type = 'subscription_stipend'`.
- If the player's subscription lapses, unclaimed stipends are forfeited (no retroactive credit on re-subscribe).
- Stipend crediting is idempotent — uses the billing period start date as the dedup key.

#### C. Cosmetic & Social Perks
| Perk | Description |
|:---|:---|
| **Ascendant Badge** | A golden star (★) badge displayed next to the player's name in chat messages |
| **Leaderboard Indicator** | An "Ascendant" frame/glow on the player's rank card in Hall of Echoes |
| **Exclusive Title: "the Ascendant"** | A suffix title available only to active subscribers. Auto-unequipped on lapse. |
| **Exclusive Chat Flair** | A unique "Ascendant" chat name color/border (distinct from purchasable flair) |
| **Profile Badge** | "Elysium Ascendant" badge on player profile page |

- Cosmetic perks are **immediately revoked** when the subscription lapses (after grace period).
- The title "the Ascendant" is unequipped automatically but not deleted — it becomes re-equippable on re-subscription.

### 3.2 Dual-Track Loyalty System
ERP tracks two independent counters per subscriber:

| Counter | Description | Resets on Lapse? |
|:---|:---|:---|
| **Continuous Streak** | Consecutive months with an active subscription. Drives boost escalation. | **Yes** — resets to 0 on any lapse. |
| **Cumulative Months** | Total months ever subscribed (lifetime). Drives milestone rewards (titles, shard bonuses). | **No** — never resets. |

#### A. Continuous Streak → Boost Escalation
The continuous streak determines the player's active boost multipliers. These bonuses are **only active while subscribed** and are based on the current unbroken streak.

| Continuous Streak | Bonus | Effective XP | Effective Essence | Effective Drop | Effective Training |
|:---|:---|:---|:---|:---|:---|
| **1 month** (base) | — | 1.15x | 1.15x | 1.10x | 1.10x |
| **3 months** | +5% XP, +5% Essence | 1.20x | 1.20x | 1.10x | 1.10x |
| **6 months** | +5% XP, +5% Essence, +5% Drop | 1.25x | 1.25x | 1.15x | 1.10x |
| **12 months** | +5% XP, +5% Essence, +5% Drop | 1.30x | 1.30x | 1.20x | 1.10x |
| **24 months** | +5% Training Speed, +50 shards/mo | 1.30x | 1.30x | 1.20x | 1.15x |
| **36 months** | +50 shards/mo (total +100) | 1.30x | 1.30x | 1.20x | 1.15x |

- If a player's streak is 8 months, they have the 6-month bonuses (latest milestone at or below their streak).
- The +50/+100 monthly shards at 24/36 months stack with the base 150 stipend (200 at 24mo, 250 at 36mo).
- **On lapse:** Streak resets to 0. When re-subscribing, boosts start fresh at the 1-month base level.

#### B. Cumulative Months → Milestone Rewards
Cumulative months track total lifetime subscription time. These milestones are checked on every renewal regardless of streak.

| Cumulative Months | Reward |
|:---|:---|
| **1 month** | Title: "the Patron" (suffix) |
| **6 months** | Title: "the Devoted" (suffix) |
| **12 months** | Title: "the Eternal Ascendant" (suffix) |
| **24 months** | Title: "Architect of Elysium" (prefix) |
| **36 months** | Title: "Voidwalker Ascendant" (prefix) |
| **48 months** | Title: "Keeper of the Spire" (prefix) |
| **60 months** | Title: "Elysium Incarnate" (prefix) |

- **Cumulative titles are permanently earned.** Once unlocked, they persist even if the subscription lapses.
- A player who subscribes for 1 month, cancels for a year, then subscribes for 5 more months earns the 6-month cumulative title — even though their continuous streak is only 5 months.
- Cumulative months are monotonically increasing and never decrease.

#### C. Loyalty Configuration
- **All streak thresholds, boost values, and cumulative milestones are stored in `game_configs`** as JSON structures, admin-adjustable.
- Continuous streak config key: `subscription_streak_bonuses` (JSON array of `{ months, xp_bonus, essence_bonus, drop_bonus, training_bonus, stipend_bonus }`).
- Cumulative milestone config key: `subscription_cumulative_milestones` (JSON array of `{ months, reward_type, reward_value }`).
- Gifted subscription periods do NOT count toward either counter by default (admin-configurable via `gift_counts_toward_loyalty` game_config, default: FALSE).

### 3.3 What Subscribers Do NOT Get
To prevent pay-to-win perception:
- No exclusive content (no subscriber-only chapters, scenes, bosses, or story).
- No exclusive equipment or artifacts (cosmetics only — no stat items).
- No marketplace advantages (no fee discounts, no priority listing, per 3.0 Decision #12).
- No ability to skip or bypass game content.
- No additional lives, retries, or boss timer extensions.

## 4. Subscription Lifecycle

### 4.1 Subscribe Flow
1. Player navigates to the Subscription page (accessible from Hub sidebar or Shop page).
2. Player selects Monthly ($1.99) or Annual ($19.90).
3. Frontend calls `POST /api/subscriptions/create` with `plan_key`.
4. Backend creates/reuses a Stripe Customer (same flow as 3.1 — `get_or_create_stripe_customer()`).
5. Backend creates a Stripe Checkout Session in `subscription` mode:
   - `mode = "subscription"`
   - `line_items`: The selected price (monthly or annual).
   - `metadata`: `player_id`, `plan_key`.
   - `success_url`: Redirect back to subscription page with confirmation.
   - `cancel_url`: Redirect back to subscription page.
6. Frontend redirects to Stripe Checkout.
7. On completion, Stripe fires `checkout.session.completed` → webhook creates/activates subscription record.
8. On success redirect, frontend polls subscription status.

### 4.2 Renewal Flow
1. Stripe automatically charges the player on their renewal date.
2. On success: `invoice.paid` webhook fires → backend extends `current_period_end`, increments streak, credits shard stipend.
3. On failure: `invoice.payment_failed` webhook fires → backend marks subscription as `past_due`, starts grace period countdown.

### 4.3 Cancellation Flow
- Player cancels from the Subscription Management page.
- Frontend calls `POST /api/subscriptions/cancel`.
- Backend calls `stripe.Subscription.modify(cancel_at_period_end=True)`.
- **Benefits continue until the end of the current paid period.** No prorated refund.
- Subscription status becomes `canceling` (active but won't renew).
- At period end, Stripe fires `customer.subscription.deleted` → backend revokes benefits.
- Player can re-activate before the period ends by calling `POST /api/subscriptions/reactivate` → backend calls `stripe.Subscription.modify(cancel_at_period_end=False)`.

### 4.4 Plan Switch Flow
- Player switches from monthly to annual (or vice versa).
- Frontend calls `POST /api/subscriptions/switch` with `new_plan_key`.
- Backend calls `stripe.Subscription.modify()` with the new price ID and `proration_behavior = "create_prorations"`.
- Benefits continue uninterrupted.
- Streak counter is unaffected by plan switches.

### 4.5 Failed Payment & Grace Period (Business-Day Logic)
When a renewal payment fails:

1. `invoice.payment_failed` webhook fires.
2. Backend marks subscription as `past_due` and records `grace_period_start` (UTC timestamp).
3. **Grace period extends until 23:59:59 UTC of the next US business day after the failure:**
   - A "business day" is Monday–Friday, excluding US federal holidays.
   - The "next business day" is the first business day **after** the calendar day (UTC) on which the failure occurred.
   - If payment fails at any time on Tuesday → next business day is Wednesday → grace expires Wednesday 23:59:59 UTC.
   - If payment fails at any time on Friday → Saturday and Sunday are non-business days → next business day is Monday → grace expires Monday 23:59:59 UTC.
   - If payment fails on Friday and Monday is a holiday → next business day is Tuesday → grace expires Tuesday 23:59:59 UTC.
   - If payment fails on Wednesday and Thursday is Thanksgiving → next business day is Friday → grace expires Friday 23:59:59 UTC.
4. During the grace period:
   - **All benefits remain active.** The player sees a "Payment issue — please update your payment method" banner.
   - Stripe retries the payment automatically (up to 4 retries over ~3 weeks by default, but our grace period is independent of Stripe's retry schedule).
5. If payment succeeds during grace → status returns to `active`, banner clears.
6. If grace period expires without payment → status becomes `expired`, benefits are revoked, continuous streak resets to 0.

**All timestamps and calculations use UTC.** Holiday dates are determined using UTC calendar dates.

**US Federal Holidays (hardcoded + admin-overridable):**
New Year's Day, MLK Day, Presidents' Day, Memorial Day, Juneteenth, Independence Day, Labor Day, Columbus Day, Veterans Day, Thanksgiving, Christmas Day. Observed dates (Monday shift for Saturday/Sunday holidays) are used.

An admin-configurable `subscription_custom_holidays` game_config (JSON array of ISO date strings, e.g., `["2026-12-24", "2027-01-02"]`) allows adding additional closure dates.

### 4.6 Expiration & Benefit Revocation
When a subscription expires (cancellation end-of-period or grace period exhaustion):
1. Set subscription status to `expired`.
2. Set `is_ascendant = FALSE` on the player record.
3. Unequip the "the Ascendant" title if currently equipped (do NOT delete the title record — it can be re-equipped on re-subscribe).
4. Remove Ascendant chat badge and flair.
5. Remove Ascendant leaderboard indicator.
6. Remove all boost multipliers.
7. Stop shard stipend crediting.
8. Reset **continuous streak** to 0. **Cumulative months are NOT affected.**
9. **All cumulative titles** (Patron, Devoted, Eternal Ascendant, Architect of Elysium, etc.) are NOT revoked — they are permanently earned.

### 4.7 Re-subscription
- A player who previously subscribed and lapsed can re-subscribe at any time.
- No "welcome back" incentive — same price, same benefits, same flow.
- **Continuous streak** restarts from 0. **Cumulative months** resume from where they left off.
- "the Ascendant" title becomes equippable again.
- Previously earned cumulative titles remain available.

## 5. Stripe Integration Details

### 5.1 Stripe Products & Prices
Create one Stripe Product with two Price objects:

| Product | Price Key | Billing | Amount |
|:---|:---|:---|:---|
| Elysium Ascendant | `ascendant_monthly` | Monthly recurring | $1.99/mo |
| Elysium Ascendant | `ascendant_annual` | Yearly recurring | $19.90/yr |

- Stripe Price IDs are stored in `game_configs` so they can be updated without code deployment.
- If the price changes, new Stripe Price objects are created and existing subscriptions are migrated to the new price on their next billing cycle.

### 5.2 Webhook Events (New)
These events extend the existing webhook handler in `backend/routes/webhooks.py`:

| Event | Action |
|:---|:---|
| `checkout.session.completed` (mode=subscription) | Create/activate subscription record, set `is_ascendant = TRUE` (no stipend yet — waits for `invoice.paid`) |
| `invoice.paid` | Extend `current_period_end`, increment continuous streak + cumulative months, credit shard stipend (including initial), check loyalty milestones |
| `invoice.payment_failed` | Mark `past_due`, start grace period, trigger banner |
| `customer.subscription.updated` | Sync plan changes (monthly↔annual switch), price updates |
| `customer.subscription.deleted` | Revoke all benefits, reset continuous streak |
| `charge.refunded` (subscription) | Stipend clawback, immediate cancellation, cumulative month decrement (see §10.7) |

### 5.3 Subscription Checkout vs. Purchase Checkout
The existing `POST /api/webhooks/stripe` handler routes by event type. The `checkout.session.completed` handler must distinguish between:
- `mode = "payment"` → existing 3.1 shard purchase flow
- `mode = "subscription"` → new 3.2 subscription activation flow

This is determined from the Stripe session object's `mode` field.

## 8. Boost Application (Server-Side)

### 8.1 Where Boosts Apply

| System | How Boost Is Applied | Code Location |
|:---|:---|:---|
| Story Mode XP | Multiply XP earned at `/complete` by subscriber XP multiplier | `backend/routes/story_mode.py` |
| Idle Training XP | Multiply XP tick by subscriber XP multiplier | `backend/routes/idle_training.py` |
| Essence (Story) | Multiply Essence earned at `/complete` by subscriber Essence multiplier | `backend/routes/story_mode.py` |
| Essence (Idle) | Multiply Essence earned per level-up by subscriber Essence multiplier | `backend/routes/idle_training.py` |
| Essence (Achievement) | Multiply Essence reward by subscriber Essence multiplier | `backend/services/achievement_service.py` |
| Artifact Drop Chance | Multiply drop chance roll threshold by subscriber Drop multiplier | `backend/services/artifact_service.py` |
| Idle Training Speed | Multiply training tick rate by subscriber Speed multiplier (reduces time) | `backend/routes/idle_training.py` |

### 8.2 Boost Calculation
Boosts are determined by the **continuous streak** (not cumulative months). The system finds the highest streak milestone at or below the player's current continuous streak and applies its bonuses.

```
effective_multiplier = base_subscription_boost + sum(streak_bonuses_at_or_below_current_streak)
```

Example: A player with a 8-month continuous streak:
- Base: 1.15x
- 3-month streak bonus: +0.05
- 6-month streak bonus: +0.05
- (12-month not reached yet)
- **Effective XP: 1.25x**

Example: A player who subscribed for 14 months, lapsed, and is now 2 months into a new streak:
- Continuous streak: 2 months → only base boosts apply
- Cumulative months: 16 → has earned the 12-month cumulative title
- **Effective XP: 1.15x** (base only — no streak bonuses yet)

### 8.3 Boost Stacking with Shop Boosters (3.3)
When shop boosters are implemented in 3.3, subscription boosts and shop boosters stack **multiplicatively**:
```
total_multiplier = subscription_multiplier × shop_booster_multiplier
```
Example: 1.25x sub XP × 1.5x shop booster = 1.875x total XP.

### 8.4 Boost Resolution
A utility function `get_subscriber_multipliers(player_id)` returns the current effective multipliers for a given player:
```python
{
    "xp": 1.25,              # Base 1.15 + streak bonuses
    "essence": 1.25,
    "drop_rate": 1.15,
    "training_speed": 1.10,
    "stipend_shards": 150,   # Base 150 + streak bonus (0 at this streak)
    "is_ascendant": True,
    "continuous_streak": 8,
    "cumulative_months": 14
}
```
If the player is not subscribed, all multipliers return 1.0 and stipend returns 0.

## 9. Admin Management

### 9.1 Admin Subscription Endpoints
All endpoints under `POST /api/admin/subscriptions/` require admin JWT auth.

| Endpoint | Description |
|:---|:---|
| `GET /api/admin/subscriptions/` | List all subscriptions (paginated, filterable by status/plan) |
| `GET /api/admin/subscriptions/{player_id}` | Get a specific player's subscription details |
| `POST /api/admin/subscriptions/{player_id}/gift` | Grant a free subscription period (N days/months) |
| `POST /api/admin/subscriptions/{player_id}/extend` | Extend current subscription by N days |
| `POST /api/admin/subscriptions/{player_id}/cancel` | Force-cancel a player's subscription immediately |
| `PATCH /api/admin/subscriptions/{player_id}/streak` | Override continuous streak and/or cumulative months (for support edge cases) |

### 9.2 Gift Subscriptions
- Admins can grant free subscription periods without Stripe billing.
- A gifted subscription creates a `player_subscription` record with `source = 'admin_gift'` and a set `current_period_end`.
- Benefits apply identically to paid subscriptions.
- Gifted periods do NOT count toward either loyalty counter by default (admin-configurable via `gift_counts_toward_loyalty` game_config, default: FALSE).
- At the end of the gifted period, the player must subscribe via Stripe to continue.

### 9.3 Subscription Metrics Dashboard
The following metrics are tracked and displayed in the admin panel (3.6):

| Metric | Description |
|:---|:---|
| Active Subscribers | Count of currently active subscriptions |
| Monthly vs. Annual Split | Breakdown by plan type |
| MRR (Monthly Recurring Revenue) | `(monthly_count × $1.99) + (annual_count × $19.90 / 12)` |
| ARR (Annual Run Rate) | `MRR × 12` |
| Churn Rate | `(expired in period / active at start of period) × 100` |
| Conversion Rate | `(ever subscribed / total players) × 100` |
| Average Lifetime (months) | Mean subscription duration before cancellation |
| Reactivation Rate | `(re-subscriptions / total cancellations) × 100` |
| Streak Distribution | Histogram of streak counts (1mo, 3mo, 6mo, 12mo, 24mo+) |
| Stipend Shards Distributed | Total shards credited via subscription stipends this period |

## 10. Error Handling & Edge Cases

### 10.1 Concurrent Subscription Attempts
- Only one active subscription per player is allowed.
- `POST /api/subscriptions/create` checks for existing `active` or `past_due` subscription before creating a new Checkout Session.
- If a player has an active subscription and attempts to subscribe again → 400 error: "You already have an active subscription."

### 10.2 Subscription During Active Dispute
- If `account_flag = 'dispute'` on the player record, subscription creation is blocked (same as shard purchases in 3.1).
- Existing subscriptions are NOT automatically canceled during disputes (Stripe handles this independently).

### 10.3 Webhook Ordering
- Stripe may deliver webhooks out of order. The handler must be resilient:
  - `invoice.paid` before `checkout.session.completed` → skip (log warning). The checkout handler creates the subscription row; the next `invoice.paid` or lazy stipend credit catches up.
  - Multiple `invoice.payment_failed` events → idempotent, only start grace period once.
  - `customer.subscription.deleted` after already expired → no-op.

### 10.4 Stripe Customer Without Prior Purchase
- If a player subscribes without ever buying shards, they may not have a `stripe_customer_id` yet.
- The subscribe flow reuses `get_or_create_stripe_customer()` from 3.1 — same behavior.

### 10.5 Grace Period Edge Cases
- **Payment fails at 23:30 UTC Friday:**
  - Saturday and Sunday are non-business days.
  - Next business day after Friday is Monday.
  - Grace expires: Monday 23:59:59 UTC.
- **Payment fails Tuesday before Thanksgiving (Thursday):**
  - Next business day after Tuesday is Wednesday.
  - Grace expires: Wednesday 23:59:59 UTC.
  - (If payment had failed Wednesday, next business day would be Friday since Thursday is Thanksgiving.)
- **Payment fails on a Wednesday and Thursday+Friday are both holidays:**
  - Next business day is Monday.
  - Grace expires: Monday 23:59:59 UTC.
- **All calculations use UTC** for both holiday date determination and deadline expression.

### 10.6 Stipend Crediting Edge Cases
- **Annual subscribers:** Stipend credits on the monthly anniversary date. If the anniversary date doesn't exist in a short month (e.g., subscribed Jan 31, February has no 31st), credit on the last day of that month.
- **Grace period stipend:** If the subscription is `past_due` when a stipend would be due, the stipend is NOT credited. It is forfeited.
- **Admin-gifted subscriptions:** Stipend credits normally during gifted periods.

### 10.7 Subscription Refund & Stipend Clawback
When a subscription payment is refunded (via Stripe refund or admin action):
1. The subscription is canceled immediately (not end-of-period).
2. All benefits are revoked immediately.
3. **Stipend clawback:** If the current period's stipend was already credited, the stipend shards are debited from the player's balance using the same `debit_shards()` flow from 3.1. Logged as `source_type = 'subscription_refund'`.
4. The player's `shard_balance` can go negative from this clawback (same as purchase refunds in 3.1).
5. Continuous streak resets to 0. Cumulative months for the refunded period are decremented (since the month was not actually paid for).
6. Cumulative milestone titles are NOT revoked even if the cumulative count drops below the milestone threshold (they were earned at the time and are permanent).

**Refund scenarios:**
- **Monthly subscriber refunded:** Debit that month's 150 stipend shards (if credited). Cancel immediately.
- **Annual subscriber refunded partially:** Proportional approach — if refunding 6 of 12 months, debit stipend for any credited months within the refunded portion. Use the same proportional formula concept as 3.1 but applied to stipend periods.
- **Annual subscriber full refund:** Debit ALL stipend shards credited during the subscription period. Cancel immediately.

## 11. Security Requirements

### 11.1 Webhook Integrity
- All subscription webhook events use the same signature verification as 3.1.
- Subscription state changes are ONLY applied via webhooks — never from frontend calls directly.
- The frontend cannot activate, extend, or modify subscription status — it can only initiate Stripe Checkout redirects and request cancellations (which go through Stripe).

### 11.2 Boost Validation
- All boost multipliers are applied server-side. The client displays boost indicators but never sends boost values to the server.
- The `get_subscriber_multipliers()` function reads from the database on each request — no client-side caching of boost values.

### 11.3 Rate Limiting
- `POST /api/subscriptions/create`: 3 requests per player per minute.
- `POST /api/subscriptions/cancel`: 3 requests per player per minute.
- `POST /api/subscriptions/switch`: 3 requests per player per minute.
