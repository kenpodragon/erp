# REC 2.3.1: Idle Training — UX & Feature Requirements

> **Scope:** Full feature specification for the 2.3 Idle Training screen.
> **DB Schema:** See `2.3.1.0_IDLE_TRAINING_SCHEMA.md`.
> **Inspired By:** Melvor Idle (one-at-a-time skill training, sub-action system, offline delta calc).
> **Diverges From Inspiration:** Lore-locked narrative gates, Essence soft gate, active mode replaces idle instead of layering, terminal aesthetic.

---

## 1. Design Goals

1. **Passive power floor.** Idle Training levels determine the starting stats for every Story Mode session. A well-trained character is meaningfully stronger before buying a single upgrade.
2. **One decision at a time.** Players pick a single skill, then a single action within it. No multitasking. The tension is in choosing *what* to train.
3. **Narrative immersion.** Every action is a named activity from the lore. Training doesn't happen in a vacuum — it happens in S Corp's facilities, in the Dreamscape, aboard the Genesis ship.
4. **24-hour passive loop.** The system should reward logging in once a day and reward returning more often (active mode). It must never feel like a chore to maintain.
5. **Sci-fi terminal aesthetic.** The UI reads like a process monitor, not a fantasy skill tree. This matches the "Etheris is a construct" theme.

---

## 2. Navigation & Location

- **Tab:** The existing **Skills** navigation tab in the side nav.
- **No new nav items needed.** Idle Training lives at `/skills` (or whatever route the Skills tab resolves to).
- The Skills tab is always accessible, regardless of whether a Story Mode session is active.
- **Background persistence:** Training continues while the player is in Story Mode, Home Base, or any other screen. It does NOT require the Skills tab to be open.

---

## 3. Visual Identity: Terminal Aesthetic

The Skills screen uses a **terminal / process-monitor aesthetic**:

- **Background:** Near-black (`#0a0a0f`), consistent with the app's cosmic horror palette.
- **Text:** Phosphor green (`#00ff88`) for active data, dim grey (`#4a5a4a`) for locked/inactive content.
- **Font:** Monospace throughout. All numbers right-aligned. All labels uppercase.
- **Progress Bars:** ASCII block-fill style using Unicode block characters:
  - Filled: `█`
  - Partial: `▓` or `▒`
  - Empty: `░`
- **Headers:** Bracket-style: `┌─ SECTION TITLE ──────────────────────────┐`
- **Active indicator:** `■` (filled square) for the currently-training skill; `○` for idle; `▒` for locked.
- **No decorative images** on the main skills screen. Flavor images are only in the Active Mode mini-game.

## 4. Panel 1: All Skills Overview

The bottom panel always shows a compact summary of all 4 skills, visible regardless of which skill tab is selected.

Each row displays:
- Skill name (uppercase)
- Current level (right-padded to 2 digits)
- XP progress bar (20 chars wide)
- Current status: `TRAINING: [action name]` | `IDLE` | `LOCKED — [unlock condition hint]`

Clicking a row:
- If unlocked: switches the detail panel to that skill.
- If locked: shows the unlock condition in a tooltip/inline message.

## 6. Panel 3: Action Selection Table

The action table lists all trainable actions for the currently-viewed skill.

### Row States

| Symbol | State | Description |
|:-------|:------|:------------|
| `▶` | Active | Currently training this action |
| (no symbol) | Available | Player meets level requirement, can select |
| `▒` | Locked (level) | Player hasn't reached the required level yet |
| `░` | Locked (level, far) | Requires 10+ more levels — grayed out more severely |

### Columns
| Column | Content |
|:-------|:--------|
| `#` | State symbol (▶ / blank / ▒ / ░) |
| `NAME` | `display_name` from `skill_actions` |
| `LVL REQ` | `level_required` |
| `INTERVAL` | `interval_ms / 1000`s (e.g., `3.0s`) |
| `XP/ACT` | `xp_per_action` |
| `STATUS` | `[TRAINING]`, `[SELECT]`, `[LVL N]` |

### Interaction
- Clicking an available (unlocked) row **selects** it as the current action for that skill.
- If the skill is actively training, changing the action resets the action timer to 0%.
- Clicking a locked row shows a tooltip: `"Requires [SKILL_NAME] level [N]"`.
- The active action is highlighted (bright green row).

### Flavor Text Tooltip
Hovering/tapping a row shows the `lore_description` for that action in a tooltip beneath the table:
```
> [lore_description text]
```
This is the only place flavor text appears in the terminal layout — it doesn't clutter the table.

## 7. Skill Stat Formulas (Permanent Story Mode Bonuses)

These bonuses are calculated at session start and applied as the character's base stats. They use the character's current idle training levels.

### 7.1 Attack → Base Click Damage Floor

```
click_damage_floor = floor(Attack_Level / 2)
```

Added to the base click damage value before any in-session upgrades.

| Level | Bonus |
|:------|:------|
| 1 | +0 |
| 10 | +5 |
| 30 | +15 |
| 60 | +30 |
| 99 | +49 |

### 7.2 Magic → Auto-DPS Global Multiplier

```
auto_dps_multiplier = 1.0 + (Magic_Level × 0.01)
```

Applied as a multiplier to the total auto-DPS calculated from all skills and upgrades.

| Level | Multiplier |
|:------|:-----------|
| 1 | ×1.01 |
| 25 | ×1.25 |
| 50 | ×1.50 |
| 75 | ×1.75 |
| 99 | ×1.99 (~×2.0) |

### 7.3 Lore → Story Gate Reduction + Essence Bonus

**Story Time Gate Reduction** (reduces the WPM narrative progress % required to advance a wave):
```
gate_reduction = min(Lore_Level × 0.003, 0.25)
```
Capped at 25% reduction. (i.e., a 5-minute gate becomes ~3m 45s at cap.)

**Essence Gain Multiplier** (applied to all Essence earned from Story Mode):
```
essence_multiplier = 1.0 + (Lore_Level × 0.008)
```

| Level | Gate Reduction | Essence Multiplier |
|:------|:--------------|:-------------------|
| 1 | 0.3% | ×1.008 |
| 25 | 7.5% | ×1.20 |
| 50 | 15.0% | ×1.40 |
| 84 | 25.0% (cap) | ×1.67 |
| 99 | 25.0% (cap) | ×1.79 |

### 7.4 Precision → Crit Chance + Crit Multiplier

**Crit Chance Additive** (added to the base crit chance):
```
crit_chance_bonus = Precision_Level × 0.001  (as 0.0–1.0 fraction)
```

**Crit Multiplier Additive** (added to the base crit multiplier of 2.0×):
```
crit_multiplier_bonus = Precision_Level × 0.01
total_crit_multiplier = 2.0 + crit_multiplier_bonus
```

| Level | Crit Chance Bonus | Total Crit Multiplier |
|:------|:-----------------|:---------------------|
| 1 | +0.1% | ×2.01 |
| 25 | +2.5% | ×2.25 |
| 50 | +5.0% | ×2.50 |
| 75 | +7.5% | ×2.75 |
| 99 | +9.9% | ×2.99 |

## 9. Offline Progression

### How It Works

1. When a player leaves the app, the server records:
   - Which skill is actively training
   - Which action within that skill
   - The `last_offline_calc_at` timestamp
   - The current `action_started_at` (partial action progress is **discarded** — only completed actions count)

2. On next API call after the player returns, the server runs the offline calculation:
   ```
   elapsed_seconds = current_time - last_offline_calc_at
   capped_seconds = min(elapsed_seconds, idle_offline_cap_hours × 3600)
   actions_completed = floor(capped_seconds / action.interval_ms × 1000)
   xp_earned = actions_completed × action.xp_per_action × essence_xp_rate_at_time
   ```
3. XP is applied to `character_skill_levels.current_xp`. If XP overflows into the next level (or multiple levels), levels are applied iteratively.

4. Essence drain is also calculated for offline time:
   ```
   essence_drained = capped_seconds / 60 × idle_essence_drain_per_minute
   ```

5. On next app load, a **"TRAINING REPORT"** modal appears (terminal-style):
   ```
   ┌─ TRAINING REPORT ────────────────────────────────────────────────┐
   │  OFFLINE DURATION: 8h 24m (of 24h cap)                          │
   │                                                                  │
   │  ATTACK :: Shadowboxing in the Garage                            │
   │  Actions completed: 10,080                                       │
   │  XP earned: 100,800                                              │
   │  Levels gained: +2 (LVL 23 → LVL 25)                            │
   │                                                                  │
   │  Essence consumed: 504                                           │
   │  Remaining Essence: 3,241                                        │
   │                                                                  │
   │  [CONTINUE]                                                      │
   └──────────────────────────────────────────────────────────────────┘
   ```

### Offline Cap
- **24 hours.** Configurable via `game_configs.idle_offline_cap_hours`.
- Progress beyond 24 hours is silently discarded. No warning is shown retroactively.

### Edge Cases
- If Essence runs out during offline time: the backend calculates how many minutes of full-rate training occurred before Essence hit 0%, then applies the degraded rate for remaining time.
- If the player hasn't selected an action: no offline XP accrues.
- If the skill has no active training set: no offline XP accrues.

## 10. Essence Soft Gate

Training consumes **Elysium Essence** (the permanent currency from `player_essence`) at a rate defined by `game_configs.idle_essence_drain_per_minute`.

The Essence level (as a % of character's total Essence capacity) determines the XP rate modifier:

| Essence % | XP Rate Modifier |
|:----------|:-----------------|
| 75–100% | 100% (full rate) |
| 40–74% | 75% |
| 15–39% | 50% |
| 1–14% | 25% |
| 0% | 10% (minimum — never fully stops) |

- The drain rate itself is **constant** regardless of XP rate modifier. Essence drains the same whether you're at full rate or minimum rate.
- The Essence bar on the training panel reflects **current Essence %** in real-time.
- When Essence drops below 40%, a **warning pulse** appears on the Essence bar: `[ ESSENCE DEGRADING ]` blinks.
- When Essence drops to 0%, a persistent warning: `[ ESSENCE EMPTY — REPLENISH VIA STORY MODE ]`.

**Replenishment:** Players earn Essence by completing Story Mode scenes and earning from `player_meta_progression`. This creates the intended loop: train passively → deplete Essence → play Story Mode to replenish.

## 11. Active Mode (Clicker Mini-Game)

### Purpose
Active Mode lets a player temporarily engage directly with a skill's training, earning XP faster than idle but pausing the idle accumulation.

### Entry
- Player clicks **[ENTER ACTIVE MODE]** from the skill detail panel.
- A confirmation modal appears (terminal style):
  ```
  ┌─ ENTER ACTIVE MODE ──────────────────────────────────────────────┐
  │  SKILL: ATTACK                                                    │
  │  ACTION: Shadowboxing in the Garage                              │
  │                                                                  │
  │  WARNING: Idle accumulation PAUSES while Active Mode is running. │
  │  All XP earned comes from enemy kills.                           │
  │  Essence is NOT consumed during Active Mode.                     │
  │                                                                  │
  │  [ENTER]  [CANCEL]                                               │
  └──────────────────────────────────────────────────────────────────┘
  ```
- On confirmation, idle training pauses (`is_active_mode = TRUE` recorded on backend).

### Combat Engine

Active Mode **reuses the Story Mode combat engine** (CombatStage.tsx / PixiJS):
- **No narrative block.** No WPM gate. No audio player. Only combat.
- **No Essence earned.** This is XP-only mode.
- **Endless waves** with boss every `idle_active_mode_boss_interval` waves (configurable, default: 10).
- Enemy HP and gold scale with wave number using the same zone-scaling formula as Story Mode.

### Skill-Specific Flavor

Each skill has a distinct identity in Active Mode:

| Skill | Header Text | Enemy Pool Source | Location/Background |
|:------|:-----------|:-----------------|:-------------------|
| Attack | `TRAINING: COMBAT PROTOCOL` | Combat-type entities from unlocked story progress (e.g., Red Hat soldiers, Shadow Wraiths, Kuiper Belt hostiles) | S Corp Combat Facility / MOM Antarctic Base |
| Magic | `TRAINING: DREAMWALKING` | Dreamscape entities (energy constructs, astral manifestations, anything from the Threshold scenes) | The Dreamscape / The Threshold |
| Lore | `TRAINING: AKASHIC RESEARCH` | Knowledge-guarding entities (Pointers, Audit constructs, abstract cosmic forms) | Akashic Realm / S Corp Research Archives |
| Precision | `TRAINING: CALIBRATION` | Technical adversaries (Red Hat operatives, prison constructs, infiltrators) | Infinitron Lab / ERB Portal Room / Genesis Ship deck |

**Enemy Pool Fallback:** If no skill-relevant entities exist for the player's current story progress, use zone-scaled generic entities (same as Story Mode's fallback logic). Log a `dev_content_audit` entry.

### XP Earning in Active Mode

Each enemy kill grants XP toward the **currently selected idle action** for this skill:
```
xp_per_kill = xp_per_action × (1 + (wave_number × 0.01))
xp_per_boss_kill = xp_per_action × 5
```

Where `xp_per_action` is the XP value of the currently selected action (e.g., "Shadowboxing in the Garage" = 10 XP/action).

**Action Looping:** XP from kills accumulates against the action's XP-per-action value. When enough XP is earned to complete the action, it is marked complete and begins again (loops). If multiple loops complete in a single kill batch, all are registered. The UI shows: `ACTION COMPLETE × 3 — LOOPING`.

This means active mode feels rewarding: clearing a wave quickly might complete the current action 5 times over, earning the player several minutes worth of idle XP in seconds.

### Exit Active Mode

- Player clicks **[EXIT ACTIVE MODE]** (always-visible button during active mode).
- All accumulated XP is applied to `character_skill_levels.current_xp`.
- Idle training resumes from scratch (action timer resets to 0%).
- The Training Report modal does NOT appear on exit (not an offline calc).

## 12. Skill Unlock Gates

Skills unlock at specific narrative story beats. These gates are configured via `skills.unlock_scene_id` (FK to `scenes` table) and `skills.unlock_display_text`.

| Skill | Unlock Condition | Display Text (when locked) |
|:------|:----------------|:--------------------------|
| **Attack** | Available immediately (no gate) | N/A |
| **Magic** | After completing the first dreamwalking scene (Ch.6 narrative equivalent) | `UNLOCK: Complete the first Dreamwalking story scene` |
| **Lore** | After completing the Eternal Engine discovery scene (Ch.7 narrative equivalent) | `UNLOCK: Discover the Eternal Engine in the Dreamscape` |
| **Precision** | After completing the Infinitron / S Corp founding scene (Ch.19-20 narrative equivalent) | `UNLOCK: Witness the Infinitron Breakthrough` |

**UX for Locked Skills:**
- The skill tab shows `[▒ LOCKED]` in the skills overview.
- Clicking a locked skill in the overview panel shows:
  ```
  ┌─ PRECISION :: CALIBRATION ────────────────────────────────────────────┐
  │  ▒ LOCKED                                                              │
  │                                                                        │
  │  UNLOCK: Witness the Infinitron Breakthrough                          │
  │                                                                        │
  │  Precision training becomes available after the Infinitron            │
  │  breakthrough story event. Continue through Story Mode to unlock.     │
  └────────────────────────────────────────────────────────────────────────┘
  ```
- Locked actions within an unlocked skill show: `[LVL N]` with the required level greyed out.

**Unlock Notification:**
When a player completes the relevant story beat, a banner appears on the Skills tab:
```
[ NEW SKILL UNLOCKED: PRECISION :: CALIBRATION ]
```
