# REC 5.0: Administrative Systems (Game Operations & Content Management)

This document defines the high-level requirements for the Administrative Systems phase — the comprehensive admin tooling needed to operate, tune, and populate the game without code deployments.

**Parent:** [0_REQUIREMENTS.md](0_REQUIREMENTS.md) §5

---

## 1. Overview & Scope

### 1.1 Purpose
Phase 5.0 builds out the remaining administrative tools needed to transition ERP from a developer-operated prototype into an operationally independent product. This phase is also designed with **platform reusability** in mind — the admin tooling should be generalizable so that any book series can be loaded into the system to create its own RPG experience.

After this phase, a non-developer game admin should be able to:
- Manage players and their characters (support, testing, moderation)
- Edit and manage all game content (chapters, scenes, entities, skills, items)
- Tune gameplay parameters (wave scaling, stat weights, drop rates) without redeploying
- Audit and remediate missing/generic content flagged by the system
- Manage entity classification, types, and visual presentation
- Track and organize all visual assets via a centralized registry

### 1.3 Entity Classification Foundation (Completed in 5.3)
Entity classification has been normalized from free-form strings into proper lookup tables:
- **`entity_types`** table — 9 seeded types (enemy, creature, character, manifestation, object, group, environment, event, other). `entities.entity_type_id` FK replaces old VARCHAR.
- **`entity_families`** table — Admin-created families with base stat templates, lore references. `entities.entity_family_id` FK replaces old VARCHAR.
- **`visual_behaviors`** table — 5 seeded behaviors (grounded_melee, grounded_ranged, airborne, magic_caster, hybrid). Mapped from attack types via `visual_behavior_id` FK.
- **`attack_types`** table — Extended with `visual_behavior_id` FK and `stat_multipliers` JSONB. Migrated from ContentEditor to WorldBuilder Classification tab.
- **WorldBuilder "Classification" tab** — 6 sub-tabs: Entity Types, Families, Attack Types, Visual Behaviors, Bulk Assignment, Audit.

### 1.4 Scope Boundaries
- **In Scope:** Player/character deep editing, game content editing (books/chapters/scenes/story beats/entities), entity type/class management, banner & scaling editor, dev content audit dashboard, content management tooling, asset registry, lore description updates, UI polish (hide debug elements).
- **Out of Scope:** C_ content generators (deferred to final pass — see §5 below for gap analysis), Finance Dashboard (complete in 3.6), Chat Manager (complete in 2.6.4), NG+ system (deferred to §99).
- **Dependencies:** All prior phases (1.0–3.6) complete. Database migrations 001–058 applied. Migrations 059 (5.4) and 060 (5.6) to be applied during this phase.

### 5.2 — Game Content Editor (Narrative & World Data) — **COMPLETE**
A comprehensive editor for managing all narrative and world-building data. Initial content has been seeded via SQL migrations and the `book_parser` tool — this editor is for **managing and editing** that content going forward. Future content population at scale is handled by C_ generators.
*Detailed docs: [5.2_GAME_CONTENT_EDITOR.md](5.2_GAME_CONTENT_EDITOR.md) | [Design](5.2_GAME_CONTENT_EDITOR_DESIGN.md) | [Schema](5.2_GAME_CONTENT_EDITOR_SCHEMA.md)*

**Platform vision:** This editor must be designed so that a new book series can be loaded and its content managed entirely through the admin UI, supporting the long-term goal of a reusable book-RPG platform.

- [x] **Book Editor:** CRUD for books (title, author, description, transition_lore_text, sort order)
- [x] **Chapter Editor:** CRUD for chapters within books (title, summary, transition_lore_text, base_atmosphere, sort order)
- [x] **Scene Editor:** CRUD for scenes within chapters (title, scene_type, sort order, duration, wave config)
- [x] **Narrative Text Editor:** Rich text / markdown editor for scene narrative content. This is the actual story text displayed to players — must support editing the full narrative passages per scene.
- [x] **Story Beat Editor:** Create and edit story beats / narrative segments within scenes
- [x] **Entity Editor:** Full CRUD for entities (name, description, stat block, sprite_key (should link to sprite editor), scene associations, entity_type, entity_family, gold reward, HP)
- [x] **Background Editor:** Full CRUD for backgrounds (name, description, background_key (should link to background editor), scene associations)
- [x] **Entity-Scene Mapper:** Bulk assignment UI — assign entities to scenes, set spawn rates, manage wave compositions
- [x] **Location Editor:** CRUD for locations (name, description, atmosphere associations)

### 5.4 — Banner & Scaling Editor (Visual & Difficulty Tuning) — **COMPLETE**
Admin controls for visual weight configuration, wave difficulty scaling, intensity curves, and difficulty presets. Lives as the fourth tab in WorldBuilder ("Scaling & Difficulty").
*Detailed docs: [5.4_BANNER_SCALING_EDITOR.md](5.4_BANNER_SCALING_EDITOR.md) | [Design](5.4_BANNER_SCALING_EDITOR_DESIGN.md) | [Schema](5.4_BANNER_SCALING_EDITOR_SCHEMA.md)*

- [x] **Visual Weight Editor:** `stat_weights` JSONB on `visual_behaviors` table — configure how STR/AGI/INT affect sprite size, speed, and VFX intensity per behavior. Clamps prevent extreme values.
- [x] **Wave Presets:** Named JSONB wave configuration templates (`wave_presets` table) with book/chapter assignment via `wave_preset_assignments`. Inheritance chain: scene → chapter → book → global default. Bulk "Apply to Scenes" action.
- [x] **Difficulty Curves:** Named multi-dimension per-chapter multiplier profiles (`difficulty_curves` table) — HP, gold, wave_density, spawn_speed per chapter position. Books reference by FK. Chapters beyond defined range use last entry.
- [x] **Chapter Scaling Preview:** Client-side comparison mode — two configurations side-by-side with color-coded diff cells (green=easier, red=harder). No dedicated backend endpoint.
- [x] **Difficulty Presets:** Named bundles (`difficulty_presets` table) combining game_configs snapshot (combat + upgrades categories) + difficulty_curve FK + wave_preset FK. Atomic apply endpoint. No auto-revert — apply a different preset to revert.
- [x] **Global Wave Defaults:** 4 new `game_configs` keys (category: `waves`) as ultimate fallback.

## 5. C_ Generator Gap Analysis

The following generators are needed but **out of scope for Phase 5** (deferred to C_ final pass). Listed here for cross-reference so 5.0 tooling is designed to support their output.

| Generator | Status | What It Produces | 5.0 Dependency |
|-----------|--------|-----------------|----------------|
| **Background Parallax Generator** | Not built | `bg_{chapter}_{layer}.png` images | Asset Registry (5.7) |
| **DB Populator / Lore-to-Content AI** | Partial (`book_parser` exists) | Lore-accurate stat blocks, descriptions, entity enrichment | Entity Editor (5.2), Stat Templates (5.3) |
| **Sprite Generator** | Not built | Entity sprites, item icons, class sprites, avatars, spell icons | Asset Registry (5.7) |
| **PNG Text Generator** | Not built | Copy-protected narrative text images | Scene Editor (5.2) |
| **Boss Lore Text Generator** | Not built | `transition_lore_text` for chapters/books | Chapter Editor (5.2) |
| **Cosmetic Asset Generators** | Not built | Skins, badges, flair, avatars for Emporium (3.3) | Asset Registry (5.7) |
| **Achievement Badge Icons** | Not built | Visual badge icons for leaderboard rank cards | Asset Registry (5.7) |
| **Banner Animation System** | Not built | PixiJS rendering integration consuming `visual_behaviors.animation_config`, per-behavior animation state machines, animation sprite sheets | Visual Behaviors (5.3), Asset Registry (5.7) |

| **Content Audit Scanner** | Not built | Proactive `dev_content_audit` population (missing stats, sprites, SFX, atmospheres, lore text) | Dev Audit Dashboard (5.6) |

**Key takeaway:** Asset Registry (5.7) is the critical bridge between Phase 5 admin tooling and Phase C generators. All generators should output a manifest that can be bulk-imported via 5.7. The Content Audit Scanner (new) populates `dev_content_audit` proactively for the 5.6 dashboard.

## 6. Design Decisions (Resolved)

| # | Decision | Resolution |
|---|----------|------------|
| 1 | Character editor depth | Full editing: stats, level, XP, class reassignment with cascading skill updates |
| 2 | Item creation in admin | Piggyback on existing `item_generator.py` / `artifact_service.py` — admin selects descriptors (rarity, prefix, suffix, slot, type) to craft items; also edit descriptors on existing items |
| 3 | Player impersonation | Not implementing — direct stat/inventory editing is sufficient |
| 4 | Content creation workflow | Initial seeding done via migrations + `book_parser`. Admin editor for managing/editing existing content. Future bulk creation via C_ generators. |
| 5 | Narrative text editing | Yes — full rich text editor for story content per scene. Required for platform reusability (any book → RPG). |
| 6 | In-game preview from admin | No — game just renders text on frontend, preview not needed |
| 7 | Entity types architecture | Already built: 13 attack types (many-to-many), entity_family, entity_type. 5.3 extends with management UI + visual behavior tags for banner. |
| 8 | Entity type combat impact | Visual only in clicker combat (no gameplay effect). **Battle banner must reflect types:** flying = airborne, ranged = projectile, melee = close-range, magic = spell VFX. |
| 9 | Intensity curve editor style | Table-based (chapter → multiplier), not visual graph editor. Multi-dimension: HP, gold, wave_density, spawn_speed per chapter. |
| 10 | Difficulty preset scope | Global only. NG+ is deferred to §99. Presets bundle game_configs snapshot + curve FK + wave preset FK. |
| 11 | GameConfigs relationship | **Resolved in 5.5:** Selective specialization — Drop Rates, Skill Balance, and Economy get specialized tabs. Everything else stays in reorganized category tabs with type-inferred inputs. HP/Gold Scaler merged into 5.4. Narrative Timing stays as single key in generic editor. |
| 12 | Audit dashboard behavior | Reactive — displays records logged at runtime by `dev_content_audit` when fallbacks occur. Not a proactive scanner. Proactive scanning deferred to C_ generators. |
| 13 | Asset storage approach | DB-based lightweight definitions (following Web Audio `audio_configs` pattern). Current filesystem assets to be cataloged and registered. |
| 14 | Asset Registry timing | Built first (5.7) — required before C_ generators and to catalog existing assets. |
| 15 | 5.4 visual weight storage | `stat_weights` JSONB on `visual_behaviors` table (per-behavior). Flat weights + global clamps. |
| 16 | 5.4 wave preset storage | JSONB blob in `wave_presets` table, assignments via `wave_preset_assignments`. Inheritance: scene → chapter → book → global default. |
| 17 | 5.6 severity flagging | Skipped — `audit_type` is sufficient for prioritization. |
| 18 | 5.6 progress dashboard scope | Counts by type + status from `dev_content_audit` only. Coverage percentages deferred to C_ scanner. |
