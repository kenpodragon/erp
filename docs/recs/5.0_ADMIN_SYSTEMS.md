# REC 5.0: Administrative Systems (Game Operations & Content Management)

This document defines the high-level requirements for the Administrative Systems phase — the comprehensive admin tooling needed to operate, tune, and populate the game without code deployments.

**Parent:** [0_REQUIREMENTS.md](0_REQUIREMENTS.md) §5

---

## 1. Overview & Scope

### 1.1 Purpose
Phase 5.0 builds out the remaining administrative tools needed to transition ERP from a developer-operated prototype into an operationally independent product. This phase is also designed with **platform reusability** in mind — the admin tooling should be generalizable so that any book series can be loaded into the system to create its own RPG experience.

After this phase, a non-developer game admin should be able to:
- Manage players and their characters (support, testing, moderation)
- Edit and manage all game content (chapters, scenes, entities, skills, items)
- Tune gameplay parameters (wave scaling, stat weights, drop rates) without redeploying
- Audit and remediate missing/generic content flagged by the system
- Manage entity classification, types, and visual presentation
- Track and organize all visual assets via a centralized registry

### 1.3 Existing Entity Classification Foundation
The following entity classification systems are already in the database:
- **`entity_type`** field on `entities` table — simple string classification (e.g., "boss", "enemy")
- **`entity_family`** field on `entities` table — groups related entities (e.g., "Wraith", "Golem", "Shade") — added in migration 042
- **`attack_types`** table — 13 combat archetypes already seeded (melee, ranged, akashic, aerial, psychic, nanite, phase, void, resonance, construct, thermal, gravitic, corruption) — migration 037
- **`entity_attack_types`** junction table — many-to-many linking entities to attack types (e.g., Rust Guardian = melee + construct + thermal) — migration 038
- **ContentEditor** already has an "Attack Types" tab with CRUD

### 1.4 Scope Boundaries
- **In Scope:** Player/character deep editing, game content editing (books/chapters/scenes/story beats/entities), entity type/class management, banner & scaling editor, dev content audit dashboard, content management tooling, asset registry, lore description updates, UI polish (hide debug elements).
- **Out of Scope:** C_ content generators (deferred to final pass — see §5 below for gap analysis), Finance Dashboard (complete in 3.6), Chat Manager (complete in 2.6.4), NG+ system (deferred to §99).
- **Dependencies:** All prior phases (1.0–3.6) complete. Database migrations 001–054 applied.

## 2. Section Breakdown

### 5.1 — Player & Character Management (Support Tooling)
Extend the existing PlayerDetail page into a full support/testing workbench.

- [ ] **Character Deep Editor:** Direct manipulation of character stats (STR/AGI/INT), level, XP. Full class reassignment with cascading skill updates (swapping class resets class-exclusive skills to match the new class).
- [ ] **Item Crafting Tool:** Piggybacks on the existing reward/item generation system (`item_generator.py`, `artifact_service.py`). Admin selects descriptors (rarity, prefix, suffix, gear slot, type base) to craft an item and grant it to a player's inventory. Also allows editing descriptors on existing items to recalculate stats programmatically.
- [ ] **Currency Editor:** Grant/debit Elysium Essence and Elysium Shards with audit trail and reason field.
- [ ] **Progression Editor:** Manually set chapter/scene progression, unlock/lock story content, reset boss completions.
- [ ] **Skill Editor:** Override character skill levels, unlock/lock skills.
- [ ] **Subscription/Premium Override:** Extend/revoke subscription, toggle boosts (extends existing 3.6 tools within player context).
- [ ] **Activity Timeline:** Unified view of player's recent actions (logins, purchases, story progress, chat, anti-cheat flags).

### 5.2 — Game Content Editor (Narrative & World Data)
A comprehensive editor for managing all narrative and world-building data. Initial content has been seeded via SQL migrations and the `book_parser` tool — this editor is for **managing and editing** that content going forward. Future content population at scale is handled by C_ generators.

**Platform vision:** This editor must be designed so that a new book series can be loaded and its content managed entirely through the admin UI, supporting the long-term goal of a reusable book-RPG platform.

- [ ] **Book Editor:** CRUD for books (title, author, description, transition_lore_text, sort order)
- [ ] **Chapter Editor:** CRUD for chapters within books (title, summary, transition_lore_text, base_atmosphere, sort order)
- [ ] **Scene Editor:** CRUD for scenes within chapters (title, scene_type, sort order, duration, wave config)
- [ ] **Narrative Text Editor:** Rich text / markdown editor for scene narrative content. This is the actual story text displayed to players — must support editing the full narrative passages per scene.
- [ ] **Story Beat Editor:** Create and edit story beats / narrative segments within scenes
- [ ] **Entity Editor:** Full CRUD for entities (name, description, stat block, sprite_key, scene associations, entity_type, entity_family, gold reward, HP)
- [ ] **Entity-Scene Mapper:** Bulk assignment UI — assign entities to scenes, set spawn rates, manage wave compositions
- [ ] **Location Editor:** CRUD for locations (name, description, atmosphere associations)

### 5.3 — Entity Type & Classification Management
Manage the existing entity classification systems (attack types, entity families, entity types) and extend with visual classification for banner rendering.

**Already built:** 13 attack types seeded, `entity_attack_types` junction table, `entity_family` field, ContentEditor "Attack Types" tab. This section extends that into a full management workflow.

- [ ] **Attack Type Manager:** Extend existing ContentEditor tab — add bulk assignment of attack types to entities (search, filter, multi-select), show current assignment counts per type
- [ ] **Entity Family Manager:** UI for managing `entity_family` values — view all families, reassign entities between families, create new families
- [ ] **Visual Classification Tags:** Add visual behavior tags to entities/attack types that define how they render:
    - Flying entities → airborne animation in battle banner
    - Ranged entities → projectile attack animation
    - Melee entities → close-range swing animation
    - Magic entities → spell cast VFX
- [ ] **Battle Banner Behavior Mapping:** Configure how each visual tag affects rendering in the side-scrolling battle banner (animation set, positioning, movement pattern)
- [ ] **Stat Block Templates:** Pre-defined stat templates per attack type combo for rapid entity creation (e.g., "standard melee" template, "aerial magic" template)

### 5.4 — Banner & Scaling Editor (Visual & Difficulty Tuning)
Admin controls for the PixiJS battle banner and wave difficulty scaling.

- [ ] **Visual Weight Editor:** Configure how each stat (STR/AGI/INT) affects sprite size, movement speed, and VFX intensity
- [ ] **Global Wave Settings:** Set `max_enemies_per_wave`, default spawn intervals, spawn pattern presets
- [ ] **Intensity Curve Editor:** Table-based editor defining how wave density increases across chapters and resets per book (chapter number → multiplier mapping)
- [ ] **Chapter Scaling Preview:** Show projected HP/Gold/Wave curves for a given chapter range
- [ ] **Difficulty Presets:** Save/load named global difficulty configurations for A/B testing

### 5.5 — Content Management & Live Tuning
Extend GameConfigs into purpose-built tuning interfaces. Investigation needed to determine which tuning controls should live as specialized UI vs. remaining in the generic GameConfigs key-value editor.

- [ ] **Drop Rate Manager:** Unified UI for adjusting artifact, item, and entity drop rates (per scene, chapter, or global)
- [ ] **Enemy HP/Gold Scaler:** Adjust base HP and gold reward scaling formulas with live preview of impact
- [ ] **Narrative Timing Editor:** Adjust WPM rates, scene durations, and narrative trigger timings
- [ ] **Skill Balance Editor:** Tune skill damage multipliers, cooldowns, DPS scaling coefficients, and cost curves
- [ ] **Economy Tuning:** Adjust Essence earn rates, idle training speeds, and related scaling factors
- [ ] **Config Categories:** Organize game_configs into logical groups with search/filter (extends existing GameConfigs page)

### 5.6 — Dev Content Audit Dashboard
A reactive dashboard for identifying and remediating missing or placeholder content. Records are logged to `dev_content_audit` at runtime when the system falls back to generic/placeholder data — this dashboard surfaces those records so they can be fixed.

- [ ] **Audit Table Viewer:** Paginated, filterable view of all `dev_content_audit` records
- [ ] **Category Filters:** Filter by audit type:
    - Missing `base_atmosphere` or music tracks
    - Entities using generic/placeholder sprites
    - Entities missing unique death sounds or SFX keys
    - Skills with missing SFX keys
    - Generic stat blocks not extracted from lore
    - Scenes with no entity assignments
    - Chapters with no transition lore text
- [ ] **Severity Flagging:** Flag items as critical / warning / info priority
- [ ] **Inline Fix Actions:** Quick-link to the relevant editor (Entity Editor, Atmosphere Editor, etc.) pre-filtered to the flagged record
- [ ] **Bulk Status Updates:** Mark items as "acknowledged", "in-progress", "resolved", or "won't fix"
- [ ] **Progress Dashboard:** Summary cards showing audit coverage (e.g., "73% of entities have lore-specific stat blocks")
- [ ] **Generic vs. Specific Tagging:** Visual indicators distinguishing placeholder content from lore-derived content

### 5.7 — Asset Registry & Sprite Management
Centralized registry mapping visual asset keys to lightweight DB-stored definitions (following the same pattern as the Web Audio music/SFX system — small JSON definitions in DB, not large binary files). This must be built **before** the C_ generators so generated assets have somewhere to be registered.

- [ ] **Asset Registry Table:** DB table mapping `asset_key` → asset data (category, metadata, source URL or inline definition). Schema modeled after `audio_configs` pattern.
- [ ] **Asset CRUD:** Admin page for creating, editing, and deleting asset registry entries
- [ ] **Asset Preview:** Thumbnail preview of registered sprites/icons within the admin UI
- [ ] **Orphan Detection:** Identify `sprite_key` values referenced in entities/items/skills but missing from the registry
- [ ] **Reverse Orphan Detection:** Identify registry entries not referenced by any game object
- [ ] **Bulk Import:** Import multiple asset entries from a CSV/JSON manifest (output format of C_ generators)
- [ ] **Asset Categories:** Organize by type (entity sprites, item icons, skill icons, avatar art, class sprites, spell effects, backgrounds, badges)
- [ ] **Existing Asset Inventory:** Catalog all assets that already exist in the filesystem (`frontend/public/`) and register them

## 5. C_ Generator Gap Analysis

The following generators are needed but **out of scope for Phase 5** (deferred to C_ final pass). Listed here for cross-reference so 5.0 tooling is designed to support their output.

| Generator | Status | What It Produces | 5.0 Dependency |
|-----------|--------|-----------------|----------------|
| **Background Parallax Generator** | Not built | `bg_{chapter}_{layer}.png` images | Asset Registry (5.7) |
| **DB Populator / Lore-to-Content AI** | Partial (`book_parser` exists) | Lore-accurate stat blocks, descriptions, entity enrichment | Entity Editor (5.2), Stat Templates (5.3) |
| **Sprite Generator** | Not built | Entity sprites, item icons, class sprites, avatars, spell icons | Asset Registry (5.7) |
| **PNG Text Generator** | Not built | Copy-protected narrative text images | Scene Editor (5.2) |
| **Boss Lore Text Generator** | Not built | `transition_lore_text` for chapters/books | Chapter Editor (5.2) |
| **Cosmetic Asset Generators** | Not built | Skins, badges, flair, avatars for Emporium (3.3) | Asset Registry (5.7) |
| **Achievement Badge Icons** | Not built | Visual badge icons for leaderboard rank cards | Asset Registry (5.7) |

**Key takeaway:** Asset Registry (5.7) is the critical bridge between Phase 5 admin tooling and Phase C generators. All generators should output a manifest that can be bulk-imported via 5.7.

## 6. Design Decisions (Resolved)

| # | Decision | Resolution |
|---|----------|------------|
| 1 | Character editor depth | Full editing: stats, level, XP, class reassignment with cascading skill updates |
| 2 | Item creation in admin | Piggyback on existing `item_generator.py` / `artifact_service.py` — admin selects descriptors (rarity, prefix, suffix, slot, type) to craft items; also edit descriptors on existing items |
| 3 | Player impersonation | Not implementing — direct stat/inventory editing is sufficient |
| 4 | Content creation workflow | Initial seeding done via migrations + `book_parser`. Admin editor for managing/editing existing content. Future bulk creation via C_ generators. |
| 5 | Narrative text editing | Yes — full rich text editor for story content per scene. Required for platform reusability (any book → RPG). |
| 6 | In-game preview from admin | No — game just renders text on frontend, preview not needed |
| 7 | Entity types architecture | Already built: 13 attack types (many-to-many), entity_family, entity_type. 5.3 extends with management UI + visual behavior tags for banner. |
| 8 | Entity type combat impact | Visual only in clicker combat (no gameplay effect). **Battle banner must reflect types:** flying = airborne, ranged = projectile, melee = close-range, magic = spell VFX. |
| 9 | Intensity curve editor style | Table-based (chapter → multiplier), not visual graph editor |
| 10 | Difficulty preset scope | Global only. NG+ is deferred to §99. |
| 11 | GameConfigs relationship | Investigation needed per 5.5 — determine which tuning needs specialized UI vs. staying in generic key-value editor |
| 12 | Audit dashboard behavior | Reactive — displays records logged at runtime by `dev_content_audit` when fallbacks occur. Not a proactive scanner. |
| 13 | Asset storage approach | DB-based lightweight definitions (following Web Audio `audio_configs` pattern). Current filesystem assets to be cataloged and registered. |
| 14 | Asset Registry timing | Built first (5.7) — required before C_ generators and to catalog existing assets. |
