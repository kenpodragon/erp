## 1. Artifact System

### 1.1 Artifact Generation Pipeline (Generated Artifacts)

Generated artifacts use a simplified version of the Dream Item generator (2.4.2). The pipeline:

```
1. Roll rarity (weighted by book, same as dream items but shifted toward lower tiers)
2. Select artifact_type from artifact_type_bases (small pool: ~15 types vs 86 for items)
3. Select prefix from artifact_prefixes (small pool: ~20)
4. Select suffix from artifact_suffixes (small pool: ~20)
5. Generate artifact_code: "{PREFIX}_{TYPE}_{SUFFIX}"
6. Check ownership: query player_artifacts for this character + artifact_code
   a. If owned at same or higher rarity → DISCARD (no duplicate/downgrade)
   b. If owned at lower rarity → REPLACE existing row (rarity upgrade, update stats)
   c. If not owned → proceed to insert
7. Compute stats: base_range * rarity_multiplier (multipliers much lower than dream items)
8. Insert into player_artifacts (or update existing row for upgrades)
```

**Stat Budget Comparison (at Cosmic rarity):**
- Dream Item: ~50-80 total stat points across 3-5 stats
- Generated Artifact: ~8-15 total stat points across 1-2 stats
- Curated Artifact (Common): ~20-30 total stat points across 2-4 stats
- Curated Artifact (Cosmic): ~60-100 total stat points across 3-6 stats + unique effect

**Rarity Weights (Generated Artifacts):**
```json
{
  "artifact_rarity_weight_book_1": { "common": 70, "uncommon": 20, "rare": 8, "epic": 1.8, "cosmic": 0.2 },
  "artifact_rarity_weight_book_2": { "common": 60, "uncommon": 25, "rare": 11, "epic": 3.5, "cosmic": 0.5 },
  "artifact_rarity_weight_book_3": { "common": 50, "uncommon": 27, "rare": 15, "epic": 6, "cosmic": 2 }
}
```

**Drop Trigger:** Generated artifacts can drop from:
- Story Mode scene completion (configurable base chance per scene type)
- Boss kills (higher chance)
- Chapter mastery (100% completion of all scenes in a chapter)

**Chapter Mastery Detection:** At `/complete`, the server must check if this scene completion fills the last gap in the chapter. Query all non-boss scenes in the scene's chapter, check `player_scene_records` for each, and if all now have records, trigger the mastery artifact roll. This reuses the same scene-query pattern as the existing boss-gate logic in `story_mode.py`.

**`/complete` Integration Notes (Critical):**
1. **`upsert_scene_record()` must be extended** with `damage_dealt` and `time_seconds` parameters. Currently `/complete` passes `enemies_killed=0` (hardcoded) and no time — these must be computed from the session and sent by the client.
2. **Boss `/complete` path returns early** (line ~1393 in `story_mode.py`) without calling `upsert_scene_record()` or the item/achievement pipeline. The 2.7 artifact drop evaluation and `evaluate_achievements()` must run for **both** normal and boss completions. The boss path must be extended to include scene record upsert, artifact evaluation, and achievement evaluation before returning.
3. **Existing `check_run_achievements()`** (dream item drops from 2.4) coexists with the new `evaluate_achievements()`. Both run at `/complete` — they serve different purposes (item generation vs. persistent achievement tracking).

### 1.2 Curated Artifact System

Curated artifacts are hand-designed with specific lore, stats, and sources.

**Data Structure:**
```python
class CuratedArtifact:
    id: int
    name: str                    # "Cracked Data Core"
    description: str             # Short flavor text
    lore_text: str               # Extended lore for inspection modal
    icon_sprite_key: str         # "artifact_cracked_data_core"
    source_type: str             # "boss" | "chapter" | "rare_spawn"
    source_id: int               # FK to scenes (boss), chapters, or entities (rare spawn)
    source_hint: str             # "Drops from: Chapter 3 Boss - The Pallid Mask"
    base_drop_chance: float      # 0.001 - 0.05 (0.1% to 5%)
    synergy_set_id: int | None   # FK for future synergy sets (NULL in 2.7)
    is_active: bool              # Admin can deactivate
```

**Per-Rarity Tier Data:**
```python
class CuratedArtifactTier:
    curated_artifact_id: int     # FK to curated_artifacts
    rarity: str                  # "common" | "uncommon" | "rare" | "epic" | "cosmic"
    stat_bonuses: dict           # {"strength": 5, "crit_chance_pct": 1.5}
    unique_effect: str | None    # Text description of special effect (display only in 2.7)
    drop_chance_multiplier: float # 1.0 for common, 0.5 uncommon, 0.1 rare, 0.02 epic, 0.005 cosmic
```

**Drop Evaluation Flow (at `/complete`):**
```
1. Get list of curated artifacts sourced from this scene/boss/chapter
2. For each: roll against base_drop_chance * tier.drop_chance_multiplier * book_difficulty_bonus
3. Start from Cosmic tier down to Common (highest possible rarity first)
4. On success: check if player already owns this artifact
   a. If not owned: grant at rolled rarity
   b. If owned at lower rarity: upgrade to new rarity
   c. If owned at same or higher rarity: no grant (skip)
5. Log artifact drop to activity_events
6. Return dropped artifacts in /complete response for PostBattleSummary display
```

**`/complete` Response Additions:**
The existing `/complete` response is extended with artifact and achievement data for PostBattleSummary display:
```json
{
  "...existing fields...",
  "artifact_drops": [
    { "id": 1, "name": "Cracked Data Core", "rarity": "rare", "type": "curated", "is_upgrade": true, "stat_bonuses": {"strength": 8} }
  ],
  "achievements_earned": [
    { "id": 5, "name": "Collector II", "description": "Own 15 artifacts", "reward_shards": 10, "reward_essence": 0, "reward_title": null }
  ],
  "chapter_mastery_achieved": false
}
```

**`/complete` Request Addition:**
The client must send `deaths` (integer, number of respawns during session) and `rare_spawn_kill_count` in the completion payload:
```json
{
  "...existing fields...",
  "deaths": 0,
  "rare_spawn_kill_count": 1
}
```
`deaths` is persisted on `player_story_sessions.deaths` for "Flawless Victory" achievement tracking (deaths == 0).

**Rare Spawn Artifacts (~5-8):**
- Source type = `"rare_spawn"`, source_id = NULL (any rare spawn can drop them)
- Drop evaluation runs when a rare spawn is killed (in addition to normal drops)
- These are among the rarest artifacts in the game

**Rare Spawn Kill Tracking (Implementation Note):**
The current tick payload tracks `entity_encounters` but `/complete` doesn't distinguish rare spawn kills from normal kills. To support curated artifact drops from rare spawns:
- StoryMode.tsx must accumulate a `rare_spawn_kill_count` (or list of rare spawn entity IDs killed) during the session.
- This count is sent in the `/complete` request payload.
- The server uses this to evaluate rare-spawn-sourced curated artifact drops.
- Anti-cheat: server validates rare_spawn_kill_count <= total session waves (cannot kill more rare spawns than waves played).

### 1.3 Artifact Bonus Integration

Artifact bonuses are integrated into `recalculate_character_stats()`:

```python
def recalculate_character_stats(character_id: int, db: Session):
    # Existing flow:
    # 1. Base class affinities
    # 2. Idle skill contributions
    # 3. Equipment bonuses (from player_inventory)

    # NEW: 4. Artifact bonuses
    artifact_bonuses = get_artifact_stat_totals(character_id, db)
    # artifact_bonuses = {"strength": 12, "agility": 5, "crit_chance_pct": 2.0, ...}

    # All artifact bonuses stack additively
    for stat_name, value in artifact_bonuses.items():
        computed_stats[stat_name] += value

    # 5. Write to character_stats
```

`get_artifact_stat_totals()` sums:
- All owned generated artifact `stat_bonuses`
- All owned curated artifact tier `stat_bonuses` (at owned rarity)

This is cached in `character_stats` and only recomputed when artifacts change.

### 2.1 Endpoint Design

```python
@router.get("/home-base/akashic-log")
async def get_akashic_log(token: dict = Depends(get_current_player), db: Session = Depends(get_db)):
    player = token.get("player")
    character = get_active_character(player.id, db)
    intelligence_stat = get_stat_value(character.id, "intelligence", db)

    # Fetch all completed scenes for this player
    completed_scenes = get_completed_scene_ids(player.id, db)

    # Build hierarchical log
    books = get_books_with_chapters_and_beats(completed_scenes, db)

    # For each beat, determine hidden lore eligibility
    for book in books:
        book.completion_pct = calc_completion(book, completed_scenes)
        for chapter in book.chapters:
            chapter.completion_pct = calc_completion(chapter, completed_scenes)
            for scene in chapter.scenes:
                for beat in scene.beats:
                    beat.hidden_lore_unlocked = (
                        beat.lore_intelligence_threshold is not None
                        and intelligence_stat >= beat.lore_intelligence_threshold
                    )

    return AkashicLogResponse(books=books, total_completion_pct=overall_pct)
```

### 2.2 Hidden Lore System

**Schema Addition** (on `story_beats` table):
- `hidden_lore_text TEXT DEFAULT NULL` — Extra lore text revealed by high Intelligence.
- `lore_intelligence_threshold INTEGER DEFAULT NULL` — Minimum Intelligence stat to reveal. NULL = no hidden lore on this beat.

**Population:** Hidden lore text is populated via the content pipeline (admin editor or book processing tools). Not all beats have hidden lore — approximately 15-20% of beats should have it.

**Hidden Lore View Tracking:** When a player views a beat with hidden lore (and their Intelligence qualifies), a record is inserted into `player_discovery_log` with `discovery_type = 'hidden_lore'` and `reference_id = story_beat.id`. This enables "Hidden Knowledge" achievement tracking (count of unique hidden lore entries viewed).

### 2.3 Keyword Search (Client-Side)

The Akashic Log endpoint returns all beat content in one payload. Keyword search is performed client-side:

```tsx
const [searchQuery, setSearchQuery] = useState("");

const filteredBeats = useMemo(() => {
  if (!searchQuery.trim()) return allBeats;
  const q = searchQuery.toLowerCase();
  return allBeats.filter(beat =>
    beat.content.toLowerCase().includes(q) ||
    (beat.hidden_lore_unlocked && beat.hidden_lore_text?.toLowerCase().includes(q))
  );
}, [allBeats, searchQuery]);
```

Results display with keyword highlighting using a simple `<mark>` wrapper.

### 2.4 "New" Badge Tracking

**Approach:** Store `akashic_last_visited_at` as a new `TIMESTAMPTZ` column on `player_settings` (added in migration 046). Any beat with `first_completed_at > akashic_last_visited_at` gets the "New" badge. Updated via `PATCH /api/players/me/settings` when the player opens the Akashic Log terminal.

> **Note:** `player_settings` has no JSONB column — all settings are typed scalar columns. Each terminal's "last visited" timestamp is stored as a dedicated column (e.g., `akashic_last_visited_at`, `gallery_last_visited_at`, `achievements_last_visited_at`).

## 4. Hall of Echoes (Leaderboards)

### 4.1 Leaderboard Categories

| Category | Metric | Source |
|:---|:---|:---|
| Vanguard (Progression) | Furthest scene_id completed | `player_progress` |
| Alchemist (Essence) | Lifetime Essence accumulated | `player_meta_progression.total_essence_earned` |
| Swift (Speedruns) | Best time (seconds) on chapter boss scenes | `player_scene_records.best_time_seconds` |
| Scholar (Lore) | Total unique story beats unlocked | COUNT of `story_beats` belonging to completed scenes (via `player_scene_records`). Beats are not individually tracked — completion is inferred from scene completion. |

### 4.2 Server-Side Caching

Leaderboard computation is expensive (full table scans + joins). Cache strategy:

**Refresh Mechanism: On-Request with TTL**
- When any player requests a leaderboard, check `leaderboard_cache.updated_at` for that category.
- If cache is older than `leaderboard_refresh_interval_min` (default: 5 min), recompute synchronously before returning.
- First request after TTL expiry pays the recompute cost (~200-500ms). Subsequent requests are instant from cache.
- No background scheduler or external cron needed.

```python
# LeaderboardCache table stores pre-computed rankings

class LeaderboardCache:
    id: int
    category: str           # "vanguard" | "alchemist" | "swift" | "scholar"
    rank: int
    player_id: int
    player_alias: str       # Denormalized for fast reads
    character_class: str    # Denormalized
    character_level: int    # Denormalized
    equipped_title: str     # Denormalized (nullable)
    metric_value: float     # The actual score/time/count
    badge_tier: str         # "cosmic" | "gold" | "silver" | "bronze" | null
    updated_at: datetime
```

**Refresh Logic:**
```python
async def refresh_leaderboard(category: str, db: Session):
    # Compute full rankings for this category
    rankings = compute_rankings(category, db)
    total = len(rankings)

    # Assign badge tiers by percentile
    for i, entry in enumerate(rankings):
        pct = (i + 1) / total * 100
        if pct <= 1: entry.badge_tier = "cosmic"
        elif pct <= 5: entry.badge_tier = "gold"
        elif pct <= 15: entry.badge_tier = "silver"
        elif pct <= 30: entry.badge_tier = "bronze"
        else: entry.badge_tier = None

    # Upsert top 100 + player's own rank
    upsert_leaderboard_cache(category, rankings[:100], db)
```

**Endpoint:**
```
GET /api/game/home-base/leaderboard/{category}?page=1&per_page=25
```

Returns paginated leaderboard entries + the requesting player's own rank/badge (even if outside top 100).

### 5.2 Achievement Evaluation Engine

Achievement evaluation runs at **session boundaries** — not mid-combat.

**Trigger Points:**
1. `POST /api/game/story/session/{id}/complete` — combat, economics, narrative achievements
2. Level-up events — idle training achievements
3. Artifact acquisition — collection achievements
4. Discovery events — discovery achievements

```python
async def evaluate_achievements(player_id: int, trigger: str, context: dict, db: Session):
    """
    trigger: "session_complete" | "level_up" | "artifact_acquired" | "discovery"
    context: trigger-specific data (session stats, new level, artifact info, etc.)
    """
    # Get all active achievements not yet earned by this player
    pending = get_pending_achievements(player_id, db)

    # Get player's cumulative stats
    stats = get_player_cumulative_stats(player_id, db)

    newly_earned = []
    for achievement in pending:
        if check_achievement_met(achievement, stats, context):
            grant_achievement(player_id, achievement, db)
            newly_earned.append(achievement)

    return newly_earned
```

**`get_player_cumulative_stats()`** aggregates from multiple sources:
```python
{
    "total_enemies_killed": sum from player_scene_records.total_enemies_killed,
    "total_bosses_killed": count from boss_completions,
    "total_sessions": count from player_story_sessions (completed),
    "total_essence_earned": from player_meta_progression,
    "total_beats_unlocked": count from completed scenes -> beats,
    "total_artifacts_owned": count from player_artifacts,
    "max_wave_reached": max from player_scene_records.best_wave,
    "max_session_damage": max from player_scene_records.best_session_damage,
    "skill_levels": dict from character_skill_levels,
    "hidden_lore_unlocked": count of beats with hidden lore viewed,
    "entity_discoveries": count from player_entity_discovery,
    "ss_rank_count": count from player_entity_discovery where rank='SS',
    "has_flawless_scene": any session in player_story_sessions with deaths == 0 and status == 'completed',
    ...
}
```

### 5.3 Achievement Reward Distribution

When an achievement is earned:
1. Insert `PlayerAchievement` record with `earned_at` timestamp
2. If `reward_shards > 0`: credit `player_meta_progression.shard_balance` and `total_shards_earned`. Insert `shard_transactions` row with `source_type='achievement'`, `source_id=achievement.id`.
3. If `reward_essence > 0`: credit to `player_essence.current_balance`
4. If `reward_title_id`: insert into `player_titles` (available to equip)
5. Return earned achievements in the API response for client-side toast/summary display

```python
    sort_order: int
```

**Equip Title:** `PATCH /api/players/me/title` with `{ "title_id": 5 }`. Stored as `equipped_title_id` on `player_characters`. Displayed on leaderboards and in chat.

### 5.5 Idle Training Milestone Rewards

These are implemented as achievements in the "idle" category:

| Skill | Level 25 | Level 50 | Level 75 | Level 99 |
|:---|:---|:---|:---|:---|
| Each Skill | +50 Essence, Badge | +200 Essence, Badge | +500 Essence, Title | +2000 Essence, Title |

Milestone achievements are seeded per-skill. With 4 idle skills (Attack, Magic, Lore, Precision) x 4 milestones = 16 achievements. These are tracked via `character_skill_levels` on level-up.

## 6. Consolidated Home Base API

### 6.1 Summary Endpoint

**`GET /api/game/home-base/summary`**

A lightweight endpoint that returns badge counts and quick stats for the hub navigation.

```json
{
  "akashic": {
    "new_beats": 3, "total_completion_pct": 42.5
  },
  "artifacts": {
    "new_artifacts": 1, "curated_progress": "7/50", "total_owned": 30
  },
  "leaderboard": {
    "best_rank": 42, "best_category": "vanguard", "badge_tier": "silver"
  },
  "achievements": {
    "new_completed": 2, "total_completed": 47, "total_available": 90
  },
  "hub_badge_count": 6
}
```

`hub_badge_count` = sum of all "new" items across terminals. Displayed as a badge on the Home Base nav icon.

### 6.2 "New" Flag Clearing

Each terminal clears its own "new" flags when visited:
- Akashic Log: update `player_settings.akashic_last_visited_at` to NOW()
- Relic Gallery: update `is_new = false` on all owned player_artifacts + update `player_settings.gallery_last_visited_at`
- Achievements: update `is_new = false` on all player_achievements + update `player_settings.achievements_last_visited_at`

Clearing is done via a `POST /api/game/home-base/{terminal}/mark-visited` endpoint.

### 6.3 Route Consolidation

**Existing endpoints (from 2.1 framework) to be deprecated:**
- `GET /api/game/artifacts` → replaced by `GET /api/game/home-base/artifacts`
- `GET /api/game/journal` → replaced by `GET /api/game/home-base/akashic-log`
- `GET /api/game/leaderboards` → replaced by `GET /api/game/home-base/leaderboard/{category}`

**Strategy:** Keep old endpoints functional but redirect internally to new implementations. Mark as deprecated in code comments. Remove in a future cleanup pass.

**New route file:** `backend/routes/home_base.py` — all new Home Base endpoints live here.
