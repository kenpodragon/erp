# REC 2.3.1.0: Idle Training — Database Schema

> **Scope:** All database changes required to support 2.3.1 Idle Training.
> **UX Spec:** See `2.3.1_IDLE_TRAINING_UX.md`.
> **Migration Number:** This spec covers migrations `021` and `022`.
> **Mandate:** Any schema change here MUST also update `db/data_dictionary.md`.

---

## 1. Overview

The Idle Training system requires:

1. **`skill_actions` table** — Catalog of trainable sub-actions within each skill (the "work tasks").
2. **Modifications to `character_skill_levels`** — Add training state columns (active action, timestamps, active mode flag).
3. **Modifications to `skills`** — Add narrative unlock gate columns.
4. **New `game_configs` seeds** — Idle system tuning values.
5. **Seed data** — All 35 skill actions (8–9 per skill) with lore-accurate content.

### Existing Tables Used (No Structural Changes)
- `skills` — Modified (additive columns only)
- `character_skill_levels` — Modified (additive columns only)
- `player_essence` — Read/write for Essence drain calculation; no schema change
- `scenes` — Referenced by `skills.unlock_scene_id`; no schema change
- `player_characters` — Referenced by `character_skill_levels`; no schema change

## 2. Migration 021: Core Idle Training Schema

**File:** `db/021_idle_training_schema.sql`

### 2.1 New Table: `skill_actions`

The catalog of all trainable sub-actions within each skill. Each row represents one "work task" a player can select to train a skill.

```sql
CREATE TABLE IF NOT EXISTS skill_actions (
    id                  SERIAL PRIMARY KEY,
    skill_id            INTEGER NOT NULL REFERENCES skills(id) ON DELETE CASCADE,
    name                VARCHAR(100) NOT NULL,            -- snake_case key (e.g., 'shadowboxing_garage')
    display_name        VARCHAR(150) NOT NULL,            -- Human-readable (e.g., 'Shadowboxing in the Garage')
    lore_description    TEXT NOT NULL,                    -- Flavor text shown on hover/tap
    level_required      INTEGER NOT NULL DEFAULT 1,       -- Minimum skill level to train this action
    interval_ms         INTEGER NOT NULL DEFAULT 3000,    -- Base time per action in milliseconds
    xp_per_action       INTEGER NOT NULL DEFAULT 10,      -- XP granted per completed action
    sort_order          INTEGER NOT NULL DEFAULT 0,       -- Display order within the skill (ascending)
    created_at          TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at          TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    UNIQUE(skill_id, name)
);
```

**Notes:**
- `interval_ms` is the **base** interval before any future modifiers. The 2.3 implementation has no interval modifiers; this column exists for future extensibility (equipment, pets, etc.).
- `xp_per_action` is a flat integer. Future versions may add a multiplier column.
- `UNIQUE(skill_id, name)` prevents duplicate action keys per skill.
- No `mastery_level` columns: per-action Mastery is explicitly deferred to a future phase.

### 2.2 Modify `character_skill_levels`

Add training state to track idle progression for each character-skill pair.

```sql
ALTER TABLE character_skill_levels
    ADD COLUMN IF NOT EXISTS active_action_id       INTEGER REFERENCES skill_actions(id) ON DELETE SET NULL,
    ADD COLUMN IF NOT EXISTS action_started_at      TIMESTAMP WITH TIME ZONE,
    ADD COLUMN IF NOT EXISTS is_active_training     BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN IF NOT EXISTS is_in_active_mode      BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN IF NOT EXISTS active_mode_started_at TIMESTAMP WITH TIME ZONE,
    ADD COLUMN IF NOT EXISTS last_offline_calc_at   TIMESTAMP WITH TIME ZONE;
```

**Column Descriptions:**

| Column | Type | Description |
|:-------|:-----|:------------|
| `active_action_id` | INTEGER FK | The currently-selected sub-action for this skill. NULL = no action selected. |
| `action_started_at` | TIMESTAMPTZ | When the current action timer started. Used to calculate partial progress (discarded on offline calc). |
| `is_active_training` | BOOLEAN | TRUE for the **one skill currently being idle-trained**. Backend enforces only one row per character can be TRUE. |
| `is_in_active_mode` | BOOLEAN | TRUE when the player is in the Active Mode mini-game for this skill. |
| `active_mode_started_at` | TIMESTAMPTZ | When the current Active Mode session started. NULL if not in active mode. |
| `last_offline_calc_at` | TIMESTAMPTZ | Timestamp of the last offline progression calculation. Set on login; used to compute elapsed offline time. |

**Constraint to enforce one-at-a-time training** (applied as a partial unique index):
```sql
CREATE UNIQUE INDEX IF NOT EXISTS uix_character_one_active_training
    ON character_skill_levels (character_id)
    WHERE is_active_training = TRUE;
```

This prevents two skills from having `is_active_training = TRUE` for the same character at the database level.

### 2.3 Modify `skills`

```sql
ALTER TABLE skills

```

**Column Descriptions:**

| Column | Type | Description |
|:-------|:-----|:------------|
| `unlock_scene_id` | INTEGER FK | The scene that must be completed to unlock this skill. NULL = available from start. |

| `idle_flavor_title` | VARCHAR(100) | The terminal subtitle shown in the skill header (e.g., "COMBAT PROTOCOL", "DREAMWALKING"). |

## 5. Backend Logic Notes

These notes document expected backend computation patterns. They are not schema, but inform the ORM models and service layer.

### 5.1 XP Curve

From the existing spec (`2.3_IDLE_TRAINING.md`) and consistent with Melvor Idle / RuneScape:

```
XP_to_reach_level(N) = floor( (1/4) * sum_{i=1}^{N-1} floor(i + 300 * 2^(i/7)) )
```

This is the **cumulative** XP required to reach level N from level 1. To find XP needed for the *next* level from the current level, compute:
```
xp_needed = XP_to_reach_level(current_level + 1) - XP_to_reach_level(current_level)
```

Key reference values:
| Level | Cumulative XP Required |
|:------|:----------------------|
| 1 | 0 |
| 10 | 1,154 |
| 20 | 4,470 |
| 30 | 13,363 |
| 50 | 101,333 |
| 70 | 737,627 |
| 80 | 2,034,343 |
| 99 | 13,034,431 |

### 5.2 Offline Progression Calculation

```python
def calculate_offline_xp(character_skill_level, now):
    row = character_skill_level  # SQLModel row
    if not row.is_active_training or not row.active_action_id:
        return 0, 0  # xp_earned, essence_drained

    elapsed = (now - row.last_offline_calc_at).total_seconds()
    cap = get_config('idle_offline_cap_hours') * 3600
    capped = min(elapsed, cap)

    action = row.active_action  # joined skill_action
    actions_completed = int(capped / (action.interval_ms / 1000))

    # Essence rate modifier (use Essence % at time of calc — simplify to current %)
    essence_rate = get_essence_xp_rate(character.essence_pct)
    xp_earned = int(actions_completed * action.xp_per_action * essence_rate)

    # Essence drain (constant regardless of rate)
    essence_drained = int((capped / 60) * get_config('idle_essence_drain_per_minute'))

    return xp_earned, essence_drained
```

### 5.3 Essence XP Rate Function

```python
def get_essence_xp_rate(essence_pct: float) -> float:
    full    = get_config('idle_essence_xp_full_threshold')      # 0.75
    mid     = get_config('idle_essence_xp_mid_threshold')       # 0.40
    low     = get_config('idle_essence_xp_low_threshold')       # 0.15
    crit    = get_config('idle_essence_xp_critical_threshold')  # 0.01
    floor   = get_config('idle_essence_xp_floor_rate')          # 0.10

    if essence_pct >= full:  return 1.00
    if essence_pct >= mid:   return 0.75
    if essence_pct >= low:   return 0.50
    if essence_pct >= crit:  return 0.25
    return floor
```

### 5.4 Stat Formula Application (at Story Mode session start)

```python
    magic_level     = skill_levels.get('Magic', 1)
    lore_level      = skill_levels.get('Lore', 1)

    return {
        'click_damage_floor':     attack_level // 2,
        'auto_dps_multiplier':    1.0 + (magic_level * 0.01),
        'gate_reduction':         min(lore_level * 0.003, 0.25),
        'essence_multiplier':     1.0 + (lore_level * 0.008),
        'crit_chance_bonus':      precision_level * 0.001,
        'crit_multiplier_total':  2.0 + (precision_level * 0.01),
    }
```

### 5.5 One-at-a-Time Training Enforcement

When a player starts training a skill:
1. Set `is_active_training = FALSE` on **all** `character_skill_levels` rows for this character.
2. Set `is_active_training = TRUE` on the target skill's row.
3. Set `action_started_at = NOW()`.
4. Set `last_offline_calc_at = NOW()`.

The partial unique index `uix_character_one_active_training` provides a database-level guarantee. The backend service should still enforce this in application logic before the DB call.

### 5.6 Active Mode XP Formula

```python
def xp_per_kill(action, wave_number):
    base = action.xp_per_action
    return int(base * (1.0 + (wave_number * 0.01)))

def xp_per_boss_kill(action):
    return action.xp_per_action * 5
```

## 6. Future Extension Points

These are NOT part of 2.3 scope. They are documented here to ensure the schema design does not block them.

| Feature | Extension Point |
|:--------|:----------------|
| Per-action Mastery system | Add `mastery_level INTEGER DEFAULT 1` and `mastery_xp NUMERIC DEFAULT 0` to `character_skill_levels` or a new `character_action_mastery` table |
| Skill pets | New `skill_pets` table with `skill_id`, `pet_key`, `unlock_condition_type`, `unlock_condition_value` |
| Interval reduction bonuses | Add `interval_modifier_pct NUMERIC DEFAULT 0` to `character_skill_levels`; modify offline calc |
| Additional skills (beyond 4) | No schema changes required — just seed new rows in `skills` and `skill_actions` |
| Skill outfit bonuses | Use existing `inventory_items.benefits_json` with new effect keys in `benefit_effect_data` |
| Admin action editor | `skill_actions` is fully admin-editable; no schema changes required |
