# REC 5.4: Banner & Scaling Editor (Visual & Difficulty Tuning)

This document defines the complete requirements for the Banner & Scaling Editor — admin tooling for configuring visual weight mappings on entity behaviors, wave difficulty settings, intensity curves, chapter scaling preview, and difficulty presets.

**Design:** [5.4_BANNER_SCALING_EDITOR_DESIGN.md](5.4_BANNER_SCALING_EDITOR_DESIGN.md) | **Schema:** [5.4_BANNER_SCALING_EDITOR_SCHEMA.md](5.4_BANNER_SCALING_EDITOR_SCHEMA.md)

## 1. Overview & Scope

### 1.1 Purpose
Section 5.4 provides admin tooling for tuning how entities render visually in the battle banner and how wave difficulty scales across the game. After this phase, a game admin should be able to:

- Configure how character stats (STR/AGI/INT) influence sprite size, movement speed, and VFX intensity per visual behavior
- Define reusable wave configuration presets and assign them to books/chapters as defaults
- Create named intensity curves that control how difficulty ramps across chapters within a book
- Preview projected HP/Gold/Wave curves for any chapter range, comparing two configurations side-by-side
- Save and load named difficulty presets that bundle game_configs tuning + curve + wave preset into a single A/B testable configuration

**Platform vision:** All difficulty tuning is admin-configurable and data-driven. A different book series could define its own difficulty curves, wave presets, and visual weight profiles without code changes.

### 1.2 Existing Foundation

| System | Current State | What 5.4 Does |
|--------|--------------|----------------|
| `visual_behaviors` table (5.3) | 5 seeded behaviors with `animation_config` JSONB | Extends with `stat_weights` JSONB for visual weight mapping |
| `scene_wave_configs` table (5.2) | Per-scene wave config — **0 of 724 scenes populated** | Adds wave presets as reusable templates + inheritance chain |
| `game_configs` table (2.4) | 137 keys across 18 categories | Adds global wave defaults; combat/upgrades keys captured in presets |
| Combat scaling (game_configs) | `hp_scaling_factor`, `monsters_per_zone`, stat coefficients | Preview tool visualizes impact; presets snapshot these values |

### 1.3 Scope Boundaries
- **In Scope:** Visual weight editor (stat_weights on visual_behaviors), wave presets with book/chapter assignment, difficulty curves with multi-dimension multipliers, chapter scaling preview with comparison mode, difficulty presets bundling configs + curve + wave preset.
- **Out of Scope:** Actual PixiJS rendering integration (deferred to C_BANNER_ANIMATION_SYSTEM). Drop rate tuning (5.5). Per-scene wave config editing (already in 5.2). Economy balancing (5.5). Player simulation in preview.
- **Dependencies:** 5.3 (Entity Classification) complete — `visual_behaviors` table exists. 5.2 (Game Content Editor) complete — `scene_wave_configs` table exists.

## 2. Visual Weight Editor

### 2.1 Concept
Visual weights define how a character's stats (STR/AGI/INT) influence the visual presentation of entities in the battle banner. Weights are stored per visual behavior so that different entity archetypes respond differently to stat scaling (e.g., a magic_caster might be more influenced by INT for VFX intensity, while grounded_melee is more influenced by STR for size).

### 2.2 Stat Weight Configuration
- [ ] **2.2.1** Add `stat_weights` (JSONB, nullable) column to the existing `visual_behaviors` table.
- [ ] **2.2.2** `stat_weights` JSONB structure:
  ```json
  {
    "size": {"strength": 0.6, "agility": 0.2, "intelligence": 0.2},
    "speed": {"strength": 0.1, "agility": 0.7, "intelligence": 0.2},
    "vfx_intensity": {"strength": 0.1, "agility": 0.1, "intelligence": 0.8},
    "clamps": {"size": [0.5, 2.5], "speed": [0.3, 1.5], "vfx_intensity": [0.0, 1.0]}
  }
  ```
  - `size`: How much each stat influences sprite scale factor.
  - `speed`: How much each stat influences movement speed modifier.
  - `vfx_intensity`: How much each stat influences VFX particle density/brightness.
  - `clamps`: Min/max bounds per visual property to prevent extreme values.
  - All weights are proportional (0.0–1.0). Weights within a property should sum to ~1.0 but are not strictly enforced.
- [ ] **2.2.3** Seed default `stat_weights` for all 5 existing visual behaviors:
  - `grounded_melee`: size STR-dominant (0.6), speed AGI-dominant (0.6), VFX slightly INT-biased (0.4)
  - `grounded_ranged`: size AGI-leaning (0.4), speed AGI-dominant (0.7), VFX INT-dominant (0.6)
  - `airborne`: size AGI-dominant (0.5), speed AGI-dominant (0.7), VFX INT-dominant (0.6)
  - `magic_caster`: size INT-dominant (0.6), speed INT-dominant (0.6), VFX heavily INT (0.85)
  - `hybrid`: equal weights (0.33/0.34) across all stats for all properties

### 2.3 Visual Weight Admin UI
- [ ] **2.3.1** Extend the existing `VisualBehaviorManager.tsx` (5.3, WorldBuilder → Classification → Visual Behaviors) with a "Stat Weights" section on the edit form.
- [ ] **2.3.2** Per-property (size, speed, vfx_intensity): three labeled slider inputs for STR/AGI/INT weights (0.0–1.0 range, step 0.05).
- [ ] **2.3.3** Clamp inputs: min/max number fields per property.
- [ ] **2.3.4** Visual indicator showing the weight distribution as a simple proportional bar (STR=red, AGI=green, INT=blue segments).
- [ ] **2.3.5** "Reset to Defaults" button per behavior to restore seeded values.

## 3. Wave Presets

### 3.1 Concept
Wave presets are named, reusable wave configuration templates stored as JSONB blobs. They can be assigned to books or chapters to provide default wave settings for scenes that lack their own `scene_wave_configs` record. The inheritance chain is: scene `scene_wave_configs` → chapter wave preset → book wave preset → global default wave preset → hardcoded fallback.

### 3.2 Wave Presets Table
- [ ] **3.2.1** Create `wave_presets` table with `id`, `name` (unique), `description`, `config` (JSONB), `is_default` (boolean, at most one true), `sort_order`, timestamps.
- [ ] **3.2.2** `config` JSONB structure:
  ```json
  {
    "max_enemies_per_wave": 5,
    "wave_count": 10,
    "spawn_interval_ms": 2000,
    "scaling_factor": 1.0,
    "hp_multiplier": 1.0,
    "gold_multiplier": 1.0,
    "spawn_pattern": "uniform"
  }
  ```
  - `spawn_pattern`: Controls enemy distribution across wave duration. Values: `"uniform"` (even spacing), `"front_loaded"` (more enemies early), `"crescendo"` (ramp up), `"random"` (randomized intervals).
  - All fields are optional within the JSONB — missing fields fall through to hardcoded defaults.
- [ ] **3.2.3** Seed one default preset: "Standard" with `is_default: true` matching current hardcoded values.

### 3.3 Wave Preset Assignments
- [ ] **3.3.1** Create `wave_preset_assignments` table with `id`, `wave_preset_id` (FK → wave_presets), `book_id` (FK → books, nullable), `chapter_id` (FK → chapters, nullable), timestamps.
- [ ] **3.3.2** Constraint: exactly one of `book_id` or `chapter_id` must be non-null (CHECK constraint).
- [ ] **3.3.3** Unique constraint on `(book_id)` where `book_id IS NOT NULL` and on `(chapter_id)` where `chapter_id IS NOT NULL` — each book/chapter can have at most one assigned preset.

### 3.4 Wave Preset Admin UI
- [ ] **3.4.1** CRUD interface for wave presets: create, edit, delete with deletion blocking (if assignments reference the preset).
- [ ] **3.4.2** Edit form with labeled inputs for each config field. Spawn pattern as dropdown.
- [ ] **3.4.3** "Set as Default" toggle — only one preset can be default. Setting a new default clears the old one.
- [ ] **3.4.4** Assignment panel: shows which books/chapters use this preset. Bulk assign/unassign from this view.
- [ ] **3.4.5** "Apply to Scenes" bulk action: writes the preset's config values into `scene_wave_configs` for all scenes in the assigned books/chapters that don't already have a scene-level config. Confirmation dialog with count of scenes to be populated.

### 3.5 Global Wave Defaults (game_configs)
- [ ] **3.5.1** Add the following game_configs keys as ultimate fallback values (category: `waves`):
  - `wave_default_max_enemies`: Default max enemies per wave (integer, default 5)
  - `wave_default_wave_count`: Default waves per scene (integer, default 10)
  - `wave_default_spawn_interval_ms`: Default spawn interval in ms (integer, default 2000)
  - `wave_default_spawn_pattern`: Default spawn pattern (string, default "uniform")

## 4. Intensity Curves (Difficulty Curves)

### 4.1 Concept
Difficulty curves define how wave density, HP, gold, and spawn speed scale across chapters within a book. Each curve is a named profile with multi-dimension per-chapter multipliers. Books reference a curve by FK — applying the curve multipliers on top of base values and wave presets.

### 4.2 Difficulty Curves Table
- [ ] **4.2.1** Create `difficulty_curves` table with `id`, `name` (unique), `description`, `curve_data` (JSONB), `is_default` (boolean, at most one true), `sort_order`, timestamps.
- [ ] **4.2.2** `curve_data` JSONB structure — chapter number (relative within book) → multi-dimension multipliers:
  ```json
  {
    "1": {"hp": 1.0, "gold": 1.0, "wave_density": 1.0, "spawn_speed": 1.0},
    "2": {"hp": 1.1, "gold": 1.05, "wave_density": 1.1, "spawn_speed": 1.0},
    "3": {"hp": 1.25, "gold": 1.1, "wave_density": 1.2, "spawn_speed": 0.95},
    "4": {"hp": 1.45, "gold": 1.15, "wave_density": 1.3, "spawn_speed": 0.9},
    "5": {"hp": 1.7, "gold": 1.2, "wave_density": 1.4, "spawn_speed": 0.85}
  }
  ```
  - `hp`: Multiplier on base enemy HP for that chapter position.
  - `gold`: Multiplier on base gold rewards.
  - `wave_density`: Multiplier on enemies per wave (applied on top of wave preset / scene config).
  - `spawn_speed`: Multiplier on spawn interval (< 1.0 = faster spawns).
  - Chapters beyond the defined range use the last defined entry's values.
- [ ] **4.2.3** Seed one default curve: "Standard Ramp" with `is_default: true` and a 10-chapter gentle ramp.

### 4.3 Book → Curve Assignment
- [ ] **4.3.1** Add `difficulty_curve_id` (FK → difficulty_curves, nullable, ON DELETE SET NULL) column to the `books` table.
- [ ] **4.3.2** When a book has no assigned curve, the global default curve is used. If no default exists, all multipliers are 1.0.

### 4.4 Intensity Curve Admin UI
- [ ] **4.4.1** CRUD interface for difficulty curves: create, edit, delete with deletion blocking (if books reference the curve).
- [ ] **4.4.2** Table-based editor: rows = chapter numbers, columns = hp / gold / wave_density / spawn_speed multipliers. Editable number inputs.
- [ ] **4.4.3** "Add Chapter Row" / "Remove Last Row" buttons to extend or shorten the curve.
- [ ] **4.4.4** "Set as Default" toggle — same pattern as wave presets.
- [ ] **4.4.5** Shows which books use this curve, with quick-assign/unassign controls.

## 5. Chapter Scaling Preview

### 5.1 Concept
A read-only calculator that computes and displays projected difficulty values for a given chapter range, using the current game settings. Supports comparison mode to evaluate two configurations side-by-side before applying changes.

### 5.2 Preview Calculator
- [ ] **5.2.1** Admin selects: Book (dropdown), Chapter range (from/to), and Configuration source:
  - **"Current"**: Uses the currently active game_configs, assigned difficulty curve, and wave preset.
  - **"Preset"**: Uses a selected difficulty preset (loads its config_snapshot, referenced curve, and wave preset).
- [ ] **5.2.2** For each chapter in the range, compute and display:
  - **Base HP**: `hp_scaling_factor ^ chapter_position × curve_hp_multiplier`
  - **Base Gold**: Base gold value × `session_gold_multiplier` × `curve_gold_multiplier`
  - **Wave Count**: From wave preset or scene_wave_configs
  - **Enemies/Wave**: `max_enemies_per_wave × curve_wave_density_multiplier`
  - **Spawn Interval**: `spawn_interval_ms × curve_spawn_speed_multiplier`
  - **Effective Difficulty**: Composite index combining HP, density, and speed factors

### 5.3 Comparison Mode
- [ ] **5.3.1** Two-column layout: "Configuration A" vs. "Configuration B". Each column independently selects its source (Current or a Preset).
- [ ] **5.3.2** Per-cell color coding: green for decreases (easier), red for increases (harder), neutral for unchanged. Percentage delta shown in parentheses.
- [ ] **5.3.3** Summary row at bottom: average difficulty change across the selected range.

## 6. Difficulty Presets

### 6.1 Concept
Difficulty presets are named configurations that bundle a snapshot of combat/scaling game_configs values with references to a difficulty curve and a wave preset. Presets enable A/B testing of difficulty configurations — save "known good" settings before experimenting, then apply a different preset to test.

### 6.2 Difficulty Presets Table
- [ ] **6.2.1** Create `difficulty_presets` table with `id`, `name` (unique), `description`, `difficulty_curve_id` (FK → difficulty_curves, nullable), `wave_preset_id` (FK → wave_presets, nullable), `config_snapshot` (JSONB), `is_active` (boolean, at most one true), timestamps.
- [ ] **6.2.2** `config_snapshot` JSONB: Captures all game_configs keys in the `combat` and `upgrades` categories, plus `session_gold_multiplier` and `first_clear_multiplier` from `economy`. Category-based capture — if new keys are added to `combat` or `upgrades` categories, they are automatically included in future snapshots.
- [ ] **6.2.3** `is_active`: Tracks which preset is currently applied. Only one preset can be active at a time.

### 6.3 Preset Lifecycle
- [ ] **6.3.1** **Create**: Admin names the preset. System auto-captures current game_configs values (combat + upgrades + economy subset). Admin selects which difficulty curve and wave preset to associate.
- [ ] **6.3.2** **Apply**: Writes the `config_snapshot` values back into `game_configs`, updates book `difficulty_curve_id` assignments to the preset's curve, and updates `wave_preset_assignments` for the preset's wave preset. Sets `is_active = true` (clears previous active). Confirmation dialog showing count of changes.
- [ ] **6.3.3** **Revert**: No auto-revert mechanism. Admins revert by applying a different preset (e.g., a saved "Production Default" preset). The preset system itself is the safety net.
- [ ] **6.3.4** **Update**: Admin can re-snapshot current values into an existing preset, or change the associated curve/wave preset.
- [ ] **6.3.5** **Delete**: Soft-block if preset `is_active`. Otherwise, delete freely.

### 6.4 Difficulty Preset Admin UI
- [ ] **6.4.1** CRUD interface for difficulty presets: list with name, description, associated curve, associated wave preset, active status badge.
- [ ] **6.4.2** Create form: name, description, curve picker, wave preset picker. "Capture Current Settings" button auto-fills the config_snapshot.
- [ ] **6.4.3** Detail view: expandable config_snapshot showing all captured key-value pairs, grouped by category.
- [ ] **6.4.4** "Apply Preset" button with confirmation dialog listing all changes (game_configs to be overwritten, curve/wave preset assignments to change).
- [ ] **6.4.5** Active preset indicator: badge on the list view, banner on the page header showing currently active preset name.

## 9. Design Decisions (Resolved)

| # | Decision | Resolution | Rationale |
|---|----------|------------|-----------|
| Q1 | Visual weight storage | `stat_weights` JSONB on `visual_behaviors` table | Co-locates weights with the behavior they affect; extensible without migration |
| Q2 | Global wave settings | game_configs defaults + `wave_presets` table with assignment | Inheritance chain (scene → chapter → book → global default) manages 724 scenes without per-scene config |
| Q3 | Intensity curve scope | Named `difficulty_curves` table, books reference by FK | Platform reusability — different book series use different curves |
| Q4 | Scaling preview output | Read-only calculator with comparison mode (two configs side-by-side) | Comparison is most actionable for A/B testing decisions |
| Q5 | Difficulty preset scope | game_configs snapshot + curve FK + wave preset FK | Captures meaningful tuning knobs without over-reaching into visual territory |
| Q6 | UI placement | Fourth tab in WorldBuilder: "Scaling & Difficulty" | Consolidates all game-world config under one roof |
| Q7 | stat_weights structure | Flat weights per property + global clamps section | Clamps prevent extremes without per-stat complexity |
| Q8 | Wave preset storage | JSONB blob (flexible, decoupled from scene_wave_configs schema) | Schema changes to wave config don't require preset migration |
| Q8b | Wave preset assignment | Separate `wave_preset_assignments` table, no FK on existing tables | Clean separation, no alteration of existing book/chapter tables |
| Q9 | Difficulty curve dimensions | Multi-dimension (hp, gold, wave_density, spawn_speed per chapter) | HP and gold often need independent scaling rates |
| Q10 | Preset component references | FKs to curve + wave preset, JSONB snapshot for game_configs | FKs stay in sync; snapshot captures point-in-time tuning values |
| Q11 | Preset config capture scope | Category-based: all `combat` + `upgrades` keys + economy subset | Self-maintaining — new keys in those categories auto-included |
| Q12 | Preset revert mechanism | No auto-revert — apply a different preset to revert | Presets themselves are the safety net; simplest approach |
| Q13 | Preview visualization | Table-only with color-coded diff cells | Consistent with existing admin UI patterns; no chart library dependency |
