# REC 5.2: Game Content Editor (Narrative & World Data)

This document defines the complete requirements for the Game Content Editor — a comprehensive admin tooling suite for managing all narrative and world-building data in the Elysium Rising universe.

**Design:** [5.2_GAME_CONTENT_EDITOR_DESIGN.md](5.2_GAME_CONTENT_EDITOR_DESIGN.md) | **Schema:** [5.2_GAME_CONTENT_EDITOR_SCHEMA.md](5.2_GAME_CONTENT_EDITOR_SCHEMA.md)
**Parent:** [5.0_ADMIN_SYSTEMS.md](5.0_ADMIN_SYSTEMS.md) §2 (5.2)

## 1. Overview & Scope

### 1.1 Purpose
Section 5.2 provides admin tooling for managing all narrative and world-building data that was initially seeded via SQL migrations and the `book_parser` tool (Phase A). After this phase, a game admin should be able to:

- View and edit all books, chapters, scenes, and story beats
- Manage the full entity catalog (3,936+ entities across 9 types) including gameplay data
- Configure scene wave composition and entity spawn behavior
- Manage locations with full sensory metadata and atmosphere associations
- Assign entities to scenes and story beats with bulk operations
- Manage background definitions for scene rendering
- Edit semantic tags for AI-enriched story beat metadata
- Manage entity and location aliases

**Platform vision:** This editor is designed so that content from any book series can be managed entirely through the admin UI once initially loaded via the book_parser tool (Phase A). Future bulk content population at scale is handled by C_ generators — this editor is for **managing and editing** that content going forward.

### 1.2 Scope Boundaries
- **In Scope:** Book/Chapter/Scene CRUD (read-only raw_text on books/chapters/scenes), Story Beat CRUD (full text editing), Entity CRUD (all types — narrative + gameplay), Entity Gameplay Data editing, Background definitions (new table), Scene Wave Config (new table), Entity-Scene/Beat mapping, Location CRUD with sensory fields, Semantic Tag management, Entity/Location alias management, Boss Config structured editor, World Builder top-level page shell.
- **Out of Scope:** C_ content generators (deferred to final pass), initial book ingestion (Phase A `book_parser`), entity type/classification management (5.3), banner & scaling visual behavior (5.4), drop rate / HP tuning (5.5), dev content audit dashboard (5.6), asset registry (5.7 — complete). Attack type management stays in existing ContentEditor (2.4).
- **Dependencies:** All prior phases (1.0–3.6, 5.7, 5.1) complete. Database migrations 001–056 applied. Existing ContentEditor page and admin route infrastructure.

### 1.5 Page Architecture
A new top-level **"World Builder"** admin page is created that serves as the primary content editing interface. It contains two major sub-sections:

- **Narrative Editor** (new — 5.2): Books, Chapters, Scenes, Story Beats, Entities, Locations, Backgrounds, Semantic Tags, Entity/Location mappers
- **Content Editor** (existing — 2.4): Stats, Classes, Skills, Benefits, Items, Attack Types, Gear Slots

The existing ContentEditor page is preserved but accessible as a tab/route within World Builder. The admin sidebar navigation gets a "World Builder" entry that replaces or sits alongside the existing "Content Editor" link.

### 1.6 Audit Requirements
Every admin mutation in this phase **must** be logged to `admin_audit_log` with:
- `admin_email`: Authenticated admin's email
- `action`: Descriptive action name (e.g., `book_updated`, `entity_created`, `scene_wave_config_updated`)
- `target_type`: Resource type (e.g., `book`, `chapter`, `scene`, `entity`, `location`)
- `target_id`: Resource ID
- `details`: JSON payload with before/after values where applicable
- `ip_address`: Request IP

### 1.7 Deletion Policy
All delete operations use **hard confirmation with child record blocking**:
- If a record has child records (e.g., a book has chapters, a scene has story_beats), deletion is **blocked** until all child records are manually removed or reassigned.
- The confirmation dialog displays the exact count and type of child records preventing deletion.
- No cascade deletes are triggered from the admin UI (even though DB cascades exist as a safety net).
- This prevents accidental data loss of deeply nested content trees.

## 9. Background Editor

### 9.1 Purpose
CRUD for background definitions — a new `backgrounds` table that stores metadata for scene backgrounds. This replaces the loose `background_sprite_key` string on `scene_gameplay_data` with a structured record that can hold parallax layers, time-of-day variants, and other visual metadata for the battle banner renderer.

### 9.2 Fields

| Field | Type | Constraints | Notes |
|:---|:---|:---|:---|
| `id` | SERIAL | PK | Auto-increment |
| `name` | varchar(100) | Required, unique | Display name (e.g., "Dark Forest", "Crystal Cavern") |
| `description` | text | Optional | Description for admin reference |
| `background_key` | varchar(100) | Required, unique | Asset reference key (links to Asset Registry `background` category) |
| `parallax_config` | JSONB | Optional, default: {} | Parallax layer configuration (layer depths, scroll speeds) |
| `time_of_day` | varchar(50) | Optional | Time variant (e.g., "day", "night", "dusk", "dawn") |
| `mood` | varchar(50) | Optional | Visual mood (e.g., "ominous", "serene", "chaotic") |
| `color_palette` | JSONB | Optional | Dominant color palette for tinting/effects |
| `created_at` | timestamptz | Default: NOW() | Timestamp |
| `updated_at` | timestamptz | Default: NOW() | Timestamp |

### 9.3 Migration from `background_sprite_key`
A migration creates the `backgrounds` table and:
1. Scans all unique `background_sprite_key` values in `scene_gameplay_data`.
2. Creates a `backgrounds` row for each unique value (name = key, background_key = key).
3. Adds `background_id` FK column to `scene_gameplay_data`.
4. Populates `background_id` from the matching `backgrounds.background_key`.
5. `background_sprite_key` is retained temporarily for backwards compatibility but marked deprecated. New code uses `background_id`.

### 9.4 Asset Registry Integration
Each `backgrounds.background_key` should correspond to an Asset Registry entry with category `background`. The Background Editor includes a "Preview" button that renders the asset using the Asset Registry's `AssetPreview` component.

### 9.5 UI: Background Editor
- **Location:** World Builder → Narrative Editor → Backgrounds tab
- **Layout:** Grid view (showing previews) or table view. Columns: name, background_key, mood, time_of_day, scene_count (how many scenes use this background).
- **Detail panel:** All fields editable. Asset Registry picker for background_key. Parallax config as structured JSON editor. Color palette as a color picker array.
- **Actions:** Create, Edit, Delete (blocked if any `scene_gameplay_data` records reference this background).

## 10. Scene Wave Config

### 10.1 Purpose
Per-scene wave composition configuration via a new `scene_wave_configs` table. This defines how enemy waves are composed for each scene — which entities spawn, in what quantities, and at what rates.

### 10.2 Fields

| Field | Type | Constraints | Notes |
|:---|:---|:---|:---|
| `id` | SERIAL | PK | Auto-increment |
| `scene_id` | integer | Required, FK → scenes, unique | One config per scene |
| `max_enemies_per_wave` | integer | Default: 5 | Maximum simultaneous enemies |
| `wave_count` | integer | Default: 10 | Number of waves in this scene |
| `spawn_interval_ms` | integer | Default: 2000 | Base spawn interval in milliseconds |
| `scaling_factor` | float | Default: 1.0 | Difficulty scaling multiplier for this scene |
| `hp_multiplier` | float | Default: 1.0 | HP scaling multiplier applied to all entities in this scene |
| `gold_multiplier` | float | Default: 1.0 | Gold reward multiplier for this scene |
| `entity_pool` | JSONB | Default: [] | Array of `{entity_id, weight, min_wave, max_wave}` defining spawn pool |
| `boss_entity_id` | integer | Optional, FK → entities | Boss entity for boss waves (null for normal scenes) |
| `created_at` | timestamptz | Default: NOW() | Timestamp |
| `updated_at` | timestamptz | Default: NOW() | Timestamp |

### 10.3 Entity Pool Structure
Each entry in the `entity_pool` JSONB array:
```json
{
  "entity_id": 42,
  "weight": 1.0,
  "min_wave": 1,
  "max_wave": null
}
```
- `weight`: Relative spawn probability (higher = more frequent). Normalized across all pool entries.
- `min_wave` / `max_wave`: Wave range this entity can appear in (null = no limit).

### 10.4 Bulk Operations (QoL)
- **Apply Base Template:** Set a base wave config (max_enemies, wave_count, spawn_interval) and apply it across all scenes in a chapter or book with automatic scaling:
  - Scene index within chapter determines `scaling_factor` increment (e.g., +0.1 per scene).
  - Later chapters within a book get higher base scaling.
- **Copy Config:** Copy wave config from one scene to another (or to all scenes in a chapter).
- **Bulk HP/Gold Scaling:** Select multiple scenes and apply a multiplier adjustment to `hp_multiplier` / `gold_multiplier` across all selected.
- **Auto-populate Entity Pool:** For scenes with `entity_scene_appearances` but no wave config, generate an initial `entity_pool` from the scene's assigned entities (equal weights, full wave range).

### 10.5 UI: Scene Wave Config
- **Location:** Accessible from Scene Editor detail panel as "Wave Config" section, and as a dedicated World Builder → Narrative Editor → Wave Config tab for bulk editing.
- **Scene Editor integration:** Inline wave config form within Scene Editor's "Gameplay" section.
- **Bulk tab:** Table of all scenes with wave config summary columns. Multi-select for bulk operations. "Apply Template" dialog with chapter/book scope selector and scaling formula preview.
- **Entity Pool editor:** Drag-and-drop entity list with weight sliders, min/max wave inputs. "Add from Scene Entities" quick-add button.
- **Actions:** Create (for scenes without config), Edit, Delete, Bulk Apply Template, Bulk Adjust Multipliers.

### 11.1 Purpose

- **Actions:** Create, Edit, Delete (blocked if scenes reference this location via `primary_location_id`, or if `location_scene_appearances` / `location_aliases` exist).

## 16. Design Decisions (Resolved)

| # | Decision | Resolution | Rationale |
|:---|:---|:---|:---|
| 1 | Raw text editing scope | Story beats only — books/chapters/scenes show raw_text as read-only reference | Story beats are what players see; chapter/scene raw_text is source material |
| 2 | Entity editor breadth | Full CRUD for all 9 entity types (3,936+ entities) | Platform needs — not just gameplay entities. C_ generator backfills gameplay data later |
| 3 | Location sensory fields | Expose all 5 fields (visual, auditory, olfactory, tactile, atmosphere) + new `description` column | DB has these columns; `description` is general-purpose, others are sense-specific |
| 4 | Background storage | New `backgrounds` table with metadata (parallax, mood, color) | Structured data needed for Background Editor in 5.4; loose string keys insufficient |
| 5 | Wave composition | New `scene_wave_configs` table with entity pool, multipliers, bulk operations | Per-scene config needed; bulk template + scaling QoL essential for 724 scenes |
| 6 | Story beat fields | All fields editable including FK pickers (location, image, audio) | Full editing needed for content enrichment |
| 7 | Semantic tags | Fully editable, searchable, sortable with category counts | Admins need to correct/enrich AI-generated tags |
| 8 | Entity/Location aliases | Managed inline within respective editors | Natural grouping; aliases are tightly coupled to parent records |
| 9 | Entity-beat appearances | Included in 5.2 (not deferred) | 8,500 records exist; granular mapping needed for NarrativeBlock rendering |
| 10 | Book creation flow | Edit-only — initial population via book_parser (Phase A) | Platform reusability via external loaders, not admin UI from-scratch creation |
| 11 | Deletion policy | Block deletion if child records exist; hard confirm with child counts | Prevents accidental cascade loss of deeply nested content trees |
| 12 | Boss config editing | Structured sub-editor (not raw JSON) | Boss config has known shape; structured UI prevents malformed configs |
| 13 | Page architecture | Top-level "World Builder" containing Narrative Editor (new) + Content Editor (existing) | Clean separation; single entry point for all content management |
| 14 | Admin docs task | Add D_ task for system platform instruction documentation and admin user guides | Non-developer admins need onboarding documentation |
