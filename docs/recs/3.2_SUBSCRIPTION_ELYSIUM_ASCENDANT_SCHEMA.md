## Pre-Existing Tables (Extended)

### `players` — New Columns

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `is_ascendant` | `BOOLEAN` | `NOT NULL DEFAULT FALSE` | Fast-lookup flag: TRUE while subscription is active/past_due/canceling. Kept in sync by subscription service. |
| `cumulative_subscription_months` | `INTEGER` | `NOT NULL DEFAULT 0` | Lifetime total months subscribed. Monotonically increasing (decremented only on refund). Persists across subscription rows. |

**Index:**
- `idx_players_is_ascendant` ON `(is_ascendant)` WHERE `is_ascendant = TRUE`

### `shard_transactions` — No Schema Changes

The existing `shard_transactions` table (migration 046) supports the new `source_type` values:
- `'subscription_stipend'` — monthly shard stipend credit
- `'subscription_refund'` — stipend clawback on subscription refund

No structural changes needed.

### `player_meta_progression` — No Schema Changes

The existing `shard_balance` and `total_shards_earned` fields are reused for stipend crediting.

### `titles` — New Seed Data Only

10 new titles seeded (1 subscriber + 7 cumulative loyalty + 2 achievement rewards). No column changes.
- Columns used: `name` (VARCHAR UNIQUE), `display_format` ('prefix'|'suffix'), `sort_order`, `achievement_id` (set after achievement insert).

### `achievements` — New Seed Data Only

11 new achievements seeded. No column changes.
- Columns used: `name`, `description`, `category` ('economics'), `tracking_type` ('cumulative'|'threshold'), `tracking_source` (stat key), `threshold_value` (NUMERIC), `parent_achievement_id`, `reward_shards`, `reward_essence`, `reward_title_id` (FK to titles).
- **No `achievement_key` column exists.** Achievements are identified by `name` in seed subqueries.
- **No `badge` reward type exists.** Big Spender I uses `reward_shards=0, reward_essence=0` with a descriptive note (badge display is a frontend-only cosmetic based on the achievement being earned, not a separate reward mechanism).

## New Tables

### `player_subscriptions`

Tracks subscription lifecycle. **Append-only:** each subscription period gets its own row. When a player re-subscribes after a lapse, a new row is created. Old rows persist with `status = 'expired'` for historical reference.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `player_id` | `INTEGER` | `NOT NULL FK players ON DELETE CASCADE` | Subscribing player |
| `stripe_subscription_id` | `VARCHAR(255)` | `DEFAULT NULL` | Stripe Subscription ID (`sub_...`). NULL for admin-gifted subscriptions. |
| `stripe_price_id` | `VARCHAR(255)` | `DEFAULT NULL` | Stripe Price ID currently applied to this subscription |
| `plan_key` | `VARCHAR(30)` | `NOT NULL` | Plan identifier: `'ascendant_monthly'` or `'ascendant_annual'` |
| `status` | `VARCHAR(20)` | `NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'past_due', 'canceling', 'expired'))` | Subscription lifecycle state |
| `source` | `VARCHAR(20)` | `NOT NULL DEFAULT 'stripe' CHECK (source IN ('stripe', 'admin_gift'))` | How the subscription was created |
| `subscription_start_date` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Original subscription start date (anchor for annual stipend anniversaries). Does NOT change on plan switch. |
| `current_period_start` | `TIMESTAMPTZ` | `NOT NULL` | Start of the current billing period |
| `current_period_end` | `TIMESTAMPTZ` | `NOT NULL` | End of the current billing period |
| `cancel_at_period_end` | `BOOLEAN` | `NOT NULL DEFAULT FALSE` | TRUE when player has requested cancellation but period hasn't ended |
| `continuous_streak` | `INTEGER` | `NOT NULL DEFAULT 0` | Consecutive months in this subscription period. Reset to 0 on lapse. |
| `grace_period_start` | `TIMESTAMPTZ` | `DEFAULT NULL` | When payment failure was detected (NULL = no active grace period) |
| `grace_deadline` | `TIMESTAMPTZ` | `DEFAULT NULL` | When grace period expires (23:59:59 UTC of next business day). NULL = no active grace period. |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Row creation time |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Last update time |

**Indexes:**
- `idx_psub_player_status` ON `(player_id, status)` — for active subscription lookup
- `idx_psub_player_created` ON `(player_id, created_at DESC)` — for latest subscription row
- `idx_psub_stripe_sub` ON `(stripe_subscription_id)` WHERE `stripe_subscription_id IS NOT NULL` — for webhook lookups
- `idx_psub_status_grace` ON `(status, grace_deadline)` WHERE `status = 'past_due'` — for grace period expiration checks

**Trigger:** `trg_player_subscriptions_updated_at` — auto-sets `updated_at` on UPDATE.

**State Machine:**
```
active → canceling (player cancels, cancel_at_period_end=TRUE)
active → past_due (payment failed, grace period started)
active → expired (admin force-cancel or refund)
canceling → active (player reactivates before period end)
canceling → expired (period ends, customer.subscription.deleted webhook)
past_due → active (payment succeeds during grace)
past_due → expired (grace period expires — set by lazy check or webhook)
expired → (terminal for this row — new row created on re-subscribe)
```

### `subscription_stipend_log`

Tracks each stipend credit for idempotency, audit, and clawback calculation. One row per credited month.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `subscription_id` | `INTEGER` | `NOT NULL FK player_subscriptions ON DELETE CASCADE` | The subscription row this stipend belongs to |
| `player_id` | `INTEGER` | `NOT NULL FK players ON DELETE CASCADE` | Denormalized for efficient player-level queries |
| `period_key` | `VARCHAR(7)` | `NOT NULL` | Dedup key: `YYYY-MM` format (e.g., `'2026-03'`). Prevents double-crediting for the same month. |
| `shards_credited` | `INTEGER` | `NOT NULL CHECK (shards_credited > 0)` | Number of shards credited (base + streak bonus) |
| `stripe_invoice_id` | `VARCHAR(255)` | `DEFAULT NULL` | Stripe Invoice ID (`in_...`) that triggered this credit. NULL for lazy-credited annual stipends. |
| `period_start` | `TIMESTAMPTZ` | `NOT NULL` | Billing period start for this stipend |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | When the stipend was credited |

**Indexes:**
- `idx_stipend_sub_period` ON `(subscription_id, period_key)` UNIQUE — idempotency constraint
- `idx_stipend_player` ON `(player_id, created_at DESC)` — for player history queries
- `idx_stipend_invoice` ON `(stripe_invoice_id)` WHERE `stripe_invoice_id IS NOT NULL` — for webhook dedup

**Unique constraint:** `(subscription_id, period_key)` — ensures a subscription can only credit one stipend per calendar month.

## Entity-Relationship Summary

```
players
  ├── is_ascendant (BOOLEAN)
  ├── cumulative_subscription_months (INTEGER)
  ├── stripe_customer_id (VARCHAR, from 3.1)
  │
  ├──< player_subscriptions (player_id FK)  [APPEND-ONLY]
  │       ├── stripe_subscription_id (nullable, for Stripe subs)
  │       ├── plan_key ('ascendant_monthly' | 'ascendant_annual')
  │       ├── status ('active' | 'past_due' | 'canceling' | 'expired')
  │       ├── source ('stripe' | 'admin_gift')
  │       ├── continuous_streak (per-period, resets on new row)
  │       └── grace_period_start / grace_deadline (NULL when healthy)
  │
  ├──< subscription_stipend_log (player_id FK)
  │       ├── subscription_id FK → player_subscriptions
  │       ├── period_key (YYYY-MM, unique per subscription)
  │       └── shards_credited
  │
  ├──< shard_transactions (player_id FK)  [existing table, no changes]
  │       └── source_type: 'subscription_stipend' | 'subscription_refund' (new values)
  │
  ├──< player_titles (player_id FK)  [existing table, no changes]
  │       └── title_id FK → titles (new loyalty/subscriber titles seeded)
  │
  └──< player_achievements (player_id FK)  [existing table, no changes]
          └── achievement_id FK → achievements (new subscription achievements seeded)

titles (10 new rows: 1 subscriber + 7 cumulative loyalty + 2 achievement rewards)
achievements (11 new rows: 4 cumulative + 1 streak + 3 shard collector + 3 big spender)
game_configs (11 new rows: category 'subscription')
```
