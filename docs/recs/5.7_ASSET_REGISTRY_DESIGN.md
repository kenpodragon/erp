### 1.2 Model: `AssetRegistryEntry`

```python
class AssetRegistryEntry(SQLModel, table=True):
    __tablename__ = "asset_registry"

    id: Optional[int] = Field(default=None, primary_key=True)
    asset_key: str = Field(max_length=150, unique=True, nullable=False, index=True)
    category: str = Field(max_length=50, nullable=False)
    display_name: Optional[str] = Field(default=None, max_length=200)
    description: Optional[str] = Field(default=None)

    render_definition: Optional[Any] = Field(
        default=None,
        sa_column=Column(JSON, default={}),
    )

    tags: Optional[Any] = Field(
        default=None,
        sa_column=Column(JSON, default=[]),
    )

    source: str = Field(default="admin", max_length=50)
    created_at: Optional[datetime] = Field(default=None)
    updated_at: Optional[datetime] = Field(default=None)
```

### 1.3 Category Constraint
Category values are validated at the application level (not DB CHECK constraint) for forward-compatibility as new categories are added:

```python
VALID_CATEGORIES = [
    "entity_sprite", "class_sprite", "background",
    "item_icon", "artifact_icon", "achievement_icon", "skill_icon",
    "avatar", "skin", "badge", "flair",
    "spell_effect", "ui_icon", "narrative_image", "portrait",
]
```

### 1.4 Source Values
| Source | Meaning |
|--------|---------|
| `seed` | Created by migration seed data |
| `admin` | Manually created/edited via admin UI |
| `generator` | Created by a C_ generator pipeline |
| `migrated` | Converted from existing filesystem PNG |

### 2.2 Orphan Detection: Missing Assets
```
GET /api/admin/assets/orphans/missing
```

Queries all tables with sprite_key/icon_sprite_key columns, collects distinct values, and LEFT JOINs against `asset_registry` to find unregistered keys.

**Response:**
```json
{
  "missing": [
    {
      "asset_key": "enemy_phantom",
      "referenced_in": [
        { "table": "entity_gameplay_data", "column": "sprite_key", "count": 3 }
      ],
      "suggested_category": "entity_sprite"
    }
  ],
  "total": 7
}
```

### 2.3 Orphan Detection: Unused Assets
```
GET /api/admin/assets/orphans/unused
```

Reverse query — finds registry entries whose `asset_key` does not appear in any game table sprite_key/icon column.

**Response:**
```json
{
  "unused": [
    {
      "asset_key": "test_icon_old",
      "category": "ui_icon",
      "source": "admin",
      "created_at": "2026-03-10T..."
    }
  ],
  "total": 2
}
```

## 3. Render Definition Schemas (per Category)

Each category has a recommended `render_definition` structure. These are **conventions**, not hard constraints — the JSONB column accepts any valid JSON, allowing generators and admins flexibility.

### 4.2 AssetRenderer Core

```typescript
// Pseudocode — actual implementation in S3.1

interface RenderResult {
  canvas: HTMLCanvasElement;       // For Canvas 2D renders
  texture?: PIXI.Texture;         // For PixiJS renders (created from canvas)
  width: number;
  height: number;
}

class AssetRenderer {
  private cache: Map<string, RenderResult>;
  private maxCacheBytes: number = 50 * 1024 * 1024; // 50MB

  render(assetKey: string, definition: RenderDefinition, category: string): RenderResult {
    const cacheKey = `${assetKey}:${hashDefinition(definition)}`;
    if (this.cache.has(cacheKey)) return this.cache.get(cacheKey)!;

    const renderer = this.getRenderer(category);
    const result = renderer.render(definition);

    this.cache.set(cacheKey, result);
    this.evictIfNeeded();
    return result;
  }

  private getRenderer(category: string): CategoryRenderer {
    switch (category) {
      case 'entity_sprite': return EntityRenderer;
      case 'class_sprite': return ClassRenderer;
      case 'background': return BackgroundRenderer;
      case 'item_icon': case 'artifact_icon': case 'achievement_icon':
      case 'skill_icon': case 'ui_icon': return IconRenderer;
      case 'avatar': return AvatarRenderer;
      case 'skin': return SkinRenderer;
      case 'badge': return BadgeRenderer;
      case 'flair': return FlairRenderer;
      case 'spell_effect': return VFXRenderer;
      case 'narrative_image': return TextImageRenderer;
      case 'portrait': return PortraitRenderer;
      default: return PlaceholderRenderer;
    }
  }
}
```

### 4.3 Asset Data Flow

```
1. Game component needs visual for asset_key "enemy_sludge"
2. → AssetProvider.getAsset("enemy_sludge")
3.   → Check in-memory definition cache
4.   → If miss: fetch from /api/admin/assets/{key} (or preloaded batch)
5.   → Return { asset_key, category, render_definition }
6. → AssetRenderer.render("enemy_sludge", definition, "entity_sprite")
7.   → Check rendered canvas cache
8.   → If miss: EntityRenderer.render(definition) → canvas → texture
9.   → Return RenderResult { canvas, texture, width, height }
10. → Component uses texture in PixiJS sprite or canvas in DOM
```

### 4.4 Batch Preloading
For performance, scene entry preloads all assets needed for that scene:

```typescript
// Called when entering a story mode scene
const assetKeys = [
  ...sceneEntities.map(e => e.sprite_key),
  sceneBackgroundKey,
  playerClassSpriteKey,
];
await assetProvider.preloadBatch(assetKeys);
```

The `preloadBatch` endpoint (`GET /api/admin/assets/batch?keys=a,b,c`) returns multiple definitions in one request.

### 4.5 Fallback Behavior
When an `asset_key` has no registry entry:

1. Render a colored rectangle with the key name as text label
2. Use category-appropriate default colors (red border for entity_sprite, blue for background, etc.)
3. Log to `dev_content_audit` via the existing audit endpoint
4. Cache the fallback so it's only logged once per session

## 8. Performance Considerations

### 8.1 Admin Grid Preview
Rendering 50 canvas thumbnails simultaneously on page load could be slow. Mitigations:
- **Lazy rendering:** Use IntersectionObserver — only render previews visible in viewport
- **Thumbnail size:** 48×48 max for grid view (minimal computation)
- **Web Worker (future):** Offscreen canvas rendering in worker if needed

### 8.2 Game Runtime
- **Preload on scene entry:** Batch-fetch all asset definitions for the current scene
- **LRU cache with 50MB limit:** Evict least-recently-used rendered textures
- **Definition cache:** Store raw JSONB definitions separately (small) from rendered canvases (large)

### 8.3 Batch Preload API
The `/api/admin/assets/batch?keys=a,b,c` endpoint prevents N+1 queries during scene loading. Single query with `WHERE asset_key IN (...)`.
