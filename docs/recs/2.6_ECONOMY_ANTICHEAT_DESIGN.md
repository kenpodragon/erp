# REC 2.6: Economy, Anti-Cheat & Discovery — Design Specification

This document details the technical architecture, database schemas, and API specifications for the Economy, Anti-Cheat, and Discovery systems in the Elysium Rising MMORPG.

---

## 1. Database Schema Extensions

### 1.1 Discovery & Registry (Atomic JSONB)
To prevent race conditions, all updates to `registry_kills` and `registry_discoveries` must use atomic SQL operations (e.g., `jsonb_set` or `||`).

| Table | Column | Type | Description |
| :--- | :--- | :--- | :--- |
| `player_progress` | `registry_kills` | `JSONB` | `{ "entity_id": { "encounters": int, "kills": int } }` |
| `player_progress` | `registry_discoveries` | `JSONB` | `{ "type": ["id1", "id2"] }` (e.g., `prefix`, `skill`). |
| `player_progress` | `has_completed_onboarding` | `BOOLEAN` | Account-wide status (Default: `FALSE`). |

### 1.2 Real-Time Communication (Chat Persistence)
- **Soft Limit:** Only the last 100-200 messages are fetched by clients.
- **Cleanup:** A weekly background job (or CRON) prunes messages older than 7 days from `chat_messages`.

| Table | Column | Type | Description |
| :--- | :--- | :--- | :--- |
| `chat_messages` | `id` | `UUID` | Primary Key. |
| `chat_messages` | `player_id` | `INTEGER` | FK to `players`. |
| `chat_messages` | `channel_id` | `VARCHAR(50)` | Default: `'global'`. |
| `chat_messages` | `content` | `TEXT` | Sanitized message content. |
| `chat_messages` | `is_system` | `BOOLEAN` | TRUE for milestone broadcasts. |
| `chat_messages` | `created_at` | `TIMESTAMPTZ` | Index for chronological retrieval. |

### 1.3 Anti-Cheat & Auditing
| Table | Column | Type | Description |
| :--- | :--- | :--- | :--- |
| `admin_audit_log` | `discrepancy_score` | `INTEGER` | Counter for serious discrepancies (e.g., currency mismatch). |
| `admin_audit_log` | `metadata` | `JSONB` | Details of the discrepancy (Expected vs. Reported). |

## 2. Technical Architecture

### 2.1 Live Chat (WebSockets)
- **Protocol:** FastAPI `WebSocket` (WSS).
- **Authentication:** JWT passed via query parameter or initial "auth" message.
- **Heartbeat:** Server sends a `ping` every 30s; Client must respond with `pong`. 
- **Reconnection:** Client implements exponential backoff for dropped connections.
- **Profanity Filter:** Blocklist is loaded into an in-memory **Aho-Corasick** matcher on server startup for O(n) message scanning.

### 2.2 Server-Authoritative "Normalization"
- **Sync Tick Validation:** 
  1. Client sends `/tick` with `start_timestamp`, `end_timestamp`, `reported_clicks`, and `kill_list`.
  2. Server calculates `elapsed_s`.
  3. Server validates `reported_clicks / elapsed_s <= click_rate_cap`.
  4. Server recalculates damage/gold based on stats at the *start* of the tick.
- **Smooth Correction:** Client-side UI lerps values toward the server's `normalized_state` over 500ms to handle drift without jarring snaps.

### 2.3 Registry Reveal Logic (Ranked E -> SS)
- **Visibility Mapping (Backend-Side):**
  - **Revealed:** `encounters > 0`.
  - **Grey Lines (Blurred):** `encounters == 0` AND (entity has `first_appearance_scene_id` in current/past chapter).
  - **Ether Mist (Hidden):** `encounters == 0` AND (entity has NO `first_appearance_scene_id` OR in future chapter).
- **Batching Discoveries:** The Frontend collects all "seen" item components and entities during a scene and sends a single `POST /api/game/registry/unlock-batch` upon scene completion to reduce API overhead.

## 3. API Specifications

### 3.1 Pagination & Discovery
- `GET /api/game/registry/entities?chapter_id={id}&limit=50&offset=0`
  - Returns: `{ "total": int, "entities": [ { "id": int, "status": "revealed|grey|mist", "kills": int, "encounters": int, ... } ] }`
- `POST /api/game/registry/unlock-batch` — Batch unlock for seen items/entities.
- `GET /api/game/registry/stats` — Global discovery % and counts for the Hub UI.

### 3.2 Social & Chat
- `WS /ws/chat/global` — Main WebSocket connection.
- `GET /api/game/chat/history?limit=50` — Initial load of recent messages.

### 3.3 Anti-Cheat & Flags
- `GET /api/admin/audit/discrepancies` — List players with high discrepancy scores for review.

---

## 4. Asset Remediation Workflow
1. **Pre-Scan Tool:** `tools/check_lore_completeness.py` iterates through all `entities` and `skills` to find missing descriptions/images.
2. **Runtime Audit:** If the Frontend encounters a null lore field during a Registry reveal, it hits `/api/game/audit/log-missing` to flag it for the `dev_content_audit` table.

---

## 5. UI/UX "Style Mandates"
- **Registry View:** Dark, etched-glass panels. Discovery badges appear as glowing green "Cyberpunk" pulses when hovered, then fade to static gold.
- **Normalization Warning:** Red border-pulse on the top of the screen when `CPS > Cap` occurs, with a non-blocking toast notification.
