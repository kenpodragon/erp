# REC 2.6: Economy, Anti-Cheat & Discovery

This document defines the server-authoritative validation mechanisms, social communication, and the game's discovery/onboarding systems for the Elysium Rising MMORPG.

---

## 1. Advanced Anti-Cheat & Validation

### 1.1 Server-Authoritative "Normalization"
- **Purpose:** The system is designed to **normalize** incoming data rather than penalize users. The server's "Truth" always prevails over client-side reports.
- **Real-Time Click Normalization:**
  - **CPS Cap:** Server enforces a maximum Clicks-Per-Second (CPS) rate. Configurable via `game_configs` (e.g., `click_rate_cap`).
  - **Processing:** If a client reports clicks exceeding the cap, the server only processes up to the cap.
  - **Feedback:** When normalization occurs, the player's currency/damage will "drift" until the next server sync (rubberbanding). 
  - **UI Warning:** A top-of-screen toast/banner appears: *"Excessive automated clicking detected. Max {CPS_CAP} CPS is recorded."*
- **Damage & Gold Verification:**
  - All damage dealt and gold earned is recalculated on the backend based on permanent stats + session upgrades.
  - Client-side "visual" hacks to gold or HP are ignored during the `/tick` and `/complete` syncs.

### 1.2 Administrative Behavioral Flagging
- **Serious Discrepancies:** The system tracks major inconsistencies (e.g., attempting a purchase with 30M gold when the server-held balance is 500).
- **Flag for Review:** If a player triggers **3 or more serious discrepancies** within a rolling 24-hour window, the account is flagged in the `support_tickets` or `admin_audit_log` for manual review.
- **Anomaly Detection:** Perfectly uniform click intervals are logged to `activity_events` for pattern analysis.

## 2. Social & Communication

### 2.1 Integrated Chat
- **Global Channel:** A single, persistent global chat channel for all players.
- **Persistence:** Chat history is limited to the last **X messages** (configurable). It is intended to be a "live" experience; if you weren't online, you missed it.
- **Identity:** Each message displays: `[ClassIcon] CharName [Level]`. "Level" refers to the **Character Level** (Permanent Loop C).
- **Global Milestones:** The "System" account broadcasts major achievements to the channel:
  - Chapter/Book completions.
  - Finding super-rare items (Rarity threshold set in `game_configs` e.g., `broadcast_rarity_min`).
- **Moderation:**
  - **Profanity Filter:** Server-side regex filtering against `backend/profanity_blocklist.txt`.
  - **Spam Control:** Configurable message-per-minute rate limit.

## 3. The Akashic Records (Discovery System)

### 3.1 The Monster Codex (The "Etheric Registry")
- **State-Based Visibility:**
  - **Ether Mist (Future):** Entities in future chapters are completely hidden (no name, no count, just "Mist").
  - **Grey Lines (Passed/Current):** Entities in current or passed chapters that haven't been met are shown as blurred grey lines. They count toward the chapter total (e.g., "15/45 encountered").
  - **Revealed:** Entities met at least once in Story Mode or Training.
- **Ranked Reveal (E -> SS):**
  - **Tracking:** "Encountered" and "Killed" are tracked separately in the database.
  - **Rank-Up Requirement:** Progression through ranks (E, C, A, SS) requires **Kills**.
  - **Thresholds:** Kill counts for each rank are configurable via `game_configs`.
  - **Rank Rewards:**
    - **Rank E (1 Kill):** Name, Image, and basic Lore unlocked.
    - **Rank C:** Base HP and Gold drops revealed.
    - **Rank A:** Full Stat Block (Atk, Def, etc.) revealed.
    - **Rank SS:** Hidden lore secrets and 100% completion badge.
- **Fallback Logic:** Missing lore/stats trigger a generic placeholder and log to `dev_content_audit`.

### 3.2 Skill & Item Library
- **Unlock Trigger:** **Possession**. An entry is unlocked as soon as the player acquires an item with that Prefix/Suffix/Quality/LoreTag, or unlocks a Skill.
- **UI Feedback:** "New" items are indicated with a badge. The badge is cleared simply by **hovering** over the entry in the Codex.
- **Content:** Full mechanical breakdown and narrative origin.

### 3.3 Static Gameplay Manuals
- **Frontend Static:** "How to Play" guides and FAQ are stored as static files in the frontend.
- **Contextual Help:** Small "?" icons link directly to these static manuals.

## 4. New Player Onboarding & UI

### 4.1 Account-Wide Onboarding
- **Scope:** Tracked per account via `player_progress.has_completed_onboarding`.
- **User Control:** Options to **Skip** (even on first run) or **Replay** at any time.
- **The "Starter State":** Every player starts "naked and alone" in **Book 1, Chapter 1, Scene 1** (The Copyright Pages). Skipping the tutorial does not grant free items/levels.
- **Hybrid Flow:** Narrative slides + Interactive tasks + Visual coach marks.

### 4.2 Aesthetic Mandate
- **"Magic Research 2" Polish:** Hub and Story Mode (modern, rounded, high-contrast).
- **"Cyberpunk Terminal" Exception:** Idle Training (Loop C) remains a green-on-black retro terminal.

### 4.3 Animation Toggle (Reduce Motion)
- [ ] **Settings Toggle:** Add a "Reduce Motion" toggle to the Game Settings modal (`TopBar.tsx`).
- [ ] **Battle Banner:** When enabled, hide `BottomAnimatedBanner` entirely (or replace with a static image).

- [ ] **Persistence:** Store preference in `player.settings` JSONB column (key: `reduce_motion`), synced via `PATCH /api/players/me/settings`.
- [ ] **CSS Integration:** Apply `prefers-reduced-motion` media query as baseline; toggle overrides for users who want motion on despite OS setting.
