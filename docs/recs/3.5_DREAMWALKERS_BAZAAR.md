# REC 3.5: Dreamwalker's Bazaar (Player Marketplace)

This document defines the complete requirements for the Dreamwalker's Bazaar — the player-to-player marketplace where adventurers trade artifacts and equipment for Elysium Shards, and an NPC Vendor where unwanted items can be salvaged for Essence.

**Design:** [3.5_DREAMWALKERS_BAZAAR_DESIGN.md](3.5_DREAMWALKERS_BAZAAR_DESIGN.md) | **Schema:** [3.5_DREAMWALKERS_BAZAAR_SCHEMA.md](3.5_DREAMWALKERS_BAZAAR_SCHEMA.md)
**Parent:** [3.0_ECONOMY.md](3.0_ECONOMY.md) §3.5

---

## 1. Overview & Scope

### 1.1 Purpose
Section 3.5 introduces the **Dreamwalker's Bazaar** — the endgame item economy for Elysium Rising. Players can:
- **List** artifacts and equipment for sale at a fixed Shard price (24-hour duration)
- **Browse and buy** items listed by other players
- **Salvage** unwanted items at the NPC Vendor for Essence

The marketplace uses **Shards only** as the trading currency. A **5% transaction tax** is applied to all sales (burned from the economy as a deflationary shard sink). Marketplace activity drives the long-term demand for Shards, completing the monetization loop.

### 1.2 Scope Boundaries
- **In Scope:** Listing system (24hr fixed-price, FIFO, price adjustment, cancel), buy flow (shard debit/credit with tax, item transfer), NPC Vendor salvage (Essence per rarity, bulk salvage, double-confirm for curated artifacts), listing slot expansion (shop purchasable), marketplace UI (4th shop tab), trade notifications, browse/search/filter, trade history, marketplace achievements.
- **Out of Scope:** Cosmetic trading (shop items are non-tradeable), auction/bidding system, Essence-based trading, cross-player gifting, automated price bots, historical price charts.
- **Dependencies:** Shard balance & debit/credit infrastructure (3.1), artifact system (2.7.0 — `player_artifacts`), dream item / inventory system (2.4.2 — `player_inventory`), shop item infrastructure for listing slot expansion (3.3), achievement system (2.7), notification mechanism (idle training gains UI pattern), Firebase Auth (1.0).

### 1.3 Existing Foundation
| Component | Source | Description |
|:---|:---|:---|
| `shard_balance` / `shard_transactions` | 2.7.0/046 | Shard crediting/debiting infrastructure |
| `payment_service.py` | 3.1 | `credit_shards()`, `debit_shards()` |
| `player_artifacts` | 2.7.0/046 | Player-owned artifact instances (curated + generated) |
| `player_inventory` / `inventory_items` | 2.4.2 | Dream items / equipment owned by characters |
| `shop_items` / `player_shop_items` | 3.3 | Shop item infrastructure (reused for listing slot expansion item) |
| Achievement system | 2.7 | `achievements` + `player_achievements` tables |
| Idle Training gains UI | 2.3 | Offline/away gains notification pattern (reused for trade notifications) |
| `character_stats` / `recalculate_character_stats()` | 2.4 | Stat recalculation after item transfer |

### 1.4 Currency & Tax Model
| Aspect | Detail |
|:---|:---|
| **Trading currency** | Elysium Shards only |
| **Transaction tax** | 5% of sale price, deducted from seller's proceeds (burned — removed from economy) |
| **Tax formula** | `tax = floor(price * 0.05)`, `seller_receives = price - tax` |
| **Minimum listing price** | 1 Shard |
| **Tax on 1-Shard listings** | `floor(1 * 0.05) = 0` — no tax below 20 Shards |
| **Tax destination** | Burned (permanently removed from shard economy) |
| **Salvage currency** | Elysium Essence only (NPC Vendor) |

## 2. Tradeable Items

### 2.1 What Can Be Traded
**Both** item systems are tradeable on the marketplace:

| Item System | Table | Examples | Notes |
|:---|:---|:---|:---|
| **Artifacts** | `player_artifacts` | Curated lore artifacts, generated procedural artifacts | Player-level ownership (`player_id`) |
| **Equipment (Dream Items)** | `player_inventory` / `inventory_items` | Weapons, armor, trinkets, gear | Character-level ownership (`character_id`) |

### 2.2 What Cannot Be Traded
- **Shop cosmetics** (`player_shop_items`) — skins, flair, badges, avatars, boosters
- **Patron cosmetics** — donation tier rewards
- **Titles** — earned, not transferable
- **Currencies** — Gold, Essence, Shards cannot be listed

### 2.3 Item Ownership Transfer
When an item is sold:
- **Artifacts:** `player_artifacts.player_id` and `player_artifacts.character_id` are updated to the buyer's IDs.
- **Equipment:** The `player_inventory` record's `character_id` is updated to the buyer's character. If the item was equipped, it is unequipped first (`is_equipped = false`, `equipped_slot = NULL`).
- **Stat recalculation:** `recalculate_character_stats()` is called for both seller and buyer characters after transfer.
- **Curated artifact re-earning:** If a player sells a curated artifact, they can earn it again from drops. The sale removes ownership; the drop system treats them as if they never had it.

### 2.4 Character Requirement
- Both buyer and seller must have an active character (`player_characters` record).
- If a player attempts to interact with the marketplace without a character, they are redirected to character creation.

## 3. Listing System

### 3.1 Creating a Listing
1. Player navigates to the Dreamwalker's Bazaar tab and selects "Create Listing."
2. Player selects an item from their artifact collection or equipment inventory.
3. Player sets a price in Shards (minimum: 1 Shard).
4. **Confirmation modal** shows:
   - Item name, rarity, stats
   - Listing price
   - Estimated proceeds after 5% tax: `"You will receive [X] Shards after the 5% Bazaar tax."`
   - `"This item will be removed from your inventory and listed for 24 hours."`
   - [Confirm Listing] / [Cancel]
5. On confirm:
   - Item is **removed from the seller's active inventory** (cannot be used/equipped while listed).
   - For artifacts: a flag or marketplace record marks the artifact as listed.
   - For equipment: `player_inventory` record is flagged as listed (not visible in player's gear).
   - Listing record created with `expires_at = NOW() + 24 hours`.

### 3.2 Listing Duration & Expiry
- **Fixed 24-hour duration.** All listings have an `expires_at` timestamp set to `NOW() + 24 hours` (UTC).
- **Lazy expiry evaluation:** No cron job or background task. Expired listings are detected at query time:
  - Browse/search queries filter out listings where `expires_at < NOW()`.
  - When an expired listing is accessed (by seller viewing "My Listings" or any API call referencing it), it is marked `status = 'expired'` and the item is returned to the seller's inventory.
- On expiry, if unsold:
  - Item is automatically returned to the seller's inventory.
  - A notification is generated: `"Your listing for [ItemName] has expired. The item has been returned to your inventory."`
- **No auto-relist.** Player must manually re-list.

### 3.3 Listing Slot Cap
Players have a **base limit of 3 concurrent listings.** This cap can be expanded by purchasing a **"Bazaar Permit"** from the Elysium Emporium (3.3 shop).

| Slot | Unlock Cost (Shards) | Cumulative Spent |
|:---|:---|:---|
| Slots 1–3 | Free (default) | 0 |
| Slot 4 | 200 | 200 |
| Slot 5 | 400 | 600 |
| Slot 6 | 800 | 1,400 |
| Slot 7 | 1,600 | 3,000 |
| Slot 8 | 3,200 | 6,200 |
| Slot 9 | 6,400 | 12,600 |
| Slot 10 | 12,800 | 25,400 |

- **Hard cap: 10 listing slots.**
- Each Bazaar Permit is a separate `shop_items` entry with `category = 'marketplace_permit'`.
- Permits are **infinitely purchasable** (not one-time) — each purchase unlocks the next slot tier.
- The next permit price is calculated based on the player's `marketplace_slots_purchased` count (tracked on the `players` table).
- On purchase: `players.marketplace_slots_purchased += 1`. Max listing cap = `3 + marketplace_slots_purchased`.
- Purchased permits are **permanent** — slots do not expire or reset.

### 3.4 Price Adjustment
- Sellers can adjust the price of an active listing **at any time** (up or down).
- Minimum price: 1 Shard. No maximum price.
- Price changes do not reset the 24-hour timer.
- Price changes are logged in `marketplace_price_history` for transparency.

### 3.5 Cancel Listing
- Sellers can manually cancel an active listing at any time.
- On cancellation, the item is immediately returned to the seller's inventory.
- No penalty or cooldown for cancellation.

### 3.6 Listing While Item Is Equipped
- If a player attempts to list an **equipped** item (equipment only — artifacts are not "equipped" in the same sense):
  - The item is **automatically unequipped** before listing.
  - The confirmation modal warns: `"This item is currently equipped. Listing it will unequip it from your character."`
  - `recalculate_character_stats()` is called for the seller's character after unequip.

## 4. Buy Flow

### 4.1 Browsing & Searching
The marketplace provides:

| Filter | Options |
|:---|:---|
| **Item Type** | Artifact (Curated), Artifact (Generated), Equipment |
| **Rarity** | Common, Uncommon, Rare, Epic, Legendary |
| **Stat Bonuses** | Filter by stat type (STR, AGI, INT, CRIT, etc.) |
| **Gear Slot** | Head, Chest, Main Hand, Off Hand, Trinket, etc. (equipment only) |
| **Price Range** | Min–Max Shard price |
| **Search** | Free-text search by item name |

| Sort | Options |
|:---|:---|
| Price (Low → High) | Default |
| Price (High → Low) | |
| Rarity (Highest first) | |
| Recently Listed | |

### 4.2 Price Transparency
Each listing displays:
- The listing price
- **Current lowest price** for the same item type/name (if other listings exist)
- **Current highest price** for the same item type/name (if other listings exist)
- For curated artifacts: "X currently listed" count

### 4.3 FIFO Ordering
When multiple listings exist for the same item at the same price, **the earliest listing appears first** in search results and is prioritized for display. The marketplace sorts by price first, then by listing time (oldest first) within the same price.

### 4.4 Purchase Flow
1. Buyer browses/searches and selects a listing.
2. **Purchase confirmation modal** shows:
   - Item name, rarity, stats, seller alias
   - Price in Shards
   - Current shard balance and balance after purchase
   - `"All marketplace sales are final."`
   - [Confirm Purchase] / [Cancel]
3. On confirm, backend validates:
   - Buyer is authenticated and has a character.
   - Listing exists and is still active (not expired, not cancelled, not already sold).
   - Buyer is **not** the seller (self-purchase blocked).
   - Buyer has sufficient shard balance (≥ 0 after debit).
   - Buyer's account is not flagged (`account_flag != 'dispute'`).
4. **Atomic transaction:**
   a. Debit buyer: `debit_shards(buyer_id, price, 'marketplace_purchase', listing_id)`
   b. Calculate tax: `tax = floor(price * tax_rate)`
   c. Credit seller: `credit_shards(seller_id, price - tax, 'marketplace_sale', listing_id)`
   d. Mark listing as `status = 'sold'`.
   e. Create `marketplace_trade` record for both parties.
   f. `recalculate_character_stats()` for seller character (item removed from their loadout).
   g. Generate seller notification: `"Your [ItemName] sold for [price] Shards! You received [price - tax] Shards after the 5% Bazaar tax."`
   h. Evaluate marketplace achievements for both buyer and seller.
   i. **Item claim:** Transfer item to buyer using the claim queue (see §4.8).
5. Return success with updated balance and item details.

### 4.8 Inventory Cap & Claim Queue
The existing inventory system enforces a **10-item non-equipped cap** per character (`trg_enforce_inventory_slot_cap`). When a buyer purchases an item:

**For equipment (dream items):**
- If the buyer's character has **room** in inventory (< 10 non-equipped items): the item is transferred directly (`player_inventory.character_id` updated to buyer's character). `recalculate_character_stats()` is NOT called until the buyer equips it.
- If the buyer's character is **at cap** (10 non-equipped items): the item enters a **claim queue**. The buyer sees a claim modal (same pattern as post-battle loot pickups in Story Mode):
  - `"Your inventory is full! Choose how to claim your purchased item."`
  - Options: **Replace** an existing inventory item (swap — old item is destroyed), or **Discard** the purchased item (confirm with warning).
  - The claim must be resolved before the buyer can make another marketplace purchase.

**For artifacts:**
- Artifacts are stored in `player_artifacts` which has **no cap**. Transfer is always immediate (`player_id`/`character_id` updated). No claim queue needed.

**Claim queue behavior:**
- Pending claims are stored with `claim_status = 'pending'` on the trade record.
- The claim modal appears on the buyer's next UI interaction (same pattern as idle training gains / trade notifications overlay).
- If a buyer logs out with a pending claim, the modal appears on next login.
- Claims do not expire — the item is held until the buyer resolves it.

### 4.5 Self-Purchase Prevention
- A player cannot buy their own listing. The API returns 400: `"You cannot purchase your own listing."`
- The UI hides the "Buy" button on the player's own listings and shows "Your Listing" instead.

### 4.6 Insufficient Balance
- If the buyer's shard balance is less than the listing price, the buy button is disabled.
- Message: `"Not enough Shards. You need X more."` with a [Buy Shards] link.

### 4.7 All Sales Final
- **Marketplace sales are final.** No player-initiated refunds for marketplace trades.
- Admin can manually reverse a trade if needed (via admin endpoints — see §10).

## 5. NPC Vendor (Salvage System)

### 5.1 Overview
The NPC Vendor allows players to permanently destroy items in exchange for **Elysium Essence**. This provides a floor value for all items and a way to clean up inventory bloat.

### 5.2 Equipment Salvage Rates
Base Essence rates for dream items / equipment (by rarity):

| Rarity | Base Essence |
|:---|:---|
| Common | 5 |
| Uncommon | 15 |
| Rare | 50 |
| Epic | 150 |
| Legendary | 500 |

> **Note:** Equipment uses `inventory_items.rarity` (VARCHAR, unconstrained). Artifacts use a CHECK constraint with values: `common`, `uncommon`, `rare`, `epic`, `cosmic`. "Cosmic" is the artifact equivalent of "Legendary."

### 5.3 Artifact Salvage Rates
Artifacts return **2x the base equipment rate** due to their rarity and significance:

| Rarity | Base Essence (Artifact) |
|:---|:---|
| Common | 10 |
| Uncommon | 30 |
| Rare | 100 |
| Epic | 300 |
| Cosmic | 1,000 |

### 5.4 Curated Artifact Bonus
Curated (lore) artifacts receive an additional **15% bonus** on top of the artifact rate:

| Rarity | Curated Essence |
|:---|:---|
| Common | 12 (ceil(10 × 1.15)) |
| Uncommon | 35 (ceil(30 × 1.15)) |
| Rare | 115 (ceil(100 × 1.15)) |
| Epic | 345 (ceil(300 × 1.15)) |
| Cosmic | 1,150 (ceil(1000 × 1.15)) |

### 5.5 Configuration
**All salvage rates are admin-configurable** via `game_configs`:
- Equipment base rates per rarity
- Artifact multiplier (default: 2.0)
- Curated artifact bonus multiplier (default: 1.15)

### 5.6 Salvage Flow (Single Item)
1. Player navigates to the NPC Vendor section within the Dreamwalker's Bazaar tab.
2. Player selects an item from their inventory/artifacts.
3. **Confirmation modal** shows:
   - Item name, rarity, stats
   - Essence return amount
   - `"This item will be permanently destroyed. This action cannot be undone."`
   - [Salvage] / [Cancel]
4. **For curated artifacts, double-confirmation:**
   - First modal: `"Are you sure? This is a unique lore artifact — [ArtifactName]."`
   - Second modal: `"This action is irreversible. You will receive [X] Essence. Confirm destruction?"`
5. On confirm:
   - Item is permanently deleted from the database.
   - Essence is credited to the player's balance.
   - `recalculate_character_stats()` if the item contributed stats.
   - Activity logged.

### 5.7 Salvage Flow (Bulk)
Players can salvage multiple items at once:
1. Player enters "Bulk Salvage" mode in the NPC Vendor.
2. Items are displayed in a grid with **checkboxes** for selection.
3. **Quick-select buttons:**
   - "Select All [Rarity]" (e.g., "Select All Common")
   - "Select All Equipment" / "Select All Artifacts"
   - "Select None" (deselect all)
4. Curated artifacts are **excluded from quick-select** — they must be individually checked to prevent accidental destruction.
5. A running total shows: `"Selected: X items → Y Essence"`
6. On confirm: single confirmation modal (unless curated artifacts are included, which trigger the double-confirm per curated item).
7. All selected items are destroyed in a single atomic transaction.

### 5.8 Salvage of Equipped Items
- Players **can** salvage equipped items directly.
- The item is automatically unequipped before destruction.
- The confirmation modal warns: `"This item is currently equipped. Salvaging will unequip and destroy it."`
- `recalculate_character_stats()` is called after.

### 5.9 Salvage of Listed Items
- Items currently listed on the marketplace **cannot be salvaged** until the listing is cancelled or expires.
- These items appear greyed out in the NPC Vendor with a tooltip: `"Currently listed on the Bazaar."`

## 6. Trade Notifications

### 6.1 Notification Mechanism
Trade notifications piggyback on the existing **idle training gains** UI pattern (the notification that appears when returning to the game after idle XP/Essence gains).

### 6.2 Notification Events
| Event | Message |
|:---|:---|
| Item sold | `"Your [ItemName] sold for [price] Shards! You received [proceeds] Shards after the 5% Bazaar tax."` |
| Listing expired | `"Your listing for [ItemName] has expired. The item has been returned to your inventory."` |
| Listing cancelled (by admin) | `"Your listing for [ItemName] was removed by a moderator. The item has been returned to your inventory."` |

### 6.3 Notification Delivery
- Notifications are stored in a `marketplace_notifications` table.
- On login or return from idle, the client fetches unread marketplace notifications alongside idle gains.
- Notifications are displayed in the same overlay/modal pattern as idle gains.
- After viewing, notifications are marked as read.
- Notifications older than 30 days are automatically purged (server-side cleanup).

## 7. Trade History

### 7.1 Player Trade History
Each player can view their full marketplace trade history from the Bazaar tab:

| Column | Description |
|:---|:---|
| Date | Transaction timestamp |
| Type | "Sold" / "Purchased" |
| Item | Item name + rarity badge |
| Price | Shard amount |
| Tax | Tax deducted (for sales) or "—" (for purchases) |
| Counterparty | Buyer/Seller alias |

- Paginated (20 per page).
- Filterable by type (sales/purchases), date range.

### 7.2 Listing History
Sellers can also see their listing history (including expired/cancelled listings) with status indicators:
- **Sold** — item was purchased
- **Expired** — 24hr timer ran out, item returned
- **Cancelled** — seller manually cancelled
- **Active** — currently listed

## 11. Anti-Manipulation & Safety

### 11.1 Self-Purchase Prevention
- Backend enforces: `buyer_id != seller_id`. Returns 400 on violation.
- UI hides Buy button on own listings.

### 11.2 Account Restrictions
Accounts with `account_flag = 'dispute'`:
- **Cannot create listings** (blocked at API level).
- **Cannot purchase items** (blocked at API level).
- **Can browse** the marketplace (read-only access).
- **Can salvage** items at NPC Vendor (no shard involvement).
- Error message: `"Your account is under review due to a payment dispute. Marketplace trading is temporarily disabled."`

### 11.3 Alt Account Detection
- Flag accounts sharing **Stripe payment methods** (via `stripe_customer_id` cross-reference).
- Flagged pairs are logged to `activity_events` with type `marketplace_alt_warning`.
- No automatic blocking — admin reviews flags manually.

### 11.4 Minimum Price Floor
- All listings must be ≥ 1 Shard.
- No negative or zero-price listings.

### 11.5 No Trade Cooldown
- Buyers can immediately re-list purchased items.
- No cooldown on listing after purchase.

## 12. Security Requirements

### 12.1 API Authentication
- All `/api/marketplace/*` endpoints require Firebase JWT authentication.
- Players can only list their own items and buy for themselves.

### 12.2 Server-Side Validation
- All prices, balance checks, ownership verification, listing cap enforcement, and tax calculations are server-side.
- The client displays data but the server is the source of truth.
- Item ownership is verified before listing and before transfer.

### 12.3 Atomic Transactions
- Buy flow uses database-level row locking to prevent race conditions (double-buy).
- Listing status is checked within the same transaction as the purchase.
- Shard debit + credit + item transfer all occur atomically.

### 12.4 Rate Limiting
- `POST /api/marketplace/list`: Max 10 requests per player per minute.
- `POST /api/marketplace/buy`: Max 10 requests per player per minute.
- `GET /api/marketplace/browse`: Max 30 requests per player per minute.
- `POST /api/marketplace/salvage`: Max 10 requests per player per minute.

### 12.5 Admin Endpoints
- All `/api/admin/marketplace/*` endpoints require admin JWT auth.
- Admin actions logged to `activity_events`.

## 13. Error Handling & Edge Cases

### 13.1 Listing Cap Reached
- Returns 400: `"You have reached your listing cap (X/X). Cancel an existing listing or purchase a Bazaar Permit to expand."`

### 13.2 Item Already Listed
- Returns 400: `"This item is already listed on the marketplace."`

### 13.3 Item No Longer Owned
- Returns 400: `"You no longer own this item."` (race condition guard)

### 13.4 Listing Already Sold/Expired
- Returns 410: `"This listing is no longer available."` (shown when buyer clicks Buy on a just-sold item)

### 13.5 Negative Shard Balance
- Players with negative shard balance cannot buy items on the marketplace.
- Players with negative shard balance CAN list items for sale (they need to earn shards).

### 13.6 Concurrent Purchase Race
- Row-level locking on the listing record prevents two buyers from purchasing the same item.
- The losing buyer receives: `"This item was just purchased by another player."`

### 13.7 Salvage During Active Listing
- Items currently listed cannot be salvaged. Returns 400: `"This item is currently listed on the marketplace."`

### 13.8 Item Level / Stat Requirements
- The marketplace does **not** enforce buyer level/stat requirements at purchase time. The buyer receives the item regardless. They may not be able to equip it until they meet the requirements, but they own it.

### 13.9 Inventory Full on Purchase
- If the buyer's equipment inventory is at cap (10 non-equipped items), the item enters the claim queue (§4.8).
- The buyer must resolve the claim (replace an existing item or discard) before making another purchase.
- Attempting to buy while a claim is pending returns 400: `"You have a pending item claim. Resolve it before purchasing again."`

### 13.10 Listing Expiry During Browse
- A buyer viewing a listing that has expired between page load and purchase attempt receives 410: `"This listing has expired."`
- Browse results exclude listings where `expires_at < NOW()` at query time (lazy expiry).

## 16. Design Decisions (Resolved)

| # | Decision | Resolution |
|:---|:---|:---|
| 1 | Tab name | "Dreamwalker's Bazaar" — lore-themed marketplace name. Fourth tab in Shop. |
| 2 | Tradeable items | Both artifacts (`player_artifacts`) and equipment (`player_inventory`). No cosmetics, no currencies. |
| 3 | Trading currency | Shards only. No Essence trading. |
| 4 | Transaction tax | 5% of sale price, deducted from seller proceeds, burned (removed from economy). |
| 5 | Tax formula | `tax = floor(price * 0.05)`. Seller receives `price - tax`. Buyer pays full price. |
| 6 | Listing duration | Fixed 24 hours. No auto-relist. Expired items returned to seller. |
| 7 | Listing cap | Base 3 slots. Expandable to 10 via "Bazaar Permit" shop items (scaled pricing: 200→12,800 doubling). |
| 8 | Price adjustment | Allowed at any time. Min 1 Shard. No max. Doesn't reset timer. |
| 9 | Cancel listing | Allowed at any time. No penalty or cooldown. |
| 10 | FIFO ordering | Same-price listings: earliest listed appears/sells first. |
| 11 | Self-purchase | Blocked. API returns 400. UI hides Buy button on own listings. |
| 12 | Price transparency | Current min/max for same item type. No historical price data. |
| 13 | Trade cooldown | None. Buyers can immediately re-list purchased items. |
| 14 | Account disputes | Flagged accounts blocked from listing and buying. Can browse and salvage. |
| 15 | Alt detection | Stripe payment method overlap flagging. Admin manual review. No auto-blocking. |
| 16 | Curated artifact re-earning | Selling a curated artifact allows the player to earn it again from drops. |
| 17 | Equipment salvage rates | 5/15/50/150/500 Essence (Common→Legendary). Admin-configurable. |
| 18 | Artifact salvage rates | 2x equipment rates. Admin-configurable multiplier. |
| 19 | Curated artifact salvage bonus | 15% bonus on top of artifact rate. Double-confirmation required. |
| 20 | Bulk salvage | Supported. Checkboxes + rarity quick-select. Curated artifacts excluded from quick-select. |
| 21 | Equipped item salvage | Allowed. Auto-unequip before destruction. |
| 22 | Trade notifications | Piggyback on idle training gains UI pattern. Stored in `marketplace_notifications`. |
| 23 | Achievements | 9 marketplace achievements covering listing, sales, purchases, salvage, and value milestones. |
| 24 | Chat broadcasts | No marketplace broadcasts. Trades are private. |
| 25 | Character requirement | Both buyer and seller must have a character. Redirected to creation if missing. |
| 26 | Item level requirements | Not enforced at purchase. Buyer owns the item but may not be able to equip it. |
| 27 | Listing fees | None. No cost to list. |
| 28 | Inventory cap on purchase | Equipment purchases use a claim queue when buyer is at 10-item cap (same pattern as post-battle loot). Artifacts have no cap. |
| 29 | Listing expiry mechanism | Lazy evaluation — no cron job. `expires_at` UTC timestamp checked at query time. Expired listings filtered from browse and resolved on access. |
| 30 | Bazaar Permit tracking | `marketplace_slots_purchased` counter on `players` table. Max cap = 3 + counter. |
