## Pre-Existing Tables (Extended)

### `players` — New Columns

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `stripe_customer_id` | `VARCHAR(255)` | `DEFAULT NULL UNIQUE` | Stripe Customer ID (e.g., `cus_...`). Created on first purchase attempt. |
| `first_purchase_claimed` | `BOOLEAN` | `NOT NULL DEFAULT FALSE` | Whether the 2x first-purchase bonus has been used. Permanently consumed — NOT reset on refund. |
| `account_flag` | `VARCHAR(30)` | `DEFAULT NULL` | Flag for account issues (e.g., `'dispute'`, `'fraud_review'`). NULL = clean. When `'dispute'`, all new purchases are blocked until resolved. |

**Index:**
- `idx_players_stripe_customer` ON `(stripe_customer_id)` WHERE `stripe_customer_id IS NOT NULL`

### `shard_transactions` — No Schema Changes

The existing `shard_transactions` table (migration 046) already supports the required fields:
- `source_type` will use new values: `'purchase'`, `'refund'`, `'dispute'`, `'dispute_reversal'`
- `source_id` will reference `payment_orders.id` for purchase/refund transactions
- No structural changes needed.

### `player_meta_progression` — No Schema Changes

The existing `shard_balance` field on `player_meta_progression` (migration 046) is used as-is. Balance can go negative after refunds/disputes.

## New Tables

### `shard_packages`

Defines the purchasable shard tiers. Admin-configurable via the admin panel (3.6).

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `tier_key` | `VARCHAR(30)` | `NOT NULL UNIQUE` | Machine-readable key (e.g., `'starter'`, `'ultimate'`) |
| `name` | `VARCHAR(100)` | `NOT NULL` | Display name (e.g., "Starter Pack") |
| `description` | `VARCHAR(255)` | `DEFAULT NULL` | Optional marketing description |
| `price_cents` | `INTEGER` | `NOT NULL CHECK (price_cents > 0)` | Price in USD cents (e.g., 99 = $0.99) |
| `base_shards` | `INTEGER` | `NOT NULL CHECK (base_shards > 0)` | Base shard amount before bonus |
| `bonus_pct` | `INTEGER` | `NOT NULL DEFAULT 0 CHECK (bonus_pct >= 0 AND bonus_pct <= 100)` | Volume bonus percentage |
| `total_shards` | `INTEGER` | `NOT NULL CHECK (total_shards > 0)` | Pre-calculated: `base_shards * (1 + bonus_pct/100)` |
| `sort_order` | `INTEGER` | `NOT NULL DEFAULT 0` | Display ordering |
| `is_active` | `BOOLEAN` | `NOT NULL DEFAULT TRUE` | Soft-disable without deletion |
| `is_best_value` | `BOOLEAN` | `NOT NULL DEFAULT FALSE` | Show "Best Value" badge in UI |
| `max_purchases_per_player` | `INTEGER` | `DEFAULT NULL CHECK (max_purchases_per_player IS NULL OR max_purchases_per_player > 0)` | Per-player purchase cap. NULL = unlimited. |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | |

**Indexes:**
- `idx_shard_packages_active` ON `(is_active, sort_order)` WHERE `is_active = TRUE`

**Trigger:** `trg_shard_packages_updated_at` — auto-sets `updated_at` on UPDATE.

### `payment_orders`

Tracks each purchase attempt from initiation through completion/failure. One row per Stripe Checkout Session.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `player_id` | `INTEGER` | `NOT NULL FK players ON DELETE CASCADE` | Purchasing player |
| `package_id` | `INTEGER` | `NOT NULL FK shard_packages ON DELETE RESTRICT` | Package being purchased |
| `status` | `VARCHAR(20)` | `NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'completed', 'expired', 'refunded', 'disputed'))` | Order lifecycle state (see **Partial Refund Note** below) |
| `stripe_checkout_session_id` | `VARCHAR(255)` | `UNIQUE` | Stripe Checkout Session ID (`cs_...`) — idempotency key |
| `stripe_payment_intent_id` | `VARCHAR(255)` | `DEFAULT NULL` | Stripe PaymentIntent ID (`pi_...`) — set on completion |
| `stripe_charge_id` | `VARCHAR(255)` | `DEFAULT NULL` | Stripe Charge ID (`ch_...`) — for refund lookups |
| `idempotency_key` | `UUID` | `NOT NULL UNIQUE` | Server-generated UUID for this order |
| `price_cents` | `INTEGER` | `NOT NULL` | Price at time of purchase (snapshot, in case package price changes later) |
| `shards_credited` | `INTEGER` | `DEFAULT 0` | Total shards credited (including first-purchase bonus) |
| `shards_refunded` | `INTEGER` | `DEFAULT 0` | Total shards debited via refunds |
| `is_first_purchase` | `BOOLEAN` | `NOT NULL DEFAULT FALSE` | Whether this order triggered the first-purchase bonus |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Order creation time |
| `completed_at` | `TIMESTAMPTZ` | `DEFAULT NULL` | When shards were credited |
| `refunded_at` | `TIMESTAMPTZ` | `DEFAULT NULL` | When refund was processed |
| `expired_at` | `TIMESTAMPTZ` | `DEFAULT NULL` | When checkout session expired |

**Indexes:**
- `idx_payment_orders_player` ON `(player_id, created_at DESC)`
- `idx_payment_orders_status` ON `(status)` WHERE `status = 'pending'`
- `idx_payment_orders_stripe_pi` ON `(stripe_payment_intent_id)` WHERE `stripe_payment_intent_id IS NOT NULL`
- `idx_payment_orders_stripe_charge` ON `(stripe_charge_id)` WHERE `stripe_charge_id IS NOT NULL`
- `idx_payment_orders_player_package` ON `(player_id, package_id)` WHERE `status = 'completed'` — for purchase cap enforcement

**Trigger:** `trg_payment_orders_updated_at` — not needed (individual timestamp columns used instead).

**Partial Refund Note:**
- During a **partial refund**, `status` remains `'completed'` while `shards_refunded` is incremented by the proportional amount.
- `status` flips to `'refunded'` only when `shards_refunded >= shards_credited` (i.e., fully refunded).
- `refunded_at` is set on the **first** refund event and is not overwritten by subsequent partial refunds.
- Formula: `refund_shards = floor(shards_credited × refund_cents / price_cents)`.

### `stripe_webhook_events`

Raw log of all Stripe webhook events for debugging and deduplication.

| Column | Type | Constraints | Description |
|:---|:---|:---|:---|
| `id` | `SERIAL` | `PRIMARY KEY` | |
| `stripe_event_id` | `VARCHAR(255)` | `NOT NULL UNIQUE` | Stripe event ID (`evt_...`) — used for deduplication |
| `event_type` | `VARCHAR(100)` | `NOT NULL` | Stripe event type (e.g., `checkout.session.completed`) |
| `payload` | `JSONB` | `NOT NULL` | Full event payload from Stripe |
| `processed` | `BOOLEAN` | `NOT NULL DEFAULT FALSE` | Whether this event has been handled |
| `processing_error` | `TEXT` | `DEFAULT NULL` | Error message if processing failed |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | When the event was received |
| `processed_at` | `TIMESTAMPTZ` | `DEFAULT NULL` | When processing completed |

**Indexes:**
- `idx_stripe_events_type` ON `(event_type, created_at DESC)`
- `idx_stripe_events_unprocessed` ON `(processed)` WHERE `processed = FALSE`

```
  ├── first_purchase_claimed (BOOLEAN)
  ├── account_flag (VARCHAR, nullable)
  │
  ├──< payment_orders (player_id FK)
  │       ├── package_id FK → shard_packages
  │       ├── stripe_checkout_session_id (unique)
  │       └── stripe_payment_intent_id
  │
  ├──< shard_transactions (player_id FK)  [existing table, no changes]
  │       └── source_id → payment_orders.id (for purchase/refund types)
  │
  └── player_meta_progression
        └── shard_balance (existing, allows negative)

shard_packages (standalone reference table)
stripe_webhook_events (standalone log table)
```
