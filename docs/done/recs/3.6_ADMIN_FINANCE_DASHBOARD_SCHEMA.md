## 1. Migration 054 — Overview

Migration 054 is lightweight. The Admin Finance Dashboard is primarily a UI and analytics layer on top of existing tables (3.1–3.5). The only new schema additions are:

**New Tables (1):**
- `admin_shard_adjustments` — Audit log of manual admin shard grants/debits (supplements `shard_transactions` with admin-specific metadata)

**Seed Data:**
- 5 `game_configs` keys for marketplace anomaly detection thresholds

**No ALTER TABLE changes.** All existing tables already have the fields needed for analytics queries.

## 2. New Table: `admin_shard_adjustments`

Dedicated audit trail for admin-initiated shard adjustments. While `shard_transactions` already records these with `source_type = 'admin_grant'` or `'admin_deduct'`, this table captures the admin context (who, why, player impact) in a structured, queryable format.

```sql
CREATE TABLE admin_shard_adjustments (
    id              SERIAL PRIMARY KEY,
    player_id       INTEGER NOT NULL REFERENCES players(id) ON DELETE CASCADE,
    admin_email     VARCHAR(255) NOT NULL,
    adjust_type     VARCHAR(10) NOT NULL,  -- 'grant' | 'debit'
    amount          INTEGER NOT NULL CHECK (amount > 0),
    reason          TEXT NOT NULL,
    balance_before  BIGINT NOT NULL,
    balance_after   BIGINT NOT NULL,
    shard_txn_id    INTEGER REFERENCES shard_transactions(id) ON DELETE SET NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT admin_shard_adjustments_type_check
        CHECK (adjust_type IN ('grant', 'debit'))
);

CREATE INDEX idx_asa_player ON admin_shard_adjustments(player_id);
CREATE INDEX idx_asa_admin ON admin_shard_adjustments(admin_email);
CREATE INDEX idx_asa_created ON admin_shard_adjustments(created_at DESC);
```

**Column notes:**
- `admin_email`: The authenticated admin's email from JWT. Matches audit log pattern.
- `amount`: Always positive. The `adjust_type` indicates direction.
- `balance_before` / `balance_after`: Snapshot of the player's shard balance at time of adjustment. Enables quick auditing without joining `shard_transactions`.
- `shard_txn_id`: FK to the corresponding `shard_transactions` record (with `source_type = 'admin_grant'` or `'admin_deduct'`). Links the admin action to the financial record.
- `reason`: Required non-empty text explaining the adjustment (support case, promotion, correction, etc.).

**Why a separate table?**
`shard_transactions` is the financial ledger — it tracks every shard movement. `admin_shard_adjustments` is the operational audit log — it captures *who* made the decision, *why*, and the player impact. This separation keeps the financial ledger clean while providing rich admin accountability.

## 3. Seed Data: `game_configs` — Anomaly Detection Thresholds

```sql
INSERT INTO game_configs (key, value_json, category, description) VALUES
('anomaly_price_multiplier_threshold',    '"10"',    'marketplace_anomaly', 'Flag listings priced at > Nx the 30-day average for same item name/rarity'),
('anomaly_rapid_relist_count',            '"5"',     'marketplace_anomaly', 'Flag sellers who list the same item type more than N times in the relist window'),
('anomaly_rapid_relist_window_minutes',   '"60"',    'marketplace_anomaly', 'Time window (minutes) for rapid relist detection'),
('anomaly_wash_trade_count',              '"3"',     'marketplace_anomaly', 'Flag pairs of players trading back and forth more than N times in the wash trade window'),
('anomaly_wash_trade_window_hours',       '"24"',    'marketplace_anomaly', 'Time window (hours) for wash trade detection');
```

**Category:** `marketplace_anomaly` — new category for these config keys, keeping them grouped and distinguishable from the existing `marketplace` and `salvage` categories.

## 4. Complete Schema Diagram

```
admin_shard_adjustments (NEW)
├── id (PK, SERIAL)
├── player_id → players(id)
├── admin_email (VARCHAR 255)
├── adjust_type: 'grant' | 'debit'
├── amount (INTEGER, > 0)
├── reason (TEXT)
├── balance_before (BIGINT)
├── balance_after (BIGINT)
├── shard_txn_id → shard_transactions(id) [nullable]
└── created_at (TIMESTAMPTZ)

game_configs (SEED — 5 new keys)
├── anomaly_price_multiplier_threshold    (default: 10)
├── anomaly_rapid_relist_count            (default: 5)
├── anomaly_rapid_relist_window_minutes   (default: 60)
├── anomaly_wash_trade_count              (default: 3)
└── anomaly_wash_trade_window_hours       (default: 24)
```

## 5. Existing Tables Used (Read-Only Analytics)

The finance dashboard analytics service reads from these existing tables but does **not** modify their schema:

| Table | Analytics Purpose |
|:---|:---|
| `payment_orders` | Revenue totals, transaction log, refund tracking |
| `donations` | Donation analytics, patron tier distribution, donor identification (joins `payment_orders` via `payment_order_id`) |
| `shard_transactions` | Shard economy metrics, flow charts, balance integrity |
| `player_meta_progression` | Shard circulation (aggregated `shard_balance`) |
| `player_subscriptions` | Subscriber counts, plan splits, churn calculations |
| `players` | `cumulative_subscription_months`, `account_flag`, `patron_tier`, `display_name`, `email` |
| `marketplace_trades` | Trade volume, tax burned, anomaly detection |
| `marketplace_listings` | Active listing counts, price anomaly detection |
| `player_shop_items` | Shop purchase analytics |
| `shop_items` | Category revenue breakdown, top sellers |
| `player_active_boosters` | Active booster count |
| `stripe_webhook_events` | Webhook event viewer |
| `activity_events` | Dispute/anomaly event history, admin action logging |

## 6. Data Types Cross-Reference

| New Column | Type | Matches |
|:---|:---|:---|
| `admin_shard_adjustments.player_id` | INTEGER FK players(id) | All existing FKs to players |
| `admin_shard_adjustments.amount` | INTEGER CHECK > 0 | `marketplace_listings.price_shards` pattern |
| `admin_shard_adjustments.balance_before/after` | BIGINT | `shard_transactions.balance_after` BIGINT |
| `admin_shard_adjustments.shard_txn_id` | INTEGER FK shard_transactions(id) | Standard FK pattern |
| `admin_shard_adjustments.admin_email` | VARCHAR(255) | Matches audit log email fields |
| `admin_shard_adjustments.created_at` | TIMESTAMPTZ | Matches all existing tables |
| `game_configs.value_json` | JSONB (existing) | String values JSON-encoded (`'"10"'`) |
