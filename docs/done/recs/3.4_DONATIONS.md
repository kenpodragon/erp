# REC 3.4: Donations (One-Time Support)

This document defines the complete requirements, design, and schema for the Donations system — a heartfelt way for players to support the development of Elysium Rising.

**Parent:** [3.0_ECONOMY.md](3.0_ECONOMY.md) §3.4

---

## 1. Overview & Scope

### 1.1 Purpose
Section 3.4 adds a voluntary donation flow accessible from a new "Support Us" tab in the Shop. Donations are **purely altruistic** — donors receive **no shards, no gameplay advantages, and no premium currency.** The only rewards are cosmetic recognition through the **Patron tier system** (badges, titles, chat flair, and an exclusive avatar) and a single achievement.

The tone is warm and community-focused: thanking supporters, explaining how donations help continue development, and highlighting other ways to support the project (audiobooks, book purchases, gifting).

### 1.2 Scope Boundaries
- **In Scope:** Stripe donation checkout, fixed tiers + custom amounts, Patron tier system (4 tiers + Diamond stars), patron cosmetics (badges, titles, flair, avatar), donor leaderboard, "Support Us" tab UI, achievement, opt-in/opt-out visibility, admin endpoints.
- **Out of Scope:** Recurring donation subscriptions (use 3.2 for subscriptions), shard rewards for donations, tax receipts/501(c)(3) compliance (not a registered charity), gifting donations on behalf of another player.
- **Dependencies:** Stripe infrastructure (3.1), cosmetic equip system (3.3 `player_shop_items` / equip slots on `players`), achievement system (2.7), title system (2.7), Firebase Auth (1.0).

### 1.3 Existing Foundation
| Component | Source | Description |
|:---|:---|:---|
| Stripe Checkout Sessions | 3.1 | One-time payment flow via `payment_orders` |
| `shard_transactions` | 2.7.0 | Audit trail (used here for donation logging with `source_type = 'donation'`) |
| `payment_orders` | 3.1 | Stripe session tracking with `order_type` field |
| Cosmetic equip slots | 3.3 | `equipped_flair_id`, `equipped_badge_id`, `equipped_avatar_id` on `players` |
| `shop_items` catalog | 3.3 | Patron cosmetics are added as shop items with `category = 'patron_*'` |
| Achievement system | 2.7 | `achievements` + `player_achievements` tables |
| Title system | 2.7 | `titles` + `player_titles` tables |

## 2. Donation Flow

### 2.1 Fixed Tiers
Six quick-select donation amounts:

| Tier | Amount |
|:---|:---|
| Tier 1 | $1 |
| Tier 2 | $5 |
| Tier 3 | $10 |
| Tier 4 | $25 |
| Tier 5 | $50 |
| Tier 6 | $100 |

### 2.2 Custom Amount
- A free-form input field allows any custom donation amount.
- **Minimum:** $1.00
- **Maximum:** Uncapped (no upper limit).
- Validated client-side and server-side. Stripe handles the actual charge.

### 2.3 Stripe Checkout
Donations use the same Stripe Checkout Session flow as shard purchases (3.1), with key differences:
- `order_type = 'donation'` on the `payment_orders` record.
- **No shard crediting.** The webhook handler skips shard credit for donation orders.
- A `shard_transactions` entry is still logged with `source_type = 'donation'` and `amount = 0` for audit trail consistency.
- The donation amount (in cents) is stored on the `payment_orders` record.
- On successful payment, the player's `donations` record is created/updated (cumulative total incremented).

### 2.4 Post-Donation
After a successful donation:
1. Player's cumulative donation total is updated.
2. Patron tier is recalculated (automatic promotion if threshold crossed).
3. If a new tier is reached: cosmetic rewards are granted, achievement progress updated.
4. Player sees a thank-you confirmation with their current Patron tier and any new rewards.
5. If the player opted in to the donor leaderboard, their entry is updated.

## 3. Patron Tier System

### 3.1 Tier Thresholds
Patron tiers are based on **cumulative lifetime donation total** (USD). Tier upgrades are **automatic** — checked after every successful donation.

| Tier | Cumulative Total | Badge | Title | Chat Flair | Avatar |
|:---|:---|:---|:---|:---|:---|
| **Bronze Patron** | $5+ | Bronze shield with heart | "Bronze Patron" (prefix) | — | — |
| **Silver Patron** | $25+ | Silver shield with wings | "Silver Patron" (prefix) | — | — |
| **Gold Patron** | $100+ | Gold shield with laurel | "Gold Patron" (prefix) | Golden Benefactor flair | — |
| **Diamond Patron** | $500+ | Diamond shield with star(s) | "Diamond Patron" (prefix) | Golden Benefactor flair | "The Benefactor" exclusive avatar |

### 3.2 Diamond Stars
Diamond Patrons earn additional **stars** for every $500 donated beyond the initial $500 threshold:

| Cumulative Total | Display |
|:---|:---|
| $500 | Diamond Patron |
| $1,000 | Diamond Patron ★ |
| $1,500 | Diamond Patron ★★ |
| $2,000 | Diamond Patron ★★★ |
| $2,500 | Diamond Patron ★★★★ |
| $3,000+ | Diamond Patron ★★★★★ |

- **Display cap:** Maximum 5 stars shown in the UI (badge, title, leaderboard).
- **Backend:** The actual star count is stored with no cap. Visible on the player's profile detail page as the raw number (e.g., "Stars: 47").
- **Star formula:** `stars = floor((cumulative_total_cents - 50000) / 50000)`

### 3.3 Badge Visual Design
Each Patron tier badge is a **distinct visual design** that evolves with tier:

| Tier | Badge Description |
|:---|:---|
| Bronze | Warm copper shield with a small heart emblem. Subtle patina texture. |
| Silver | Polished silver shield with feathered wings. Soft gleam effect. |
| Gold | Ornate golden shield wrapped in a laurel wreath. Gentle radiance. |
| Diamond | Crystalline diamond shield with embedded star(s). Prismatic shimmer. Stars are rendered as small diamond-shaped sparkles along the top edge, up to 5 visible. |

### 3.4 Cosmetic Slot Rules
Patron cosmetics follow the **same equip rules** as shop cosmetics (3.3):
- Patron badges occupy the **leaderboard badge slot** (same as shop badges and subscriber badge). Player must choose one.
- Patron chat flair (Gold+) occupies the **chat flair slot** (same as shop flair and subscriber flair). Player must choose one.
- Patron avatar (Diamond) occupies the **avatar slot** (same as shop avatars). Player must choose one.
- Patron titles are equipped via the **existing title system** (one active title at a time).
- All patron cosmetics are stored as `shop_items` with special `category` values (`patron_badge`, `patron_flair`, `patron_avatar`) and granted via `player_shop_items` — reusing the full 3.3 infrastructure.

### 3.5 Tier Downgrade
Patron tiers **never downgrade.** Once earned, a tier is permanent regardless of refunds or disputes. (Refunds on donations reduce the `payment_orders` record but do NOT reduce the player's `cumulative_donation_cents`.)

## 5. Donor Leaderboard

### 5.1 Display
The donor leaderboard is shown within the **Support Us** tab, below the donation flow. It shows:

| Column | Description |
|:---|:---|
| Rank | Position by cumulative donation total |
| Player Alias | Display name (or "Anonymous" if opted out) |
| Patron Tier | Badge icon + tier name (including Diamond stars) |

- **No specific dollar amounts shown.** Only the tier and rank are visible.
- Sorted by cumulative donation total descending.
- Maximum **50 entries** displayed.

### 5.2 Recent Donors Banner
A rotating banner/ticker at the top of the Support Us tab showing recent donations:
- Format: `"[PlayerAlias] just supported Elysium Rising!"` (or `"An anonymous patron just supported Elysium Rising!"`)
- Shows the **5 most recent** donations within the last 7 days.
- Rotates every 5 seconds (client-side animation).
- Only shows donors who opted in to visibility.

### 5.3 Opt-In / Opt-Out
- **Default:** Opted OUT (donations are private by default).
- **During donation:** A checkbox on the donation confirmation: `"Show my name on the donor leaderboard"`.
- **Profile settings:** A toggle in the player's profile/settings page to change visibility at any time.
- Changing to opt-out removes the player from the leaderboard display (but their rank data is retained server-side).
- The `players` table gets a new field: `donor_visibility BOOLEAN DEFAULT FALSE`.

Shows the current player's:
- Current Patron tier (with badge icon) or "Not yet a Patron" if no donations.

After clicking "Donate":
1. **Confirmation modal** opens:

   - [Confirm Donation] / [Cancel] buttons.
2. On confirm: redirected to Stripe Checkout (same flow as 3.1).
3. On return from Stripe: thank-you page with updated Patron status and any new tier rewards.

## 8. Security Requirements

### 8.1 API Authentication
- All `/api/donations/*` endpoints require Firebase JWT authentication.
- Players can only donate for themselves.

### 8.2 Server-Side Validation
- Minimum donation: $1.00 (100 cents). Enforced server-side.
- Amount must be a positive integer (cents). No fractional cents.
- Stripe handles payment security — no card data touches the server.

### 8.3 Rate Limiting
- `POST /api/donations/create-session`: Max 5 requests per player per minute.
- `GET /api/donations/leaderboard`: Max 15 requests per player per minute.

### 8.4 Admin Endpoints
- All `/api/admin/donations/*` endpoints require admin JWT auth.
- Admin actions logged to `activity_events`.

## 9. Error Handling & Edge Cases

### 9.1 Below Minimum
- Donation below $1.00 returns 400: `"Minimum donation is $1.00."`

### 9.2 Payment Failure
- Stripe Checkout handles payment failures. Player is redirected back with an error status.
- No `donations` record is created until webhook confirms payment.

### 9.3 Disputed Donation
- If a donation payment is disputed/charged back, the Stripe webhook handler (3.1) processes it normally (flags account if applicable).
- **Patron tier is NOT downgraded.** The `cumulative_donation_cents` field is never reduced.

### 9.4 Rapid Donations
- Multiple quick donations are allowed. Each creates a separate Stripe Checkout Session.
- Cumulative total is updated per-donation; tier recalculation is idempotent.

### 9.5 Account with Negative Shard Balance
- Donations are **not blocked** by a negative shard balance (unlike shop purchases). Donations don't involve shards.

### 9.6 Account Flagged for Dispute
- Donations **are blocked** for accounts with `account_flag = 'dispute'`. A flagged account must resolve disputes before making any new payments (donations included).

## 11. Schema

### 11.1 New Table: `donations`

Tracks individual donation records and cumulative totals per player.

```sql
CREATE TABLE donations (
    id                      SERIAL PRIMARY KEY,
    player_id               INTEGER NOT NULL REFERENCES players(id),
    payment_order_id        INTEGER NOT NULL REFERENCES payment_orders(id) UNIQUE,
    amount_cents            INTEGER NOT NULL CHECK (amount_cents >= 100),
    cumulative_total_cents  INTEGER NOT NULL DEFAULT 0,  -- snapshot after this donation
    patron_tier             VARCHAR(20) DEFAULT NULL,     -- tier after this donation (bronze/silver/gold/diamond)
    diamond_stars           INTEGER DEFAULT 0,
    created_at              TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_donations_player ON donations(player_id);
CREATE INDEX idx_donations_created ON donations(created_at DESC);
```

### 11.2 ALTER TABLE: `players`

```sql
ALTER TABLE players
    ADD COLUMN cumulative_donation_cents  INTEGER NOT NULL DEFAULT 0,
    ADD COLUMN patron_tier               VARCHAR(20) DEFAULT NULL,  -- bronze, silver, gold, diamond
    ADD COLUMN patron_diamond_stars       INTEGER NOT NULL DEFAULT 0,
    ADD COLUMN donor_visibility           BOOLEAN NOT NULL DEFAULT FALSE;
```

### 11.3 `shard_transactions` — New source_type

Add `'donation'` to the `source_type` CHECK constraint:

```sql
ALTER TABLE shard_transactions
    DROP CONSTRAINT IF EXISTS shard_transactions_source_type_check;

ALTER TABLE shard_transactions
    ADD CONSTRAINT shard_transactions_source_type_check
    CHECK (source_type IN (
        'purchase', 'reward', 'spend', 'refund', 'admin_grant',
        'admin_deduct', 'subscription_stipend', 'subscription_refund',
        'shop_purchase', 'admin_refund', 'donation'
    ));
```

|:---|:---|:---|
| `POST /api/donations/create-session` | POST | Create Stripe Checkout Session for donation. Body: `{ amount_cents: int }` |
| `GET /api/donations/status` | GET | Get current player's Patron status (tier, stars, cumulative total, donation count, next tier info) |
| `GET /api/donations/history` | GET | Get current player's donation history (paginated) |
| `GET /api/donations/leaderboard` | GET | Get donor leaderboard (top N opted-in donors) |
| `GET /api/donations/recent` | GET | Get recent donors for rotating banner |
| `PUT /api/donations/visibility` | PUT | Toggle donor leaderboard visibility. Body: `{ visible: bool }` |

### 12.2 Webhook Handler
The existing Stripe webhook handler (3.1) is extended:
- On `checkout.session.completed` where `order_type = 'donation'`:
  1. Create `donations` record with `amount_cents` and snapshot values.
  2. Increment `players.cumulative_donation_cents`.
  3. Recalculate Patron tier and diamond stars.
  4. Grant new cosmetics/titles if tier changed.
  5. Evaluate "Patron of Elysium" achievement.
  6. Log to `shard_transactions` with `source_type = 'donation'`, `amount = 0`.

## 14. Design Decisions (Resolved)

| 8 | Dollar amounts on leaderboard | Not shown. Only rank, name, and tier/stars visible. |

| 10 | Achievement | Single "Patron of Elysium" achievement on first donation. Rewards suffix title. |
| 11 | Donation amounts | 6 fixed tiers ($1/$5/$10/$25/$50/$100) + uncapped custom amount (min $1). |
| 12 | Tab placement | Third tab in Shop: "Support Us". |
