# REC 3.0: Economy & Monetization (Marketplace & Premium)

This document defines the high-level requirements for the Economy & Monetization phase — the full Stripe-powered premium currency system, player marketplace, subscription, and administrative finance tooling.

**Parent:** [0_REQUIREMENTS.md](0_REQUIREMENTS.md) §3

---

## 1. Overview & Scope

### 1.1 Purpose
Phase 3.0 transforms ERP from a free-to-play prototype into a monetized product with:
- Real-money purchasing of premium currency (Elysium Shards) via Stripe
- A single "Elysium Ascendant" subscription tier providing ongoing benefits
- A player-facing shop for spending Shards on cosmetics and time-limited boosters
- A transparent player marketplace (fixed-price, FIFO) for trading artifacts and equipment
- One-time donation support with shard bonuses
- Full administrative control over finances, refunds, and currency management

### 1.2 Currency Model
ERP has three completely separate currencies with no conversion between them:

| Currency | Type | Source | Sinks |
|----------|------|--------|-------|
| **Session Gold** | Temporary | Earned per Story Mode run | Clicker upgrades (resets each run) |
| **Elysium Essence** | Permanent (F2P) | Story completion, Idle Training, achievements | Idle Training, NPC vendor purchases |
| **Elysium Shards** | Premium | Stripe purchases, donations, achievements (minimal: 1-2 per) | Shop cosmetics, boosters, marketplace trades |

- **No Essence-to-Shard conversion.** Currencies are completely separate.
- **Shards are premium-only.** F2P players earn minimal shards (1-2) from select achievements only.
- **Marketplace trades use Shards only.** Essence cannot be used for P2P trading.

### 1.3 Existing Foundation
The following systems are already in place from earlier phases:
- **`shard_balance`** field on `players` table (2.4)
- **`shard_transactions`** table with `source_type`, `amount`, `balance_after` audit trail (2.7.0)
- **Elysium Essence** — permanent currency earned via Story Mode completion and Idle Training (2.3/2.4)
- **Session Gold** — temporary per-run currency for clicker upgrades (2.2)
- **Artifact System** — curated + generated artifacts with rarity tiers (2.7.0)
- **Dream Item System** — procedural equipment generation (2.4.2)
- **Achievement Rewards** — Shards, Titles, Essence granted on achievement completion (2.7)

### 1.4 Scope Boundaries
- **In Scope:** Stripe integration, shard purchasing, subscription, donations, shop UI, player marketplace, NPC vendors, admin finance dashboard, refund workflows, cosmetic asset generators.
- **Out of Scope:** Mobile app store payments (deferred to §99 / Phase 4), Steam integration, cross-platform payment reconciliation, Essence-to-Shard conversion.
- **Dependencies:** Firebase Auth (1.0), Shard foundation (2.7.0), Artifact system (2.7.0), Inventory system (2.4.2).

## 2. Section Breakdown

### 3.1 — Stripe Integration & Shard Purchasing (Payment Foundation)
The core payment pipeline connecting Stripe to the game's shard economy.
- [ ] Stripe Checkout Sessions for one-time shard package purchases
- [ ] Stripe webhook handler for payment confirmation, failures, and disputes
- [ ] Shard package definitions (6 tiers, ~100 shards/$1 base rate):

    | Tier | Price | Shards | Bonus | Shards/$ |
    |------|-------|--------|-------|----------|
    | Starter | $0.99 | 100 | 0% | ~101 |
    | Small | $4.99 | 525 | 5% | ~105 |
    | Medium | $9.99 | 1,100 | 10% | ~110 |
    | Large | $24.99 | 2,800 | 12% | ~112 |
    | Premium | $49.99 | 6,000 | 20% | ~120 |
    | Ultimate | $99.99 | 13,000 | 30% | ~130 |

    - **First-purchase bonus: 2x shards** on the buyer's very first package (any tier)
    - Pricing is admin-configurable and can be adjusted post-launch
- [ ] Shard crediting flow: webhook → validate → credit `shard_balance` → log `shard_transactions` with `source_type = 'purchase'`
- [ ] Stripe Customer object creation/linking on first purchase
- [ ] Idempotency handling (prevent double-crediting on webhook retries)
- [ ] Payment receipt storage and player-facing transaction history
- [ ] Refund flow: Stripe refund → webhook → debit shards → log with `source_type = 'refund'` (balance can go negative if shards already spent)
- [ ] Dispute/chargeback handling: flag account, debit shards, log anomaly
- [ ] Stripe receipt polling: reconcile package receipts to ensure shard balances are correct (handles account resets)
- [ ] Stripe refund/dispute polling: flag for potential ban, reduce paid currency accordingly

### 3.2 — Subscription: Elysium Ascendant (Recurring Revenue)
A single "Elysium Ascendant" subscription tier with monthly and annual billing options.
- [ ] Stripe Subscription lifecycle (create, renew, cancel)
- [ ] Single tier: **Elysium Ascendant**
    - **Monthly:** $1.99/month
    - **Annual:** $19.90/year (2 months free — equivalent to ~$1.66/month)
- [ ] **Benefits research task:** Simulate gameplay loops to determine where subscription benefits make the most impact without being pay-to-win. Consider:
    - Bonus XP multiplier (what %?)
    - Increased drop rates (what %?)
    - Monthly shard stipend (how many?)
    - Exclusive cosmetics (which ones?)
    - Other QoL perks
    - *Must feel valuable but not mandatory for progression*
    - **Method:** Play through early Story Mode, mid-game Idle Training, and late-game farming loops. Document where a boost would feel rewarding vs. where it would feel like a paywall.
- [ ] Subscription status field on player record (`is_ascendant`, `subscription_expires_at`)
- [ ] Grace period handling for failed payments
- [ ] Webhook handlers for subscription events (`invoice.paid`, `customer.subscription.updated`, `customer.subscription.deleted`)
- [ ] Player-facing subscription management page (view plan, cancel, switch monthly↔annual)

### 3.3 — The Overworld Shop (Shard Spending)
A centralized in-game store where players spend Shards on cosmetics and boosters.
- [ ] Shop UI accessible from the Hub
- [ ] **Shop categories:**
    - **Cosmetics:** Character skins/sprite variants, chat flair, leaderboard badges, avatar profile pictures
    - **Boosters:** Time-limited buffs (XP multiplier, essence multiplier, drop rate buff)
    - **Bundles:** Curated packages (e.g., "Starter Pack" skin + flair + booster)
- [ ] **No permanent meta-upgrades.** All purchases are cosmetic or time-limited.
- [ ] **Launch cosmetics catalog:**
    - **Character skins:** 2 universal skins + 1 per class (requires skin generator tool — see §6)
    - **Chat flair:** 5 variants at launch (colored name borders + special chat icons)
    - **Leaderboard badges:** 4 cosmetic frame styles (e.g., Arcane, Void, Celestial, Infernal)
    - **Avatar profile pictures:** 5-10 premium lore-themed avatars
- [ ] **Booster system:**
    - Default durations and magnitudes (all admin-configurable):

        | Duration | XP Boost | Essence Boost | Drop Rate Boost |
        |----------|----------|---------------|-----------------|
        | 1hr | 1.25x | 1.25x | 1.25x |
        | 8hr | 1.5x | 1.5x | 1.5x |
        | 24hr | 2x | 2x | 2x |

    - Multiple boosters can stack (with admin-set cap)
    - Active booster display in game UI with countdown timer
- [ ] Shard spending flow: validate balance → debit → grant item → log `shard_transactions` with `source_type = 'shop_purchase'`
- [ ] Shop item catalog (admin-managed): name, description, category, shard price, availability window, icon
- [ ] "Featured" and "Limited Time" item rotation (admin-set start/end dates)
- [ ] Purchase confirmation modal with current shard balance display

### 3.4 — Donations (One-Time Support)
Simple donation flow for players who want to support development.
- [ ] Fixed-amount donation tiers (e.g., $5, $10, $25, $50, $100)
- [ ] Custom amount option (minimum $1)
- [ ] Donation → shard bonus mapping (donors receive bonus shards as thank-you, separate from package purchases)
- [ ] Donor recognition: optional "Patron" badge and/or title (cosmetic only)
- [ ] Donation history visible in player transaction log
- [ ] Uses same Stripe Checkout flow as 3.1 with `source_type = 'donation'`

### 3.5 — Player Marketplace (P2P Trading)
A transparent, fixed-price marketplace for trading ALL items (artifacts, equipment, any rarity) using Shards only.
- [ ] **Listing:**
    - Seller sets price in Shards
    - **24-hour listing duration only.** If unsold, player must log in and re-list.
    - Seller can adjust price up or down at any time while listed (minimum 1 Shard, no negative pricing)
    - Item is removed from seller's inventory while listed
- [ ] **Transparency:**
    - All listings show current lowest and highest price for that item type
    - Buyers can see the full price distribution to make informed decisions
- [ ] **FIFO ordering:** If multiple listings exist at the same price, the earliest listing sells first
- [ ] **Buy flow:** Buyer pays listed Shard price → debit buyer → credit seller → transfer item → log both sides in `shard_transactions`
- [ ] **No listing fees.** No trade tax. No re-list cooldown.
- [ ] **All items tradeable:** Curated artifacts, generated artifacts, dream items, equipment — everything. No rarity restrictions.
- [ ] **Listing expiration:** Unsold items auto-return to seller's inventory after 24 hours
- [ ] **Browse/search:** Filter by item type, rarity, stat bonuses, price range. Sort by price, recency, rarity
- [ ] **Trade history:** Both buyer and seller see full transaction records
- [ ] **NPC Vendor (Salvage):** Sell unwanted items to NPC for fixed Essence amounts per rarity tier:

    | Rarity | Essence Return |
    |--------|---------------|
    | Common | 5 |
    | Uncommon | 15 |
    | Rare | 50 |
    | Epic | 150 |
    | Legendary | 500 |

    - NPC returns Essence only (no shards from salvage)
    - Salvage rates admin-configurable per rarity tier
    - **All items salvageable** including curated artifacts — with double-confirmation modal ("Are you sure? This is a unique lore artifact." → "This action is irreversible. Confirm?")
- [ ] **Anti-manipulation:**
    - Price floor: minimum 1 Shard per listing
    - No wash trading between alts (flag accounts sharing payment methods)

### 3.6 — Admin Finance Dashboard & Tools
Administrative control over all monetary systems.
- [ ] **Stripe Integration Viewer:**
    - Transaction log (purchases, subscriptions, refunds, disputes) synced from Stripe
    - Search by player, date range, amount, status
- [ ] **Shard Management:**
    - Manual shard grant/debit tool (for support cases, promotions, corrections)
    - Shard economy health: total shards in circulation, spend/earn ratios
- [ ] **Subscription Management:**
    - View all active subscribers
    - Cancel/extend individual player subscriptions
    - Subscription metrics: active count, churn rate, conversion rate
- [ ] **Refund Workflow:**
    - Search transaction → initiate Stripe refund from admin UI → auto-debit shards → log
    - Partial refund support
- [ ] **Dispute Queue:**
    - Flagged accounts from chargebacks
    - Investigation tools: view player's full purchase/spend history
    - Ban/warn/clear actions
- [ ] **Shop Management:**
    - CRUD for shop items: name, description, category, price, icon, availability window
    - Booster configuration: duration options, magnitude multipliers, stack caps
    - Featured/limited-time rotation scheduling
- [ ] **Marketplace Moderation:**
    - Remove abusive listings
    - Price anomaly alerts (configurable thresholds)
    - Player trade history audit
- [ ] **Revenue Analytics:**
    - Daily/weekly/monthly income breakdown (purchases, subscriptions, donations)
    - ARPU (Average Revenue Per User)
    - Top spenders report
    - Donation totals
