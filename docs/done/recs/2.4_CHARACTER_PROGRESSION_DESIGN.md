## 1. Stat Calculation Engine

### 1.1 Formula Overview

For each stat, the total is computed as the sum of all sources. All coefficients are configurable in `game_configs` or the relevant DB table.

```
stat_total(stat_id, character) =
    class_base(class_id, stat_id)
  + idle_contribution(stat_id, character)
  + lore_contribution(stat_id, character)       # class-specific distribution
  + char_level_contribution(stat_id, character) # primary/secondary per level
  + equipment_contribution(stat_id, character)  # sum of equipped items
```

All values are integers (floored after each component calculation).

|:---|:---|:---|:---|
| Drifter | 15 | 10 | 5 |

| Conduit | 5 | 10 | 15 |
| Vessel | 10 | 10 | 10 |

These are the values at character creation (before any training or leveling).

### 1.3 Idle Training Stat Contributions

Each idle skill contributes to a specific stat. Coefficients stored in `idle_skill_stat_contributions`:

| Idle Skill | Target Stat | Coefficient (default) | At Level 50 | At Level 99 |
|:---|:---|:---|:---|:---|
| Attack | Strength | 0.5 | +25 STR | +49 STR |
| Precision | Agility | 0.5 | +25 AGI | +49 AGI |
| Magic | Intelligence | 0.5 | +25 INT | +49 INT |

```python
idle_contribution(stat_id, character) =
    floor(skill_level(mapped_skill_id) * contribution_coefficient)
```

For future stats added via `stat_definitions`, new rows are inserted into `idle_skill_stat_contributions` with the desired mapping and coefficient — no code changes required.

### 1.4 Lore Stat Distribution

The Lore skill distributes bonuses to two (or three) stats per class using configurable weights stored in `class_stat_affinities`:

| Class | Primary Stat | Primary Weight | Secondary Stat | Secondary Weight | Tertiary |
|:---|:---|:---|:---|:---|:---|
| Drifter | STR | 0.60 | AGI | 0.40 | — |
| Engineer | AGI | 0.60 | STR | 0.40 | — |
| Conduit | INT | 0.60 | AGI | 0.40 | — |
| Vessel | STR | 0.33 | AGI | 0.33 | INT 0.33 |

```python
# Lore total bonus pool
lore_bonus_pool = floor(lore_level * lore_pool_coefficient)   # default coefficient: 0.6

# Per-stat contribution
lore_contribution(stat_id) = floor(lore_bonus_pool * class_weight_for(stat_id))
```

### 1.5 Character Level Stat Contribution

On each character level-up, a flat bonus is added to primary and secondary stats:

| Class | Primary Stat Bonus / Level | Secondary Stat Bonus / Every 2 Levels |
|:---|:---|:---|
| Drifter | +1 STR | +1 AGI |
| Engineer | +1 AGI | +1 STR |
| Conduit | +1 INT | +1 AGI |
| Vessel | +1 (all three, every level) | — |

```python
char_level_contribution(stat_id, character) =
    level * primary_bonus_per_level      # if stat == class primary
  + floor(level / 2) * secondary_bonus  # if stat == class secondary
  + level * vessel_all_bonus            # if class == Vessel (for each stat)
```

Bonus amounts (`primary_bonus_per_level`, `secondary_bonus`, `vessel_all_bonus`) are stored in `class_stat_affinities` and admin-configurable.

### 1.7 Stat Effects in Story Mode

Stats affect combat calculations via configurable coefficients stored in `game_configs`:

```python
# STR: Click damage floor and physical resistance
click_damage = base_click_damage * (1 + STR * game_configs['str_damage_coefficient'])
physical_resistance = STR * game_configs['str_resistance_coefficient']
# Boss incoming damage reduced by physical_resistance (flat, clamped to min 1)

# AGI: Auto-DPS multiplier and critical hit chance
auto_dps = base_auto_dps * (1 + AGI * game_configs['agi_speed_coefficient'])
crit_chance = game_configs['crit_base_chance'] + AGI * game_configs['agi_crit_coefficient']

# INT: Hotbar skill power and cooldown reduction
skill_power_mult = 1 + INT * game_configs['int_power_coefficient']
cooldown_mult = max(0.5, 1 - INT * game_configs['int_cooldown_coefficient'])
# Cooldowns can never go below 50% of base
```

**Default coefficient seeds (tunable):**

| Config Key | Default | Effect |
|:---|:---|:---|
| `str_damage_coefficient` | 0.02 | +2% click damage per STR point |
| `str_resistance_coefficient` | 0.5 | 0.5 flat damage reduction per STR |
| `agi_speed_coefficient` | 0.015 | +1.5% auto-DPS per AGI point |
| `agi_crit_coefficient` | 0.003 | +0.3% crit chance per AGI point |
| `int_power_coefficient` | 0.02 | +2% skill power per INT point |
| `int_cooldown_coefficient` | 0.005 | -0.5% cooldown per INT point (cap: 50% reduction) |

> All coefficients are admin-editable via `game_configs`. New stats added via DB can define their own formulas using the same pattern — register the coefficient keys and implement the calculation in the stat application layer.

## 2. Character Level System

### 2.1 Character XP Sources

```python
# Source 1: Idle training XP conversion
char_xp_from_idle = idle_xp_earned * idle_to_char_xp_ratio
# default idle_to_char_xp_ratio = 0.1 (configurable in game_configs)
# 1 Character XP per 10 idle XP earned — idle training is the primary char XP engine

# Source 2: Story Mode scene completion
char_xp_from_scene = scene_base_char_xp * scene_difficulty_multiplier
# scene_base_char_xp default = 50; difficulty_multiplier from game_configs per book
```

Both sources accumulate into `player_characters.character_xp` (BIGINT, permanent).

### 2.2 Character Level Threshold Curve

Character level uses a quadratic curve (simpler than the Melvor idle XP curve):

```
XP_to_reach(N) = K × N²

where K = char_level_xp_factor (default: 1000, configurable in game_configs)
```

| Level | Cumulative XP to Reach | XP from Idle (approx at 0.1 ratio) |
|:---|:---|:---|
| 1 | 1,000 | ~4 skills each earning 2,500 idle XP |
| 5 | 25,000 | ~4 skills to avg level 5 |
| 10 | 100,000 | ~4 skills to avg level 12 |
| 25 | 625,000 | ~4 skills to avg level 30 |
| 50 | 2,500,000 | ~4 skills to avg level 55 |
| 75 | 5,625,000 | ~4 skills to avg level 75 + story completions |
| 99 | 9,801,000 | Near-maxing all 4 skills + story completions |

**Character XP from idle at max (4 core idle skills × 13,034,431 XP × 0.1 ratio):**
`= 5,213,772 char XP` — enough for approximately **Character Level 72** from idle training alone.

**Plus active skill idle XP (9 universal + 4 class = 13 additional skills)** — the exact total depends on how many active skills a player trains, but this provides a second significant char XP stream.

**Plus scene completion char XP** across ~150+ scenes at 50+ XP each = 7,500+ additional char XP.

The combined total from all sources is designed to make **Character Level 99 achievable** for dedicated players who max multiple idle skills AND complete a significant portion of the story.

> **Tuning note:** `idle_to_char_xp_ratio` and `char_level_xp_factor` are tuned together. The intent is that idle training is the **primary** char XP engine, with scene completions as a meaningful supplement.

### 2.3 XP-to-Next-Level Formula

```
xp_to_next_level(N) = XP_to_reach(N+1) - XP_to_reach(N)
                    = K × ((N+1)² - N²)
                    = K × (2N + 1)
```

| Level | XP to next level (K=1000) |
|:---|:---|
| 1 | 3,000 |
| 10 | 21,000 |
| 25 | 51,000 |
| 50 | 101,000 |
| 98 | 197,000 |

## 3. Skill Level 0 System

### 3.1 Level 0 XP Requirement

The level 0 → 1 XP threshold is stored per skill in `skills.level_0_xp_requirement`. It is intentionally **higher than the standard curve's level 1 → 2 delta** to create a meaningful first-unlock barrier.

**Design target:** Level 0 → 1 should take roughly 3–5× longer than a mid-tier standard level-up. Final values are configurable per skill and tunable in admin.

**Illustrative defaults:**

| Skill | Level 0 → 1 XP | Standard Level 1 → 2 XP (from Melvor curve) |
|:---|:---|:---|
| Magic (idle) | 1,200 | ~100 (level 1→2 standard) |
| Lore (idle) | 1,200 | ~100 |
| Precision (idle) | 1,200 | ~100 |
| Clickstorm (active) | 800 | — |
| Powersurge (active) | 1,000 | — |

*(Active skill Level 0 → 1 is met via idle training, not a separate idle timer — see §3.2.)*

### 3.2 Dual-Leveling System (Active/Hotbar Skills)

Active skills (Clickstorm, Powersurge, etc.) have **two independent levels**:

| Level Type | Where | Persistence | Function |
|:---|:---|:---|:---|
| **Idle Level** (0–99) | Idle Training panel | Permanent | Sets the skill's **base power tier** |
| **Session Level** (1+) | Story Mode UpgradeMenu (gold) | Resets per session | Multiplies on top of idle base |

**Idle level determines base power** via a per-skill `idle_level_scaling` JSONB on the `skills` table:

```python
# Example: Clickstorm
# idle_level_scaling: {"base_clicks_per_sec": {"1": 1, "10": 2, "25": 3, "50": 5, "75": 7, "99": 10}}
# Interpolated between breakpoints
base_clicks_per_sec = interpolate(idle_level, skill.idle_level_scaling["base_clicks_per_sec"])
# Session gold upgrades multiply on top: effective = base * session_level_multiplier
```

**Each active skill has its own idle training action** (seeded in `skill_actions`):

| Skill | Idle Training Action | Flavor |
|:---|:---|:---|
| Clickstorm | "Tempo Drilling" | Practicing rapid-fire click patterns against construct training dummies |
| Powersurge | "Resonance Channeling" | Calibrating resonance frequency to amplify energy output |
| Lucky Strikes | "Probability Mapping" | Studying Red Hat signal patterns for optimal strike timing |
| Super Clicks | "Impact Conditioning" | Overloading click force against reinforced substrate panels |
| Metal Detector | "Lore Excavation" | Scanning the dreamscape substrate for embedded treasures |
| Golden Touch | "Transmutation Practice" | Converting mundane dreamscape matter into value using Akashic principles |
| Energize | "Power Cycling" | Rapidly charging and discharging the Eternal Engine's output |
| Reload | "Precision Reset Drills" | Mastering the instant reset of weapon and skill cooldowns |
| The Dark Ritual | "Forbidden Invocations" | Communing with pre-prison entities — the cost is written in shadow |

**Level cap:** Same as core idle skills — 99 (configurable via `game_configs.idle_skill_level_cap`).

**For prerequisite checks:**
- `idle_skill_level` prerequisites check `character_skill_levels.level` (the permanent idle level).
- `active_skill_level` prerequisites check `character_skill_levels.max_session_level` — the all-time highest session level purchased, tracked permanently. This means "Clickstorm ≥ 5" requires the player to have bought Clickstorm to session level 5 in *any* previous run.

## 4. Item Generation Algorithm

### 4.1 Item Code Specification

```
item_code = {PREFIX_CODE}_{QUALITY_CODE}_{LORE_TAG_CODE}_{ITEM_TYPE_CODE}_{SUFFIX_CODE}
```

- Codes are 3–8 uppercase alphanumeric characters with no spaces.
- Each segment maps to a row in its respective table.
- The full code is stored in `inventory_items.item_code` (VARCHAR 60).
- Display name is **assembled server-side at item creation** and stored in `inventory_items.name` (denormalized for fast reads/sorting). The `item_code` remains the canonical source of truth.
- A backend admin utility (`regenerate_item_names`) can rebuild all display names from `item_code` if component table names are updated.

**Display assembly:**
```
display_name = f"{prefix.name} {quality.name} {lore_tag.name} {item_type.name} of {suffix.name}"
level_label  = f"Level {item.item_level}"
full_display = f"{display_name}  ({level_label})"
```

**Example:**
```
SOLAR_ELDR_INFTR_BLADE_ASCND
→ prefix:   "Solar"       (SOLAR)
→ quality:  "Elder"       (ELDR)
→ lore_tag: "Infinitron"  (INFTR)
→ type:     "Blade"       (BLADE)  [Weapon slot]
→ suffix:   "the Ascendant" (ASCND)

→ Display: "Solar Elder Infinitron Blade of the Ascendant  (Level 12)"
```

### 4.2 Generation Steps (Backend)

```python
def generate_dream_item(character, scene, chapter):
    # Step 1: Gear slot — weighted by scene type
    slot = roll_gear_slot(scene.scene_type)
    # combat scenes → 50% weapon, 30% armor, 20% trinket
    # narrative scenes → 30% weapon, 30% armor, 40% trinket

    # Step 2: Rarity
    rarity = roll_rarity(chapter.book_number)  # later books shift distribution rarer

    # Step 3: Item type for gear slot
    item_type = random.choice(item_type_bases.filter(gear_slot=slot))

    # Step 4: Name components
    prefix   = random.choice(item_prefixes.all())
    quality  = random.choice(item_qualities.all())
    lore_tag = random.choice(item_lore_tags.all())
    suffix   = random.choice(item_suffixes.all())

    # Step 5: Stat calculation
    base_stats = roll_within_range(item_type.base_stat_range)
    prefix_bonus = prefix.stat_bonuses
    suffix_bonus = suffix.stat_bonuses
    rarity_mult  = RARITY_MULTIPLIERS[rarity]
    final_stats  = {
        stat: floor((base + prefix_bonus.get(stat, 0) + suffix_bonus.get(stat, 0)) * rarity_mult)
        for stat, base in base_stats.items()
    }

    # Step 6: Item level
    item_level = min(chapter.recommended_level, character.level)

    # Step 7: Requirements
    min_char_level = max(1, item_level - 2)  # slight grace
    stat_requirements = derive_stat_requirements(final_stats, rarity)

    # Step 8: Store
    item_code = f"{prefix.code}_{quality.code}_{lore_tag.code}_{item_type.code}_{suffix.code}"
    return InventoryItem(item_code=item_code, ..., gear_slot_id=slot.id,
                         item_level=item_level, min_char_level=min_char_level,
                         stat_requirements=stat_requirements, base_stats=final_stats,
                         rarity=rarity)
```

### 4.3 Rarity Multipliers and Stat Requirement Derivation

```python
RARITY_MULTIPLIERS = {
    "common":   1.0,
    "uncommon": 1.3,
    "rare":     1.7,
    "epic":     2.2,
    "cosmic":   3.0,
}

def derive_stat_requirements(final_stats, rarity):
    # Stat requirements = 30-50% of the item's stat bonuses (player needs some stats to equip it)
    # Cosmic items require more; common items require less.
    req_fraction = {"common": 0.3, "uncommon": 0.35, "rare": 0.40, "epic": 0.45, "cosmic": 0.50}[rarity]
    return {stat: max(1, floor(val * req_fraction)) for stat, val in final_stats.items() if val > 0}
```

### 4.4 Rarity Weights by Book

Higher-book chapters shift the rarity table:

| Rarity | Book 1 weight | Book 2 weight | Book 3 weight |
|:---|:---|:---|:---|
| Common | 60% | 50% | 40% |
| Uncommon | 25% | 27% | 28% |
| Rare | 10% | 14% | 18% |
| Epic | 4% | 7% | 10% |
| Cosmic | 1% | 2% | 4% |

All weights configurable in `game_configs.rarity_weight_book_{N}` (JSONB).

### 6.2 Achievement Evaluation Logic

```python
def check_run_achievements(session_stats, character, scene):
    config = game_configs["run_achievement_config"]["achievements"]
    drops = []
    for achievement in config:
        if evaluate_threshold(session_stats, achievement):
            if random.random() < (achievement["drop_chance_pct"] / 100):
                drops.append(generate_dream_item(character, scene, scene.chapter))
    return drops
```

### 6.3 PostBattleSummary Loot UX

Dream item drops are integrated into the **PostBattleSummary** screen as a "Loot" section:

1. **Dice animation:** For each achievement cleared, a spinning dice animation plays.
2. **Failed roll:** Thundercloud appears with **Yaldabaoth** laughing behind it, then fades away. No item drops.
3. **Successful roll:** Item materializes with rarity-colored border, item sprite, name display. Stats and bonus effects shown on hover.
4. **Sequential resolution:** Multiple achievements roll one at a time (dice 1 → result → dice 2 → result → dice 3 → result).
5. **Auto-placement priority:**
   - Matching equipped gear slot empty → auto-equip immediately
   - Equipped slot occupied, bag has space → goes to bag
   - Everything full → comparison UI appears: existing items displayed FIFO (left-to-right), player picks one to replace or discards the new item
6. Multiple drops from a single run are each resolved before the next dice rolls.

### 8.3 Adding New Effect Types (Developer Guide)

When an admin needs a skill or item effect that doesn't map to an existing `benefit_effect_data` entry:

1. **DB:** Insert a new row into `benefit_effect_data` with `effect_key`, `display_name`, `description`, `value_type`.
2. **Backend:** If the effect requires server-side computation (e.g., damage formula), add the handler to the stat application layer.
3. **Frontend:** Add a handler function in `frontend/src/game/utils/effectHandlers.ts` (or equivalent) keyed by `effect_key`. Register it in the effect handler map.
4. **Test:** Add a test case in `test_skill_prerequisites.py` or `test_dream_items.py` verifying the new effect applies correctly.

Existing effect types (≈10 from the 9 universal + 4 class skills) are reusable. New skills using existing effect types require **no code changes** — only DB configuration.

### 8.2a Content Editor Data Flow

All content editor operations go through admin-authenticated routes (`/admin/game/*`). Changes are:
1. Validated server-side (e.g., weights must sum to 1.0, XP values must be positive).
2. Applied immediately to the DB.
3. Reflected in-game on the next player request (no cache invalidation needed for most — stat re-computation happens per request).
4. Logged to `admin_audit_log` with before/after values.

| 8 | Active skill dual-leveling | **Resolved:** Each active skill has idle level (permanent, trained in Idle Training) + session level (gold, resets). Idle level sets base power tier. See §3.2. |
