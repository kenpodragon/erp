# SCHEMA 5.6: Dev Content Audit Dashboard

## 1. Modified Table: `dev_content_audit`

Replace the boolean `resolved` column with a richer `status` enum column.

### 1.1 Current Table Structure (Verified 2026-03-15)

```sql
-- Current structure (pre-migration):
CREATE TABLE dev_content_audit (
    id            SERIAL PRIMARY KEY,
    audit_type    VARCHAR(50)  NOT NULL,
    entity_type   VARCHAR(50),
    entity_id     INTEGER,
    entity_name   VARCHAR(255),
    missing_field VARCHAR(100),
    scene_id      INTEGER      REFERENCES scenes(id) ON DELETE SET NULL,
    zone_level    INTEGER,
    logged_at     TIMESTAMPTZ  DEFAULT NOW(),
    resolved      BOOLEAN      DEFAULT FALSE
);
```

### 1.2 Schema Changes

```sql
-- Migration: 060_dev_audit_status.sql

-- Step 1: Add status column
ALTER TABLE dev_content_audit
    ADD COLUMN status VARCHAR(20) NOT NULL DEFAULT 'open';

-- Step 2: Migrate existing data
UPDATE dev_content_audit SET status = 'resolved' WHERE resolved = TRUE;
UPDATE dev_content_audit SET status = 'open' WHERE resolved = FALSE;

-- Step 3: Drop old resolved column
ALTER TABLE dev_content_audit DROP COLUMN resolved;

-- Step 4: Add index on status for filtering
CREATE INDEX idx_dev_content_audit_status ON dev_content_audit(status);

-- Step 5: Add index on audit_type for filtering
CREATE INDEX idx_dev_content_audit_type ON dev_content_audit(audit_type);
```

### 1.3 Updated Column Reference

| Column | Type | Nullable | Default | FK | Description |
|:---|:---|:---|:---|:---|:---|
| `id` | serial | NO | auto | — | Primary key |
| `audit_type` | varchar(50) | NO | — | — | Type of content gap (e.g., "missing_stat", "missing_entity", "missing_atmosphere", "missing_lore_text") |
| `entity_type` | varchar(50) | YES | NULL | — | Type of entity flagged (e.g., "enemy", "scene", "chapter", "book") |
| `entity_id` | integer | YES | NULL | — | ID of the flagged entity (not FK — may reference entities, scenes, chapters, or books depending on entity_type) |
| `entity_name` | varchar(255) | YES | NULL | — | Display name of the flagged entity (for dashboard display without joins) |

| `status` | varchar(20) | NO | 'open' | — | Triage status: "open", "acknowledged", "in_progress", "resolved", "wont_fix" |

## 3. Valid Status Values

| Status | Description | Dashboard Display |
|--------|-------------|-------------------|
| `open` | Newly logged, not yet triaged | Red pill |
| `acknowledged` | Admin has seen it, not yet working on it | Blue pill |
| `in_progress` | Admin is actively fixing this | Yellow pill |
| `resolved` | Fix applied, content gap closed | Green pill |
| `wont_fix` | Intentionally left as-is (acceptable generic/placeholder) | Gray pill |

Status validation is enforced at the application layer (not a DB constraint) for flexibility.
