# REC 2.1.1: Atmospheric Battle Banner (Visual Loop)

This document defines the technical and artistic requirements for the persistent side-scrolling battle banner visible in the Overworld Hub.

---

## 1. Overview & Inspiration
The **Atmospheric Battle Banner** is a high-performance visual loop providing real-time feedback on character growth and narrative progression.

### 1.1 Design Baseline: *Dwarves: Glory, Death and Loot*
- **Visual Feedback:** Every stat increase and equipment swap should be visually represented on the player's sprite (auras, weapon glows, armor changes).
- **Tug-of-War Flow:** The "battle" has momentum. Stronger stats allow the player character to push forward.
- **Parallax Depth:** Multiple layers of scrolling backgrounds to create a sense of vastness within the sci-fi/cosmic horror world of Etheris.

---

## 2. Core Functional Requirements

### 2.1 Contextual Reactivity & Transitions
- [x] **Contextual Backgrounds:** Reflects the environment of the player's furthest reached or currently selected Chapter.
- [x] **Background Transition:** When a new chapter is selected via the map modal, the banner performs an alpha cross-fade transition in the background while the modal is open.
- [x] **Character Mirroring:** Sprite matches active class, level, and stats.

### 2.2 Movement & Scrolling Logic
- [x] **Forward Momentum:** The player character moves along the `x-axis`. The background infinitely scrolls to simulate forward progress.
- [x] **Scroll Pacing:** Background scrolling slows or pauses during heavy combat waves and resumes full speed during walking/idle phases.
- [x] **Tug-of-War:** High-HP enemies can stall the player's forward progress, requiring "Focus" to overcome.

### 2.3 Character Mortality & Respawning
- [x] **Character Death:** The player can be "defeated" by powerful waves. On death, the sprite resets to the far-left edge of the screen.
- [x] **Vengeance Buff:** After respawning, the character receives a temporary visual and mechanical boost (linked to the 2-minute wave timer) to ensure they eventually clear the stall.

### 2.4 Enemy Pool & Wave Logic
- [x] **Encountered Pool:** Enemies are pulled from `completed_scenes` + the `current_available_scene`.
- [x] **Wave Density:** 
    - **Lower Levels:** Fewer mobs, simpler 1v1 encounters.
    - **Higher Progress:** Increased variability and mob density (1-4 enemies per wave).
- [x] **Clear-to-Spawn:** A new wave only spawns once the current wave has been completely defeated.

## 3. Technical Specifications (PixiJS v8)

### 3.1 Layering Architecture
- [x] **Parallax Backdrop (Far):** Slowest scroll. Distant vistas.
- [x] **Environmental Mid-ground:** Mid-speed scroll. Architectural details.
- [x] **The Ground (Near):** Fast scroll. The platform the sprites "walk" on.
- [x] **The Battle Layer:** 
    - [x] **Player Character:** Dynamic `x` position, walk/attack cycle.
    - [x] **Enemy Conveyor:** Spawning at right margin and moving toward player.
- [x] **VFX Layer:**
    - [x] **Floating Numbers:** Non-clickable real-stat damage numbers.
    - [x] **Surging Aura (Focus):** A "Red/Enraged" glow effect triggered by the 2-minute time-box or respawn.

### 3.2 Animation & Interaction (Visual Only)
- [x] **Sinusoidal Skewing:** Use skewing/scaling to simulate breathing, walking, and attacking.
- [x] **Push-Force Physics:** 
    - [x] Enemies and projectiles apply a literal "Push Force" to the character's `x` coordinate.
    - [x] **Dodge Chance:** (based on Agility) to negate pushback.
    - [x] Character "surges" forward (+x) during attacks and gets "pushed" back (-x) when taking hits.
- [x] **Stat-to-Visual Mapping:**
    - [x] **Strength/Attack:** Scales sprite size, scale, and the intensity of "Hit Shake" effects.
    - [x] **Agility:** Scales movement speed across the x-axis and attack animation frequency.
    - [x] **Intelligence:** Scales the density and complexity of ambient VFX (mana trails, particles).
    - [x] **Dynamic Weights:** Visual weights for these stats must be configurable via the database.
- [x] **The Death & Recovery Sequence:**
    - [x] **Defeat:** Character resets to the far-left edge.
    - [x] **Stall:** Background scrolling stops. Active enemies continue to advance toward the left.
    - [x] **Recovery:** Character plays a "shake it off" animation with a randomized delay before surging back into combat with the "Vengeance" buff.
- [x] **Wave Intensity Curve:**
    - [x] **Per-Book Reset:** Intensity (number of mobs) starts low at Chapter 1 of each book and peaks at the final chapter.
    - [x] **Cumulative Variety:** The pool of possible enemies grows continuously (includes all previously encountered mobs).
    - [x] **Global Cap:** A system-wide `max_enemies_per_wave` setting controls total clutter.
- [x] **Idle States:** "Silly" idle behaviors (stretching, checking gear) between waves.
- [x] **Wave Time-Box (2 Min):** If a wave persists longer than 120 seconds, apply an incremental "Focus" buff.

---

## 4. Technical Constraints (Browser-Only)
- [x] **Zero-Sync Combat:** Battle results in the banner **do not** update player progress, gold, or essence on the server.
- [x] **Static Data Fetch:** Character stats, current enemy pool, and background assets are fetched once on Hub entry or context change.

---

## 5. Visual Content Framework ("Rule of 4")

### 5.1 Paper-Doll System
- [x] **Layered Rendering:** Base Body, Head, Armor Slot, Weapon Slot.
- [x] **Default Fallbacks:** Programmatic Hue and Size shifting.
- [x] **Growth Scaling:** Visual indicators for Level 1-99 benchmarks.
