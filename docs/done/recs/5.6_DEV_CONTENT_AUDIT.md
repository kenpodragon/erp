# REC 5.6: Dev Content Audit Dashboard

This document defines the complete requirements for the Dev Content Audit Dashboard — an admin tool for viewing, triaging, and routing fixes for missing or placeholder content flagged at runtime by the backend.

**Design:** [5.6_DEV_CONTENT_AUDIT_DESIGN.md](5.6_DEV_CONTENT_AUDIT_DESIGN.md) | **Schema:** [5.6_DEV_CONTENT_AUDIT_SCHEMA.md](5.6_DEV_CONTENT_AUDIT_SCHEMA.md)
**Parent:** [5.0_ADMIN_SYSTEMS.md](5.0_ADMIN_SYSTEMS.md) §2 (5.6)

---

## 1. Overview & Scope

### 1.1 Purpose
Section 5.6 provides a reactive dashboard for surfacing and managing content gaps flagged by the backend at runtime. When the game engine falls back to generic/placeholder data (missing stat blocks, missing atmosphere assignments, etc.), it logs a record to `dev_content_audit`. This dashboard surfaces those records so admins can triage them and navigate to the relevant editor to fix them.

After this phase, a game admin should be able to:

- View all runtime-flagged content issues in a paginated, filterable table
- Filter by audit type (dynamically populated from the data)
- Update the status of records (open → acknowledged → in_progress → resolved → wont_fix)
- Bulk-update status across multiple records
- Deep-link from any audit record to the relevant content editor with the flagged item pre-selected
- See summary counts by type and status at a glance

**Platform vision:** The audit system is fully generic — any new fallback path in the codebase can log to `dev_content_audit` and records will automatically appear in the dashboard without UI changes.

### 1.2 Existing Foundation

| System | Current State | What 5.6 Does |
|--------|--------------|----------------|
| `dev_content_audit` table | 17 records (1 `missing_entity`, 16 `missing_stat`), boolean `resolved` column | Extend with `status` enum column, build admin dashboard |
| Story Mode fallbacks | `story_mode.py` logs `missing_entity` and `missing_stat` at runtime | Ensure additional fallback paths also log (atmosphere, lore text) |
| 5.2 Content Editors | Entity Editor, Scene Editor, Chapter Editor all built | Deep-link targets for "Fix →" actions |
| 5.3 Classification | Entity types, families, visual behaviors | Deep-link targets for classification gaps |

### 1.3 Scope Boundaries
- **In Scope:** Audit table viewer with filters, status management, bulk status updates, deep-link fix actions, summary cards, backend fallback instrumentation for atmosphere and lore text paths.
- **Out of Scope:** Proactive content scanning (deferred to C_ generators — see §8). Frontend-only fallback instrumentation (sprite, SFX — deferred to C_ scanner). Severity flagging (not needed — audit_type is sufficient for prioritization). Inline editing (fixes happen in existing editors via deep-links).
- **Dependencies:** 5.2 (Game Content Editor) for deep-link targets. Existing `dev_content_audit` table and runtime logging.

## 2. Audit Table Schema Extension

### 2.1 Status Column
- [x] **2.1.1** Add `status` column (VARCHAR(20), default "open") to `dev_content_audit` table. Valid values: `"open"`, `"acknowledged"`, `"in_progress"`, `"resolved"`, `"wont_fix"`.
- [x] **2.1.2** Migrate existing data: set `status = 'resolved'` where `resolved = true`, `status = 'open'` where `resolved = false`.
- [x] **2.1.3** Drop the old `resolved` boolean column after migration.

### 2.2 Deduplication
- [x] **2.2.1** Before inserting a new audit record, check if a matching record already exists with the same `audit_type`, `entity_id`, `missing_field`, and `scene_id` where `status != 'resolved'` and `status != 'wont_fix'`. If so, skip the insert.
- [x] **2.2.2** Dedup logic implemented in the shared `log_content_audit()` helper function used by all fallback paths.

## 3. Runtime Fallback Instrumentation

### 3.1 Existing Instrumented Paths
These already log to `dev_content_audit`:
- [x] **3.1.1** `missing_entity` — Scene has no entity assignments (logged in `story_mode.py` during wave generation)
- [x] **3.1.2** `missing_stat` — Entity has no `entity_gameplay_data` record (logged in `story_mode.py` during zone HP/gold calculation)

### 3.2 New Instrumented Paths
- [x] **3.2.1** `missing_atmosphere` — Atmosphere resolution chain falls back to global default. Log when a scene's chapter has no `base_atmosphere` assignment and the book-level fallback is also missing. Instrumented in the atmosphere resolution code in `audio.py`.
  - `audit_type`: `"missing_atmosphere"`
  - `entity_type`: `"chapter"` or `"book"`
  - `entity_id`: chapter_id or book_id
  - `entity_name`: chapter/book title
  - `missing_field`: `"base_atmosphere"`
  - `scene_id`: the scene that triggered the fallback
- [x] **3.2.2** `missing_lore_text` — Boss completion endpoint returns null `transition_lore_text` for a chapter or book. Log when the field is null and a boss completion requests it.
  - `audit_type`: `"missing_lore_text"`
  - `entity_type`: `"chapter"` or `"book"`
  - `entity_id`: chapter_id or book_id
  - `entity_name`: chapter/book title
  - `missing_field`: `"transition_lore_text"`
  - `scene_id`: the boss scene that triggered it

### 3.3 Shared Logging Helper
- [x] **3.3.1** Create or extend a `log_content_audit()` helper function in the backend:
  ```python
  def log_content_audit(
      session: Session,
      audit_type: str,
      entity_type: str,
      entity_id: int,
      entity_name: str,
      missing_field: str,
      scene_id: Optional[int] = None,
      zone_level: Optional[int] = None,
  ) -> None:
  ```
  - Performs dedup check before insert (§2.2.1).
  - Used by all fallback paths for consistent logging.

### 3.4 C_ Generator Cross-Reference
- [x] **3.4.1** Add a note to `docs/recs/C_STORY_ASSET_GENERATORS.md` (or create a new C_ requirement) for a proactive content scanner that:
  - Queries all entities without `entity_gameplay_data` → logs `missing_stat`
  - Queries all scenes without entity assignments → logs `missing_entity`
  - Queries all chapters without `base_atmosphere` → logs `missing_atmosphere`
  - Queries all chapters/books without `transition_lore_text` → logs `missing_lore_text`
  - Queries all entities without `sprite_key` → logs `missing_sprite`
  - Queries all entities without `death_sfx_key` → logs `missing_sfx`
  - Queries all skills without `activate_sfx_key` → logs `missing_sfx`
  This scanner runs on-demand and populates `dev_content_audit` for the dashboard to surface.

## 4. Audit Table Viewer

### 4.1 Paginated Table
- [x] **4.1.1** Paginated table showing all `dev_content_audit` records with columns: ID, Audit Type, Entity Type, Entity Name, Missing Field, Scene (if applicable), Status, Logged At.
- [x] **4.1.2** Default sort: `logged_at` descending (newest first).
- [x] **4.1.3** Page size: 50 records per page.

### 4.2 Filters
- [x] **4.2.1** Audit Type filter: dropdown dynamically populated from `SELECT DISTINCT audit_type FROM dev_content_audit`. Shows types with record counts.
- [x] **4.2.2** Status filter: dropdown with "All", "open", "acknowledged", "in_progress", "resolved", "wont_fix". Default: show non-resolved (open + acknowledged + in_progress).
- [x] **4.2.3** Entity Type filter: dropdown dynamically populated from distinct `entity_type` values.
- [x] **4.2.4** Search: text search across `entity_name`.
- [x] **4.2.5** Date range filter: from/to date pickers for `logged_at`.

### 4.3 Visual Indicators
- [x] **4.3.1** Audit type displayed as a colored badge. Colors derived from audit_type name:
  - `missing_*` types → orange badge (absent content)
  - `generic_*` types → yellow badge (placeholder content)
- [x] **4.3.2** Status displayed as a colored pill: open (red), acknowledged (blue), in_progress (yellow), resolved (green), wont_fix (gray).

## 6. Inline Fix Actions (Deep-Links)

### 6.1 Fix Routing
- [x] **6.1.1** Each audit record row has a "Fix →" button that navigates to the appropriate editor page with the flagged entity pre-selected.
- [x] **6.1.2** Deep-link routing by `audit_type`:

  | audit_type | Target Page | Query Params |
  |------------|-------------|-------------|
  | `missing_stat` | WorldBuilder → Narrative Editor → Entity Editor | `?entity_id={entity_id}` |
  | `missing_entity` | WorldBuilder → Narrative Editor → Scene Editor | `?scene_id={scene_id}` |
  | `missing_atmosphere` | WorldBuilder → Narrative Editor → Chapter Editor | `?chapter_id={entity_id}` |
  | `missing_lore_text` | WorldBuilder → Narrative Editor → Chapter/Book Editor | `?chapter_id={entity_id}` or `?book_id={entity_id}` |
  | `missing_sprite` | WorldBuilder → Narrative Editor → Entity Editor | `?entity_id={entity_id}` |
  | `missing_sfx` | WorldBuilder → Narrative Editor → Entity Editor | `?entity_id={entity_id}` |
  | `generic_stat_block` | WorldBuilder → Classification → Audit | `?entity_id={entity_id}` |

- [x] **6.1.3** For unknown `audit_type` values (future types), show a generic "View Entity" link to the entity editor if `entity_id` is present, or no link if not.

## 9. Design Decisions (Resolved)

| # | Decision | Resolution | Rationale |
|---|----------|------------|-----------|
| Q1 | Reactive vs. proactive | Reactive only — proactive scanning deferred to C_ generators | Dashboard shows runtime-flagged issues; C_ generators handle bulk scanning |
| Q2 | Table extensions | Add `status` column only (lean extension) | Minimal schema change; admin notes can be added later if needed |
| Q3 | Severity flagging | Skipped — not needed | audit_type provides sufficient categorization for prioritization |
| Q4 | Audit type filtering | Dynamic — populated from `SELECT DISTINCT audit_type` | Dashboard auto-adapts as new audit types are logged |
| Q5 | Fix actions | Deep-link navigation to existing editors | Reuses 5.2/5.3 editors; no inline fix modals to build |
| Q6 | Summary cards | Counts by type + status from `dev_content_audit` only | Reactive dashboard shows flagged issues, not full coverage stats |
| Q7 | UI placement | New top-level admin page "Dev Audit" | Operational tool, separate from content creation (WorldBuilder) |
| Q8 | Generic vs. specific tagging | Derived from audit_type prefix (`missing_*` vs. `generic_*`) | No extra column needed; UI uses different colors per prefix |
| Q9 | Fallback instrumentation | Backend paths only (atmosphere, lore text) | Frontend fallbacks (sprite, SFX) deferred to C_ scanner |
| Q10 | Deduplication | Application-level check before insert | Simple check in `log_content_audit()` helper; prevents table bloat |
