## 1. Overview & Design Goals

Idle Training is **Loop C** of the ERP game loop — the passive, ever-running skill progression system that provides the permanent power floor for all Story Mode (Loop B) sessions.

A player who actively trains their skills over weeks will start every Story Mode session significantly stronger than a new player, without having to "catch up" through session upgrades. This is the long-term investment arc.

### Design Pillars

1. **Passive power floor.** Idle Training levels determine base stats baked into every Story Mode session. A max-level Attack character clicks harder before spending a single gold coin on upgrades.
2. **One decision at a time.** Players pick one skill, one action. The tension is in *what* to prioritize, not in managing complexity.
3. **Narrative immersion.** Every trainable action is named and flavored from the Towers of Elysium books. Training happens *inside the world* — in S Corp facilities, in the Dreamscape, aboard the Genesis ship.
4. **24-hour passive loop.** Rewards daily engagement without punishing absences beyond one day. Never a chore.
5. **Economy integration.** Training consumes Elysium Essence — the currency earned in Story Mode — creating a bidirectional dependency between the two loops.

### Inspirations & Divergences

**Primary inspiration:** [Melvor Idle](https://store.steampowered.com/app/1267910/Melvor_Idle/) — one-at-a-time training, sub-action escalation, offline delta calculation, 1–99 XP curve.

**Where ERP diverges from Melvor Idle:**
- No per-action Mastery system (deferred, see §14)
- Narrative gates replace pure level gates for skill unlocks
- Essence soft gate instead of no resource cost
- Active Mode XP *replaces* idle accumulation (doesn't layer on top)
- Terminal aesthetic instead of Melvor's RPG panel style
- Class affinity bonuses on primary skill

## 2. The Training Loop (Mechanical Overview)

```
SELECT SKILL
  └─→ SELECT ACTION (sub-task within that skill)
        └─→ Action timer runs (interval_ms per action)
              └─→ Timer completes → XP awarded → timer resets → loops
                    └─→ XP accumulates → level threshold crossed → LEVEL UP
                          └─→ New actions unlock at new level
```

### Core Rules

1. **One skill trains at a time.** Selecting a new skill stops the previous one immediately. No XP is lost from the stopped skill.
2. **One action per skill.** Within a skill, the player selects which sub-action to train. This can be changed at any time; changing it resets the action timer to 0%.
3. **Continuous looping.** When an action timer completes, XP is awarded and it immediately starts again. There is no manual re-trigger required.
4. **Partial actions are discarded.** If training is stopped mid-action (manually, or on logout for offline calc), the partial action progress is lost. Only completed actions grant XP.
5. **Background persistence.** Training continues while the player navigates to Story Mode, Home Base, or any other screen. It does NOT require the Skills tab to be open.
6. **Essence consumption is constant.** Essence drains at `idle_essence_drain_per_minute` regardless of the current XP rate modifier or which action is selected.

## 3. XP & Leveling

### XP Curve Formula

The XP required to reach level `N` (cumulative from level 1):

```
XP_to_reach(N) = floor( (1/4) × Σ_{i=1}^{N-1} floor(i + 300 × 2^(i/7)) )
```

This is the RuneScape/Melvor-standard curve. XP to advance from the current level to the next:
```
xp_needed = XP_to_reach(current_level + 1) - XP_to_reach(current_level)
```

### Key Level Reference Points

| Level | Cumulative XP Required | ~Hours to reach (lowest action, no bonuses) |
|:------|:----------------------|:--------------------------------------------|
| 1 | 0 | — |
| 10 | 1,154 | ~0.3 hrs |
| 20 | 4,470 | ~1.2 hrs |
| 30 | 13,363 | ~3.7 hrs |
| 50 | 101,333 | ~28 hrs |
| 60 | 273,742 | ~76 hrs |
| 70 | 737,627 | ~205 hrs |
| 80 | 2,034,343 | ~565 hrs |
| 90 | 5,346,332 | ~1,485 hrs |
| 99 | 13,034,431 | ~3,621 hrs |

*(Hours calculated at 3,600 XP/hr — 1,200 actions/hr × 10 XP/action with lowest-tier action at 3s interval, no bonuses.)*

### Maximum Level

- **Level 99** is the hard cap for 2.3.
- Level 99 in all 4 skills represents full mastery of that skill's passive contribution.
- Mastery system (post-99 per-action progression) is a future feature deferred beyond 2.3 scope (see §14).

### Level-Up Behavior

- When XP crosses a level threshold, the level increments immediately.
- New actions are unlocked without requiring any additional player action.
- A level-up notification flashes in the terminal UI: `LVL [N] → LVL [N+1]`.
- Multi-level-ups (common offline) are applied iteratively and all shown in the Training Report.
- **Milestone rewards** (level 25, 50, 75, 99) are defined in the 2.7 Achievement Matrix. The 2.3 spec only enforces that these milestones trigger a notification event — rewards are awarded by the achievement system.

## 5. Sub-Action System

Each skill contains a curated list of trainable sub-actions ("work tasks") unlocked progressively as the skill level rises. All actions are lore-accurate, referencing real events, characters, and locations from the Towers of Elysium trilogy.

### Action Mechanics

- **One action trains at a time** within a skill.
- Actions have a **fixed base interval** (milliseconds) and **fixed XP per completion**.
- When the action timer completes, XP is awarded and the action **immediately loops** — no player input required.
- Higher-tier actions have **longer intervals but more XP**, targeting more efficient XP/hr rates.
- **Action switching** is free and immediate; switching resets the action timer to 0% (partial action progress is discarded).
- **Class affinity** applies to XP earned from all actions for the affinity skill.

## 6. Session Floor — Stat Formulas (Permanent Story Mode Bonuses)

Idle Training levels provide permanent base stat bonuses to every Story Mode session. These are calculated **at session creation** from the character's current skill levels and do not update during an active session (live update deferred to a future phase).

### 6.1 Attack → Base Click Damage Floor

```
click_damage_floor = floor(Attack_Level / 2)
```

Added directly to base click damage before any in-session upgrades.

| Level | Bonus Click Damage |
|:------|:------------------|
| 1 | +0 |
| 10 | +5 |
| 30 | +15 |
| 60 | +30 |
| 99 | +49 |

### 6.2 Magic → Auto-DPS Global Multiplier

```
auto_dps_multiplier = 1.0 + (Magic_Level × 0.01)
```

Applied as a multiplier to total auto-DPS (summed from all skill levels and in-session upgrades).

| Level | Multiplier |
|:------|:-----------|
| 1 | ×1.01 |
| 25 | ×1.25 |
| 50 | ×1.50 |
| 75 | ×1.75 |
| 99 | ×1.99 (~×2.0) |

### 6.3 Lore → Story Gate Reduction + Essence Gain Bonus

**Narrative Time Gate Reduction** (reduces the WPM narrative progress % required to advance a wave):
```
gate_reduction_pct = min(Lore_Level × 0.3%, 25%)
```
Hard cap at 25% — a 5-minute required gate becomes ~3m 45s at cap.

**Essence Gain Multiplier** (applied to all Essence earned from Story Mode sessions):
```
essence_multiplier = 1.0 + (Lore_Level × 0.008)
```

| Level | Gate Reduction | Essence Multiplier |
|:------|:--------------|:-------------------|
| 1 | 0.3% | ×1.008 |
| 25 | 7.5% | ×1.20 |
| 50 | 15.0% | ×1.40 |
| 84 | 25.0% (cap) | ×1.67 |
| 99 | 25.0% (cap) | ×1.79 |

### 6.4 Precision → Crit Chance + Crit Multiplier

**Crit Chance Additive:**
```
crit_chance_bonus = Precision_Level × 0.001   (as 0.0–1.0 fraction; i.e., ×0.1% per level)
```

**Total Crit Multiplier** (additive to the base 2.0×):


| Level | Crit Chance Bonus | Total Crit Multiplier |
|:------|:-----------------|:---------------------|
| 1 | +0.1% | ×2.01 |

| 75 | +7.5% | ×2.75 |
| 99 | +9.9% | ×2.99 |

### Stat Application Timing

- Bonuses are read from `character_skill_levels` when a new Story Mode session is **created** (POST `/api/game/story/start`).
- They are **not** recalculated during an active session (live update deferred to future release).
- To benefit from new levels, the player must complete the current session and start a new one.

## 8. Background Execution & Offline Progression

### Background Persistence

Training is entirely server-side. The client does not need to be open for XP to accumulate. Training continues while the player:
- Is in a Story Mode session
- Is on the Home Base Hub screen
- Has the app closed entirely (up to the 24-hour cap)

The backend tracks `last_offline_calc_at` and calculates the delta on the next authenticated request.

### Offline Calculation

When the player makes any authenticated request after a period of inactivity, the backend runs:

```python
elapsed_seconds = now - last_offline_calc_at
capped_seconds  = min(elapsed_seconds, idle_offline_cap_hours × 3600)  # cap: 24hr

# XP calculation
actions_completed = floor(capped_seconds / (action.interval_ms / 1000))
xp_earned = actions_completed × action.xp_per_action × essence_rate × class_affinity_multiplier

# Essence drain (constant regardless of XP rate)
essence_drained = (capped_seconds / 60) × idle_essence_drain_per_minute
```

- `essence_rate` = XP rate modifier based on Essence % at the time of calc (see §9)
- `class_affinity_multiplier` = 1.25 if this is the character's affinity skill, else 1.00
- XP is applied to `current_xp`. Multi-level-ups are applied iteratively until XP is exhausted.

### Offline Cap

- **24 hours.** Configured via `game_configs.idle_offline_cap_hours`.
- Progress beyond 24 hours is silently discarded with no warning shown retroactively.
- This cap encourages daily engagement without requiring multiple logins per day.

### Training Report Modal

The Training Report is shown **on every return** where any training occurred (even gaps of 1 minute), displayed before the Skills tab renders. It is terminal-styled:

```
┌─ TRAINING REPORT ──────────────────────────────────────────────────────┐
│  OFFLINE DURATION: 8h 24m (of 24h cap)                                 │
│                                                                         │
│  ATTACK :: Shadowboxing in the Garage                                   │
│  Actions completed:  10,080                                             │
│  XP earned:         100,800  (+25% Drifter affinity applied)            │
│  Levels gained:     +2  (LVL 23 → LVL 25)                              │
│  New action unlocked: Fighting Red Hat Brigades (LVL 36 required)       │
│                                                                         │
│  Essence consumed:  504                                                 │
│  Remaining Essence: 3,241  (82% — TRAINING AT FULL RATE)               │
│                                                                         │
│  [CONTINUE]                                                             │
└────────────────────────────────────────────────────────────────────────┘
```

The report includes:
- Offline duration (and cap context)
- Which skill and action was training
- Actions completed and XP earned (with affinity bonus noted if applicable)
- Levels gained and new actions unlocked
- Essence consumed and remaining balance with current rate status

### Edge Cases

| Scenario | Behavior |
|:---------|:---------|
| No active training set | No XP accrues. Report is suppressed. |
| No action selected within active skill | No XP accrues. Training Report still shown (0 XP earned). |
| Essence runs to 0 mid-offline | Backend calculates partial time at degraded rates; applies floor rate for remaining duration. |
| Multi-level-up from offline | All levels applied iteratively. All newly-unlocked actions listed in Training Report. |
| First login ever (no prior training) | No Training Report. Player lands directly on Skills tab. |

## 9. Essence Soft Gate

Training consumes **Elysium Essence** — the permanent currency earned from Story Mode — at a rate of `idle_essence_drain_per_minute` (default: 1 Essence/minute, configurable via `game_configs`).

The Essence **percentage** (current Essence ÷ character's Essence capacity) determines the XP rate modifier:

| Essence % | XP Rate Modifier | Status Text |
|:----------|:----------------|:------------|
| 75–100% | **100%** — Full rate | `TRAINING AT FULL RATE` |
| 40–74% | **75%** — Reduced | `ESSENCE DEGRADING — XP REDUCED` |
| 15–39% | **50%** — Low | `ESSENCE LOW — REPLENISH VIA STORY MODE` |
| 1–14% | **25%** — Critical | `ESSENCE CRITICAL — MINIMAL GAINS` |
| 0% | **10%** — Floor | `ESSENCE EMPTY — TRAINING AT MINIMUM RATE` |

**Key behaviors:**
- Training **never fully halts.** The 10% floor ensures passive progression even for players who neglect Story Mode entirely, though at a severely degraded rate.
- Essence drain is **constant** — the same rate regardless of the XP rate modifier tier.
- Essence capacity is tracked in `player_essence`. The gate uses the ratio of current Essence to the character's capacity ceiling.
- **Replenishment:** Players earn Essence from Story Mode session completions (via `player_meta_progression`). The Lore skill's `essence_multiplier` bonus stacks on top of base Essence earnings.

### Intended Resource Loop

```
Earn Essence (Story Mode)
  → Essence funds Training (Idle Training)
  → Training builds levels (skills)
  → Skill levels improve Story Mode stats (session floor)
  → Better stats make Story Mode more efficient
  → More Story Mode → more Essence → sustain Training
```

## 10. Active Mode (Manual Advancement)

### Purpose

Active Mode allows a player to directly engage with a skill's training through a clicker mini-game, earning XP significantly faster than idle accumulation — but only while actively playing.

**Active Mode PAUSES idle accumulation.** All XP during Active Mode comes from enemy kills. Essence is NOT consumed during Active Mode.

### Entry Flow

1. Player clicks **[ENTER ACTIVE MODE]** from the Skill detail panel.
2. A terminal-style confirmation modal appears with a summary of the mode rules.
3. On confirmation: `is_in_active_mode = TRUE` recorded server-side; idle timer pauses.
4. The Story Mode combat engine (CombatStage.tsx / PixiJS) launches in Active Mode configuration.

### Combat Configuration

| Parameter | Active Mode Value |
|:----------|:-----------------|
| Narrative block | Disabled (no WPM gate) |
| Audio player | Disabled |
| Essence earning | Disabled |
| Essence consumption | Disabled |
| Wave structure | Endless (no chapter/scene limit) |
| Boss spawn interval | Every `idle_active_mode_boss_interval` waves (default: 10) |
| Enemy HP scaling | Same zone-scaling formula as Story Mode |
| Header display | `TRAINING: [SKILL :: FLAVOR_TITLE]` |

### Skill-Specific Flavor

| Skill | Header | Enemy Pool | Location/Background |
|:------|:-------|:----------|:--------------------|
| Attack | `TRAINING: COMBAT PROTOCOL` | Combat-type entities from unlocked story progress (Red Hat soldiers, Shadow Wraiths, Kuiper Belt hostiles) | S Corp Combat Facility / MOM Antarctic Base |
| Magic | `TRAINING: DREAMWALKING` | Dreamscape entities (energy constructs, astral manifestations, Threshold entities) | The Dreamscape / The Threshold |
| Lore | `TRAINING: AKASHIC RESEARCH` | Knowledge-guarding entities (Pointers, Audit constructs, abstract cosmic forms) | Akashic Realm / S Corp Research Archives |
| Precision | `TRAINING: CALIBRATION` | Technical adversaries (Red Hat operatives, prison constructs, infiltrators) | Infinitron Lab / ERB Portal Room / Genesis Ship deck |

**Enemy Pool Fallback:** If no skill-relevant entities exist for the player's current story progress, fall back to zone-scaled generic entities (same as Story Mode's entity fallback logic). Log a `dev_content_audit` entry for the missing pool.

### XP Formula

```python
# Per regular enemy kill:
xp_per_kill = action.xp_per_action × (1.0 + (wave_number × 0.01)) × class_affinity_multiplier

# Per boss kill (every 10 waves):
xp_per_boss_kill = action.xp_per_action × 5 × class_affinity_multiplier
```

Where `action.xp_per_action` is the XP value of the currently-selected idle action.

### Action Looping

XP from kills accumulates against the current action's `xp_per_action` value. When enough XP accumulates to "complete" the action, it is counted as completed and the counter resets (loops). Multiple loops can occur in a single wave.

The UI displays: `ACTION COMPLETE × 3 — LOOPING` when multiple loops occur.

**Example:** Player selects "Shadowboxing in the Garage" (10 XP/action). Wave 50 gives ~15 XP per kill (10 × 1.50 scaling). After 1 kill, 5 XP remains in the loop. Second kill completes 1 full action (5 + 15 = 20 XP → 2 complete actions, 0 XP overflow). This effectively earns 2 action-completions in 2 kills — much faster than idle.

### Exit Flow

1. Player clicks **[EXIT ACTIVE MODE]** (always-visible during Active Mode).
2. All accumulated XP is applied to `character_skill_levels.current_xp` server-side.
3. `is_in_active_mode = FALSE` recorded.
4. Idle training resumes; action timer resets to 0%.
5. No Training Report modal on exit (offline calc is not triggered).

## 11. API Surface Requirements

The following backend endpoints are required for the Idle Training system. All must be server-authoritative; clients receive calculated state only.

| Method | Endpoint | Description |
|:-------|:---------|:------------|
| `GET` | `/api/game/training/status` | Returns current training state for all skills (levels, XP, active action, Essence %, rate modifier). Triggers offline calc if needed. |
| `POST` | `/api/game/training/start` | Start training a skill. Body: `{skill_id, action_id}`. Stops any currently-training skill first. |
| `POST` | `/api/game/training/stop` | Stop all training. Sets `is_active_training = FALSE`. |
| `POST` | `/api/game/training/switch-action` | Change the selected action within the currently-training skill. Body: `{skill_id, action_id}`. |
| `POST` | `/api/game/training/active-mode/enter` | Enter Active Mode for the currently-training skill. Pauses idle. |
| `POST` | `/api/game/training/active-mode/exit` | Exit Active Mode. Body: `{xp_earned}` — client reports kill XP; server validates and applies. |
| `GET` | `/api/game/training/offline-report` | Returns the Training Report data from the last offline calculation. |
| `GET` | `/api/game/training/actions/{skill_id}` | Returns all actions for a skill with unlock status (locked/available) based on current level. |

### Server Authority Model

- XP is **never granted directly by the client**. The client reports kills in Active Mode; the server validates against expected rates and applies XP.
- Offline XP is calculated server-side on the first authenticated call after a gap.
- The client polls `/api/game/training/status` for live updates (recommended: every 5 seconds while Skills tab is open). WebSocket upgrade is a future enhancement.

## 12. Integration Points

### Story Mode (Loop B) Integration

| Integration | Mechanism |
|:-----------|:---------|
| Session stat bonuses | At `POST /api/game/story/start`, server reads character skill levels and applies formulas from §6 to the session's base stats. |
| Magic hotbar gates | `GET /api/game/story/session` includes `magic_level` in character state. UpgradeMenu checks against hotbar unlock table (§7). |
| Skill unlock on scene complete | `POST /api/game/story/complete-scene` fires the unlock check: if scene matches `skills.unlock_scene_id`, mark skill as unlocked and push notification. |
| Essence replenishment | `POST /api/game/story/end-session` awards Essence to `player_essence`. Lore `essence_multiplier` is applied here. |

### Home Base Hub (Loop A / 2.7) Integration

- The Skills nav tab shows a persistent indicator of the currently-training skill even from non-Skills screens.
- Milestone rewards (level 25, 50, 75, 99) are tracked by the Achievement Matrix (2.7) which listens to `character_skill_levels` change events.

### Achievement Matrix (2.7) Hooks

| Event | Trigger |

| `skill.milestone` | Level crosses 25, 50, 75, or 99 |
| `skill.max_level` | Level reaches 99 |
| `skill.action_unlocked` | A new action becomes available |
| `active_mode.boss_killed` | Boss kill in Active Mode |

## 14. Deferred Features (Post-2.3)

These features are explicitly out of scope for 2.3. They are documented here to ensure schema and architecture decisions do not block them.

| Feature | Notes |
|:--------|:------|
| **Per-action Mastery system** | Each action gets its own 1–99 Mastery level with interval reductions. Schema hook exists in 2.3.1.0. |
| **Skill pets** | RNG-based pet unlock per action; each pet gives a permanent passive bonus. |
| **Interval reduction bonuses** | Equipment or potions that reduce `interval_ms` (e.g., -5% training speed). |
| **Additional skills beyond 4** | System is designed to be fully extensible via `skills` + `skill_actions` tables with no code changes. |
| **Magic → additional hotbar skill tiers** | If more hotbar skills are added in 2.4+, their Magic level gates follow the same pattern. |
| **Live stat updates mid-session** | Idle level-up immediately refreshing active Story Mode session stats. |
| **Training speed items/consumables** | Items in inventory that temporarily boost XP rate for a skill. |
| **Skill milestone rewards** | Badges, titles, Essence grants at levels 25/50/75/99. Defined in 2.7 Achievement Matrix. |
